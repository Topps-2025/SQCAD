# Baseline Audit — open-source status, CPU-only reproduction, comparison position

> Verified 2026-08-13 via web (official READMEs, LICENSE files, arXiv/venue pages; Hugging Face via mirror API). Local frozen snapshots (D-drive `upstream/`, SHA-256 recorded, reproduction gate R1) take precedence over web state for reproduction. Anything not locally frozen and not independently confirmed is marked `unverified`.
>
> Environment fact that motivates this audit: the working machine has **no NVIDIA GPU and no OpenAI/Anthropic/Azure/HF API keys**. This document answers, per baseline: (1) is the official code open source, (2) if not, what reproduction path remains, (3) what does a no-GPU reproduction of open code actually run, and (4) where does the baseline sit in SQCAD's experimental plan (`docs/草稿-draft/实验方案与基线/17-…`, tiers R1/R2/R3 of the unified comparison protocol).

## 2. R3 official systems, one by one

### SimpleMem — open source, API-bound (CPU workable)

- Paper: "SimpleMem: Efficient Lifelong Memory for LLM Agents", arXiv 2601.02553, ICML 2026 poster. Repo: [aiming-lab/SimpleMem](https://github.com/aiming-lab/SimpleMem), **MIT**. Locally frozen at the paper-release commit `16912523` (2026-01-02, "released version"; current main has post-paper Omni/EvolveMem changes and is deliberately **not** used for paper reproduction).
- **No-GPU reproduction:** the paper backbone is GPT-4.1-mini via API (**`OPENAI_API_KEY` required**); without it the system falls back to JSON keyword search — the full method is not exercised. Default embeddings Qwen3-Embedding-0.6B run on CPU (slow) or via API. Vector store LanceDB, CPU-friendly. → *Everything runs CPU except the backbone LLM and embeddings; the blocker is an API key, not a GPU.*
- **Comparison position:** R3; `simplemem` behavioral proxy row in the unified-contract main table, labeled `not reproduced` until R3; migration (M1) only after R3.

### Oblivion — code public, license NOT open source

- Paper: "Oblivion: Self-Adaptive Agentic Memory Control through Decay-Driven Activation", arXiv 2604.00131 (NEC Laboratories Europe). Repo: [nec-research/oblivion](https://github.com/nec-research/oblivion). **License: proprietary NEC Laboratories Europe GmbH** — use outside NEC R&D requires contacting the authors. Readable and locally snapshot at commit `b2512f9` ("Releasing Oblivion code base", 2026-05-25), but **not redistributable and not MIT-style open source**. This must be stated in the paper, not glossed as "open".
- **No-GPU reproduction:** Python 3.12 + Poetry; Qdrant local (CPU); LLM via OpenAI/Azure/OpenRouter clients — the paper used GPT-4.1-mini (API). Decay math, retrieval routing and RRF merging are all CPU. The 8×RTX-5090 vLLM path is only for the paper's optional *local-inference* experiments. → *API keys are the blocker; the code itself is CPU-runnable.*
- **Comparison position:** R3; `oblivion` proxy row in the main table; note the license limits what we may copy into this repository — keep the snapshot in the external database only.

### FadeMem (agent memory) — no official code

- Paper: "FadeMem: Biologically-Inspired Forgetting for Efficient Agent Memory", arXiv 2601.18642 (Alibaba ICDG + PKU). **No official implementation found.** A commercial SDK (VEKTOR Slipstream) claims a production implementation; fidelity to the paper unverified — excluded. The `aniki-ly/FadeMem` repo is a different paper (video diffusion, arXiv 2606.10671) and is excluded as an identity mismatch (local audit, R0).
- **Reproduction path:** the paper fully describes the mechanism — dual-layer memory (LML/SML), adaptive exponential decay `v(t)=v(0)·exp(−λ·t^β)` (β=0.8/1.2), LLM-guided conflict resolution, memory fusion, knapsack pruning — and its benchmarks (LTI-Bench, MSC, LoCoMo). A faithful behavioral proxy (decay + LLM conflict resolution) can be implemented in the unified contract; the LLM conflict-resolution step is the only model-dependent part.
- **Comparison position:** R3-pending; `fademem` proxy row; official numbers enter only if an official implementation appears.

### Memory Worth — no code, but the method is trivial to reimplement

- Paper: "When to Forget: A Memory Governance Primitive", arXiv 2604.12007 (preprint). **No repository found.** The method is two integer counters per memory unit: `MW(m) = hits⁺/(hits⁺+hits⁻)`, proven convergent to the conditional success probability — explicitly **associational, not causal** (the paper says so).
- **Reproduction path:** full metric definition, convergence proof and experimental protocol are in the paper; reimplementation is a dozen lines in the unified runner. Validation in the paper is synthetic only.
- **Comparison position:** R3-pending; `memory_worth` proxy row. Theorems 1–2 of SQCAD construct worlds where this *correctly estimated* quantity still selects the wrong lifecycle action — the proxy row demonstrates exactly this on the shared stream.

### DeMem — no code

- Paper: "Remember the Decision, Not the Description: A Rate-Distortion Framework for Agent Memory", arXiv 2605.10870 (Fudan/CUHK/Meta AI et al.). **No repository found** (an unrelated privacy paper shares the DeMem name; excluded by identity). Online learner refining a memory partition only on *certified decision conflict*, with near-minimax regret.
- **Reproduction path:** the learner and conflict-certification rule are algorithm-only (reimplementable); the LoCoMo evaluation needs LLM calls for evidence recovery checks. Unverifiable beyond the paper until code appears.
- **Comparison position:** R3-pending; `demem` proxy row (decision-conflict-gated retention).

### SAGE (memory gate) — open source (mem0 fork)

- Paper: "SAGE: A Novelty Gate for Efficient Memory Evolution in Agentic LLMs", arXiv 2605.30711. Repo: [swang1024/SAGE](https://github.com/swang1024/SAGE), **Apache-2.0** (fork of mem0, whose copyright is retained). Write-side gate: ADD/MERGE/NOOP via a von Mises–Fisher density estimator with adaptive threshold; only ambiguous cases reach the LLM.
- **No-GPU reproduction:** the vMF gate itself is closed-form vector math — CPU. Fact extraction and the rare merge step are LLM calls (paper: GPT-4o-mini + 7 open-weight backbones on LoCoMo → API keys or GPU for local backbones). As a mem0 fork it inherits mem0's API-based embedding stack.
- **Comparison position:** **`not_transportable` under the unified contract** (write-time gate; no defined access-time authorization migration protocol) — no main-table row, no numbers compared, per the claim discipline (`docs/实验证据链/09`).

### MemAudit — two papers; artifacts exist for the evaluation-protocol one

- Papers: (a) "MemAudit: Post-hoc Auditing of Poisoned Agent Memory via Causal Attribution and Structural Anomaly Detection", arXiv 2605.23723 — **no code found**; (b) "MEMAUDIT: An Exact Package-Oracle Evaluation Protocol for Budgeted Long-Term LLM Memory Writing", arXiv 2605.02199 — **reproducibility artifacts on Hugging Face** (`edgeclustr/memaudit-code`): reusable package generators, certified solvers, scorers for Mem0/Letta/A-Mem.
- **No-GPU reproduction:** both are API-based LLM + retrieval stacks; no GPU requirement stated. The protocol paper's artifacts are CPU-runnable; the poisoned-memory auditor would need full reimplementation.
- **Comparison position:** **`not_transportable`** (post-hoc audit, not an access-time governance policy) — main-table excluded.

### GateMem — a benchmark, not a memory method

- Paper: "GateMem: Benchmarking Memory Governance in Multi-Principal Shared-Memory Agents", arXiv 2606.18829. Repo: [rzhub/GateMem](https://github.com/rzhub/GateMem), **MIT**; dataset Ray368/GateMem on HF, **CC-BY-4.0**; public leaderboard. 91 multi-party episodes, 2,218 hidden checkpoints; metric `MGS = U × (1−A) × (1−F)` (utility, access control, active forgetting).
- **No-GPU reproduction:** episode/checkpoint construction is CPU; evaluation is LLM-judged across 7 agents × 6 backbones → **API-bound**, zero GPU need if backbones are API-based.
- **Comparison position:** **`not_transportable` as a method** (it is a benchmark). Candidate second-stage stress-test (doc 17, D3/D4 tier) once the unified reader is fixed; never a main-table row.

### CMI (query-local causal intervention) — open source, API-bound

- Paper: "Causal Intervention-Based Memory Selection for Long-Horizon LLM Agents", arXiv 2605.17641. Repo: [Saksham4796/causal-memory-intervention](https://github.com/Saksham4796/causal-memory-intervention). **License: not found — unverified.** Method: per candidate, three controlled conditions (no-memory / with / perturbed) → `Utility = s_with − s_no`, `Stability = s_with − s_pert`; keep iff `Utility > 0 ∧ Stability ≥ 0`.
- **No-GPU reproduction:** default model GPT-4o-mini via API (**`OPENAI_API_KEY` required**); a keyless debug pipeline with deterministic fallbacks exists; `--max_examples`, `--skip_llm_judge`, caching flags exist precisely because CMI costs several LLM calls per example. **No GPU needed.**
- **Comparison position:** R3-pending; `causal_item` proxy row (the query-local do-effect estimator). Theorem 2 (doc `11-`/`14-`) shows this *exactly correct* query-local effect still cannot authorize lifecycle decisions — the proxy row instantiates that failure on the shared stream.

### Trivium — no code

- Paper: "Trivium: Temporal Regret as a First-Class Objective for Causal-Memory Controllers", arXiv 2606.04421 (Stanford; also ACM Books). Episodic memory revised via **budgeted causal probes**; three-regret framework; `O(log E)` temporal regret. **No repository found.**
- **Reproduction path:** reimplement the causal-log + probe machinery from the paper's formal description; the controlled SCM testbed is CPU-runnable; the 70B-pilot results need GPU/API. CausalBench-Seq data not publicly located.
- **Comparison position:** R3-pending; `trivium` probe-layer row in the cost-contract comparison (its probing policy is the closest published analog of SQCAD's paid probe channel — used as the paired-probe control in the cost-contract experiment).

### GovMem — no code, no data

- Paper: "When Not to Write Memory: Governing False Promotion from Correlated Agent Traces", IEEE Xplore 11607557 (2026). Write-time conservative reference policy: promote/reject/needs-review from dependency-aware support + counterevidence retrieval. **No repository; trace datasets and adjudication labels are project-internal.**
- **Reproduction path:** the full decision procedure is disclosed; reimplementation possible, but validation data (79 traces / 120 labeled candidates) is not public, so any reimplementation can only be compared on our own traces.
- **Comparison position:** R3-pending; write-time family alongside SAGE — no main-table row unless a transport protocol is defined.

### ActMem — open source, GPU-bound (the only one)

- Paper: "ActMem: Bridging the Gap Between Memory Retrieval and Reasoning in LLM Agents", arXiv 2603.00026 (Nanjing University Websoft). Repo: [nju-websoft/ActMem](https://github.com/nju-websoft/ActMem). A LICENSE file exists; type **unverified**. Pipeline: atomic facts → clustering → causal+semantic KG → counterfactual retrieval.
- **No-GPU reproduction: no.** Fact clustering uses **Qwen3-Embedding-8B** — an 8B embedding model, not realistically CPU-runnable; this is the *only* audited baseline whose blocker is genuinely a GPU. Backbones DeepSeek-V3 / GPT-4o-mini are API-based.
- **Comparison position:** R3-pending; not in the 11-paper closest-work set (audited here because it is a reasoning-coupled memory system). Lowest priority for reproduction given the GPU wall.

**Key findings.** (1) Only **one** audited baseline is genuinely GPU-blocked: ActMem (8B embedding). Everything else is **API-key-bound**, not GPU-bound — the no-GPU environment is not the main wall; missing LLM endpoints are. (2) **Oblivion's code is public but proprietary-licensed** — it can be run and audited locally but must not be redistributed and must be described as closed-source in the paper. (3) **Five systems have no official code** (FadeMem, Memory Worth, DeMem, Trivium, GovMem); all disclose enough for behavioral proxies, which is exactly what the unified contract's proxy rows are, labeled `not reproduced`. (4) **GateMem is a benchmark**, SAGE/MemAudit are write-time/post-hoc systems — none maps to an access-time governance policy, so all three stay `not_transportable` with no main-table numbers (claim discipline, `docs/实验证据链/09`).

## 4. What this means for the doc-17 plan, executed without GPU

1. **R1/R2 tiers: fully executable now** (CPU, deterministic, in-repo) — already frozen in the unified-contract main table (`src/sqcad/unified_baseline_runner.py`).
2. **Retrieval protocol on LongMemEval-S and LoCoMo: executable now** (BM25 CPU path verified above; MiniLM-dense already run locally). This is the first public-data deliverable.
3. **LoCoMo QA scoring: executable without any judge LLM** — the official metric is deterministic token-F1. Only *answer generation* needs an endpoint; a local reader (any CPU LLM, or even a rule-based reader for the retrieval-protocol stage) can produce answers that the official scorer evaluates.
4. **End-to-end QA with the paper's readers (GPT-4o-mini etc.): blocked** — recorded honestly as an environment fact, not silently replaced by paper-reported numbers.
5. **R3 official reproductions: blocked at the R2/R3 gate** (API keys for SimpleMem/Oblivion/CMI; GPU for ActMem), with two exceptions worth prioritizing: **Oblivion** and **SimpleMem** are locally frozen (R1 done) and their non-LLM machinery is CPU-runnable — unit tests, data readers and retrieval-layer components can be verified offline *now*, narrowing what still needs endpoints later.
6. **The comparison claim stays calibrated:** in the unified contract, SQCAD's full row must use the dynamic lifecycle runner; until then `risk_gated_decomp_abstract` is reported as a controlled proxy (doc 17 §5.2). Official-system rows stay `not reproduced` / `not_transportable` until the R3/M1 gates pass.
