## 1. 分层指标设计（不同维度，互不替代）

三层指标必须不同，因为三环证据回答的问题不同：

| 层 | 服务环节 | 指标集合 | 证明的维度 | 不可用于 |
|---|---|---|---|---|
| **L1 理论指标** | 环 1/2 | 提交斜率、max regret 下界、minimax 探测下界、识别集合分离、配对恒等式 | 必要条件/充分条件的存在性（结构因果） | 系统性能对比 |
| **L2 公开数据指标** | 环 4 | Hit、evidence recall、LoCoMo 官方 token-F1（必要时补 LongMemEval 原生 QA）、persistent/exposure tokens、probe/restore、候选覆盖、成本 Pareto | 在真实轨迹上检验“当前任务质量不低于最低约束”时的持久存储与访问效率；只提供外部效度 | keep/archive 的因果资格证明（没有同源未来金标） |
| **L3 自建数据指标** | 环 5 | 当前/未来任务效用、lifecycle_value_keep/archive、tau_keep_archive、oracle 一致率、false-commit / safe-commit / abstention precision、lifecycle regret、false-forgetting、harmful-retention、rare-bridge rescue、archive-induced false forgetting、probe action-change rate、restore precision、time-to-recovery、scope/version mismatch detection | 在同一未来反事实中检验持久动作的未来价值、风险与成本，并与当前质量联合形成 Pareto 前沿 | 直接外推到真实部署 |

### 1.1 指标强调级别（主 / 次 / 不强调）

每环主张只依赖其”主”指标；”次”指标仅作报告；”不强调”指标出现差距时如实报告（`16-` bm25 召回、`20-` memory_worth 等价行均照此执行）。级别在运行前固定，防止事后挑选有利指标（评审要求 §4.3；核查依据 `24-` §3.1）：

| 层 | 主（主张依赖） | 次（仅报告） | 不强调（差距如实报告） |
|---|---|---|---|
| L1 理论 | 下界成立性（存在性证明：$\Theta(T)$、$\log(1/\delta)/\operatorname{KL}$、配对恒等式） | 斜率常数（$\tau p$、$1.06\times$） | —（结构证明不用于系统性能对比） |
| L2 公开 | 当前质量约束下的持久存储—暴露—探测成本 Pareto，以及 Guard 对候选覆盖的修复 | Hit/Recall、token-F1、probe/restore 明细 | 单独按 BM25/dense/RRF 的静态召回排名（检索差距不是 SQCAD 的长期治理主张） |
| L3 自建 | false-commit / safe-commit / abstention 精度、future utility、lifecycle regret、harm/false-forgetting | 当前任务质量、探测量、恢复延迟、time-to-recovery | 与 oracle 的绝对距离（oracle 是上界，不是可达目标） |

交叉约束（评审要求 §4.3“主/次/效率指标提前固定”）：L3 的 $\tau$ 用与 L2 同一成本合同计算，冻结常量为 $\gamma=0.9$、$v_{\mathrm{task}}=10$、$c_{\mathrm{harm}}=20$、$c_{\mathrm{exposure}}=0.05$、$c_{\mathrm{probe}}=1$、$c_{\mathrm{storage}}=0.01$、$\tau_{\mathrm{tol}}=0.5$（实现名见 `frozen.py`）。这里的目标不是预设“牺牲准确率换存储”，而是检验：在 $Q_{\mathrm{now}}\ge q_{\min}$ 的最低当前质量约束下，是否能降低持久存储；若质量、未来价值和成本发生冲突，则报告 Pareto 前沿与敏感性，而不是单一总分。

### 1.2 当前质量—持久成本—未来价值的统一主张

论文主体采用约束优化而不是“准确率越低越省存储”的叙述。对策略 $\pi$，定义当前任务质量 $Q_{\mathrm{now}}(\pi)$、未来折扣效用 $V_{\mathrm{future}}(\pi)$、持久存储 $S(\pi)$、上下文暴露 $E(\pi)$、探测成本 $P(\pi)$ 和危害惩罚 $H(\pi)$。核心比较写成：

$$
\max_{\pi}\; V_{\mathrm{future}}(\pi)-\lambda_S S(\pi)-\lambda_E E(\pi)-\lambda_P P(\pi)-\lambda_H H(\pi)
\quad\mathrm{s.t.}\quad Q_{\mathrm{now}}(\pi)\ge q_{\min}.
$$

其中 $q_{\min}$ 是预先冻结的最低当前质量，而不是事后根据 SQCAD 结果选择的阈值。L2 只能估计 $Q_{\mathrm{now}}$、$S$、$E$、$P$ 及其公开轨迹上的覆盖代理；L3 才能利用 keep/archive 同源未来估计 $V_{\mathrm{future}}$、lifecycle regret、false-forgetting 和 harmful-retention。若没有策略在所有维度都不差，统一结论必须写成“质量—存储—暴露—未来价值的 Pareto 权衡”。

**核心基线执行门**：FadeMem、Memory Worth、DeMem 三个命名代理必须在同一 frozen stream、reader、budget、evaluator、seed 与成本合同下各跑一行，并以“代理”单独分栏；若后续得到可验证官方实现，再新增“官方复现”行而不覆盖代理结果。SimpleMem 与 Oblivion 保留已验证层和未验证层的拆分。ReMe 只有在 Phase B 提供相同的程序执行回路后才进入数值主表。

**原论文指标与统一合同的关系**：具名论文的原生指标保留为背景/复现表，不直接替换 L2 主表。Oblivion 原论文明确包含 LongMemEval 静态 QA 和 GoodAI-LTM 动态交互任务；FadeMem 主要报告多跳推理/检索表现与存储减少；Memory Worth 以暴露后 success/failure 共现形成条件成功概率；SimpleMem 报告答案质量、检索效率和推理成本；DeMem 以固定记忆/运行预算下的决策质量与压缩损失为核心。上述指标回答的是各自论文的任务问题，具体数值只有在模型、prompt、reader、judge、预算和数据协议完全对齐后才能进入“官方端到端复现”列。当前 SQCAD 的 L2 主表仍使用统一 reader/evaluator，Oblivion 只进入 decay-core 验证，不能把其原论文 QA 数字写成本文本地复现结果。

## 5. 环 3：框架设计（三层 + 资格授权）

**设计**（`10-` §8 + `21-`）：
- Evidence 层：不可变证据日志（沉默语义：未暴露 $\ne$ 不存在）；
- Qualification 层：资格证书

$$
\tau(i,s)=V_s^\pi(\operatorname{keep}_i)-V_s^\pi(\operatorname{archive}_i),
\qquad \tau(i,s)\in[L,U].
$$

  - $L>0\Rightarrow\operatorname{keep}/\operatorname{restore}$；$U<0\Rightarrow\operatorname{archive}$；$L\leq0\leq U\Rightarrow\operatorname{defer}$ 或 VOI probe，其中

$$
\operatorname{VOI}=C_{\mathrm{defer}}-\left(C_{\mathrm{probe}}+R^\star(L',U')\right),
\qquad
R^\star(L,U)=\frac{U(-L)}{U-L}.
$$
  - 识别集合跨动作边界不允许"低 regret 随机 commit"（最小安全提交条件）；
- Access 层：资格投影（先移除被授权 archive 的对象）→ 排序投影（冻结 proposer 在资格兼容对象内选 top-$B$）。检索器只能决定"先看谁"，不能决定"谁长期留下"。

**实现**：`src/sqcad/qualification_access.py`（QualificationCertificate / decide_persistent_action / ProbeOption·probe_value / plan_access）+ 5 项结构测试（tests/test_qualification_access.py 全过）。

**指标（L1 派生）**：interval coverage、false-commit rate、safe-commit rate、action sign error（E1 验收）。

**待办**：E1 受控资格授权恢复实验（`21-` §3 E1：在 identification_recovery_experiment 上输出每 memory-scope 证书，treatment 随机化 keep/archive）。

### 10.1 结果反馈（最终版本，2026-08-19）

本节把已完成实验反馈回方案本身；详细过程和原始结果仍见 `03-实验证据链/`，主体实验总括见 [01-论文主体实验总括与结果反馈](01-论文主体实验总括与结果反馈-20260819.md)。

| 实验结果 | 对实验方案的反馈 | 当前方案调整/主张边界 |
|---|---|---|
| Gap A/B/C、T1/T2/P4 与识别恢复通过各自验证范围 | 理论问题不是检索排序，而是持久动作 lifecycle value 的识别和 evidence availability | 保留 L1 作为理论边界；不把理论下界当 benchmark 排名 |
| 公开集修复后 SQCAD `0.754/0.115`（LME-S Hit/Recall），Guard-1 `0.902/0.151`；LoCoMo F1：原 SQCAD `0.03391`、Guard-1 `0.04511`、BM25 `0.04538` | 主要 bad case 是候选覆盖不足；一次性 guard 能修复覆盖，而不必放宽持久资格 | Guard-1 定为推荐主配置；表述为与 BM25 F1 持平和质量—存储 Pareto，不写“全面超越” |
| dense/RRF 的静态覆盖高于 SQCAD，但存储量保持 `74,092.1` tokens；SQCAD/Guard 存储约 `1,631` tokens | 公开集同时验证任务覆盖和资源代价，不能只按 Recall 排名 | L2 主张固定为治理成本—覆盖外部效度；检索排名只作次要诊断 |
| LifecycleBench 首轮矩阵：`probe_willing` value `+0.865`，`SQCAD + lineage_conflict→archive` `−0.278`，原 certificate `−8.901` | lineage conflict→archive 是必要的框架修改；hitchhiker association-only 不应默认 keep；scope 前瞻仍有缺口 | 将 lineage 修改纳入当前方案；把 probe-willing 作为风险规避强对照；scope 前瞻留给 Phase B |
| LifecycleBench R1/R3/R5/R7 通过，R2 显示 GAMMA/TAU_TOL 敏感，R6 待外部 | 自建集可审计、可重建，但参数域和人类语义锚仍限制外推 | 结果只解释在冻结合同有效域内；不把规则世界写成真实部署证明 |

**主体实验的最终反馈结论：** SQCAD 的核心贡献应表述为“识别约束下的 Evidence–Qualification–Access 治理及其可审计实验协议”。当前结果支持统一合同下的治理—成本 Pareto、候选覆盖修复和规则世界中的生命周期反事实测量；不支持“真实 Agent Memory 已全面胜过 SOTA”的表述。Phase B 端到端、R6 人类锚和完整具名基线复现仍是开放工作包。
