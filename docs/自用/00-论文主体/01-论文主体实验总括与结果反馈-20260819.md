# SQCAD 论文主体实验总括与结果反馈

> 本文是 `00-论文主体` 的实验总括入口。它把[完整实验方案](23-SQCAD完整实验方案-理论公开自建消融-20260817.md)中的设计、指标、基线和结果反馈整理成论文可写的顺序。详细实验报告仍在 `../03-实验证据链/`；本文和 23 负责吸收结果、更新主张和记录尚未完成的实验。

## 1. 论文主体实验要回答什么

论文主体不试图用一个总分证明所有事情，而是分开回答四个问题：

1. **理论边界**：为什么普通关联、衰减或 query-local 相关性不能直接授权持久记忆动作？
2. **公开轨迹外部效度**：在真实长期对话流上，SQCAD 能否在有限存储和暴露成本下保持证据覆盖与任务质量？
3. **反事实内部效度**：在同一未来流下，`keep/archive` 对长期价值、错误保留和错误遗忘的影响是什么？
4. **机制必要性与工程可信度**：probe、restore、lineage、candidate guard 等机制是否产生可观测收益，结果能否跨环境重建？

因此实验顺序是：

```text
L1 理论边界
  -> E-Q-A 框架与授权协议
  -> L2 公开数据（外部效度）
  -> L3 LifecycleBench（反事实内部效度）
  -> 消融、基线、公平性和复现审计
```

## 2. 实验设计、指标和基线的对应关系

| 层 | 数据/实验 | 主指标 | 为什么用这些指标 | 主要基线 |
|---|---|---|---|---|
| L1 | 受控 Gap、T1/T2/P4、识别恢复 | 下界成立性、regret slope、CI coverage、false decision、识别集合是否跨边界 | 证明结构性必要性/充分性，不比较系统排名 | W0–W3、random/UCB/OPE、forced commit、probe/defer |
| L2 | LongMemEval-S、LoCoMo、chronological overlay | Hit、evidence recall、官方 token-F1、storage/exposure tokens、probe/restore、成本 Pareto | 公开集没有 keep/archive 金标，只能测真实轨迹上的覆盖、答案和资源效率 | BM25/dense/RRF、keep-all/FIFO/LRU/recency/decay、SQCAD/Guard、具名方法的可迁移层 |
| L3 | SQCAD-LifecycleBench，1380 个 keep/archive 同源反事实 episodes | lifecycle regret、false-commit、safe-commit、abstention、false-forgetting、harmful-retention、rare-bridge rescue、restore/probe 指标 | 直接测持久动作的未来价值和治理风险 | oracle、probe-willing、keep-all/archive-all、recency/frequency、Memory Worth/FadeMem/Oblivion/DeMem 代理、消融 |

### 指标解释纪律

- L1 的下界和斜率用于证明理论命题，不能当系统性能排名。
- L2 的 Hit/Recall/F1 只说明证据覆盖与答案质量，不能单独证明 lifecycle causality。
- L3 的主指标是 false-commit、safe-commit、abstention precision 和 lifecycle regret；oracle agreement 是上界诊断，不是可达 SOTA。
- storage/token 减少必须和任务效用、错误遗忘、危险保留及 probe 成本一起解释。

### 基线解释纪律

- BM25/dense/RRF 是检索和覆盖对照，不是长期治理方法。
- keep-all、FIFO、LRU、recency、frequency decay 是无治理/普通衰减对照，对应 T1/T2 的失败模式。
- FadeMem、Oblivion、Memory Worth、DeMem、SimpleMem 是具名机制对照，但必须区分官方复现、官方代码级验证、行为代理和不可迁移行。
- `oracle_policy` 是上界，不应写成普通 baseline；原 SQCAD、Guard-1/2/4 和 no-* 开关才是框架内部对照。

## 3. 结果反馈：L1 理论与机制实验

| 实验 | 结果 | 对主体方案的反馈 |
|---|---|---|
| Gap A/B/C | 观测等价但 lifecycle 符号翻转；local effect 可相同而长期价值相反；source 不自动 transport | 保留“识别层 Gap”作为论文核心问题，不把问题写成单纯检索质量不足 |
| Theorem 3 Stage 1 | bias `−0.47`；CI `12/12`；自信错误 `0`；3 个 neutral 输出 `unresolved` | 保留协议路线作为充分性验证；观测 g-formula/完整 lifecycle DR 仍不能写成已完成 |
| Theorem 3 Stage 2 | adoption、co-exposure、eligibility、drift、scope 五类违反被 gate 标记为 `unresolved/mismatch`；盲强制版本 regret 约 `41.0/83.4` | 保留 Qualification gate 的失败退守语义，不声称弃权无成本 |
| Theorem 4/5 | committing 下界 `660`、错误概率至少 `0.5`；安全提交要求识别区间不跨动作边界 | 将 `defer/probe` 写成理论必要性推论，而不是工程偏好 |
| T1/T2/P4 | 无恢复 slope `5.8500`；配对恒等式 `11700.0`；P4 探测复杂度达到 `log(1/delta)/KL` 量级 | 保留 restore/evidence-availability/probe 作为最小机制，并把成本纳入后续比较 |

### 4.3 公开集结果证明什么

1. 原 SQCAD 的主要 bad case 是一次性候选覆盖不足；受限 candidate guard 可以显著修复覆盖，且不放宽长期资格授权。
2. Guard-1 与 BM25 的 LoCoMo F1 持平，但 BM25/dense/RRF 的静态覆盖更高、存储成本也更高；因此当前结论是质量—存储—暴露的 Pareto 权衡，不是全面胜出。
3. Guard-2/4 提高覆盖和 F1，同时增加治理/探测成本；Guard-1 是推荐的最小修复配置。
4. 公开集不能单独证明 `keep/archive` 的因果生命周期价值，因为没有同源未来反事实分支。

## 5. 结果反馈：L3 LifecycleBench

LifecycleBench 包含 1380 个 episodes，六个机制家族、三个 controls 和观测等价配对；public trace、policy log 和 hidden oracle 分层，远端重建 hash 一致。

| 策略 | Mean lifecycle value | Regret | Oracle agreement | False-commit |
|---|---:|---:|---:|---:|
| oracle policy（上界） | `+0.964` | `0.015` | `1.000` | `0.000` |
| probe-willing | `+0.865` | `0.115` | `0.906` | `0.072` |
| SQCAD + lineage conflict→archive | `−0.278` | `1.258` | `0.744` | `0.228` |
| archive-all | `−2.790` | `3.770` | `0.459` | `0.000` |
| Memory Worth/storage12 proxy | `−3.476` | `4.455` | `0.703` | `0.181` |
| 原 SQCAD certificate/event rule | `−8.901` | `9.880` | `0.663` | `0.409` |
| keep-all/recency2 | `−10.280` | `11.260` | `0.541` | `0.409` |

### 5.1 自建集结果反馈

- `lineage_conflict → archive` 显著改善，相比原 certificate 规则平均提升 `8.62`；该修改进入当前框架反馈。
- 只有 hitchhiker association 的 unresolved 情形不应默认 keep；`probe-willing` 是当前规则世界中最强的风险规避对照，平均 value `+0.865`。
- `future_in_s2` 暴露了 scope 前瞻缺口；当前只确认问题，尚未完成 Phase B 端到端修复。
- `memory_worth` 与 `storage12` 在当前特征下逐 episode 同动作，必须标为代理等价行，不能解释成独立方法胜负。
- R1/R3/R5/R7 审计通过，R2 显示 GAMMA/TAU_TOL 的经济参数敏感区，R6 人类锚定尚待外部判官。

### 5.2 自建集结果能证明什么

它证明的是：在冻结的规则世界和反事实合同中，资格/授权策略可以被直接按长期价值、regret 和错误提交评分，并能定位框架修改点。它不证明该数据集代表真实 Agent Memory 分布，也不构成真实部署或 SOTA 结论。

## 6. 论文主体最终实验结论

当前论文主体可以形成的结论是：

> SQCAD 将持久记忆治理拆分为 Evidence、Qualification 和 Access。L1 证明了常用关联、局部因果和普通无恢复提交在特定未识别/自遮蔽类上的结构性限制；L2 公开数据表明，受限 candidate guard 可以在显著更低的存储规模下修复证据覆盖 bad case；L3 反事实 LifecycleBench 使 keep/archive 的长期价值和错误治理风险可直接测量，并给出了 lineage 冲突和 hitchhiker 处理的定量修改方向。

必须同时写明：

- 公开集的检索覆盖仍落后于 dense/RRF，Guard-1 只是与 BM25 F1 持平；
- 具名方法的完整端到端复现尚未完成，代理行不能升级为官方系统结论；
- LifecycleBench Phase B、R6 人类锚定和完整观测路径估计仍未完成；
- 因此当前声称是“统一合同下的治理—成本 Pareto 与反事实内部效度”，不是“全面 SOTA”。
