## 1. 三要素论证框架

在基础理论空白（环 2）与自有框架（环 3）已确立的前提下，剩余论证目标只有一个：**证明 SQCAD 框架在可检验维度上优于既有方案，并明确框架仍需修改的方向**。该目标可分解为三个可执行组件：

| 组件 | 回答的问题 | 当前状态 | 缺口 |
|---|---|---|---|
| **数据** | 主张在哪些场景上检验？ | L2 公开（LongMemEval-S / LoCoMo / overlay）+ L3 自建（LifecycleBench 1380） | 端到端 agent loop（Phase B）；2026 新生态盘点（§2） |
| **指标** | 主张如何被可测化？差异能否被看出？ | L1/L2/L3 三层指标 + R1–R8 公允性防线 | 主/次/效率指标显式化；人类锚 κ 执行（§3） |
| **基线** | 与谁比较？复现是否可信？ | 18 策略主表 + LB 矩阵 + 5 具名代理/官方层 | 核心具名基线执行门；闭源 SOTA 参考价值界定（§4） |

结论先行：**数据不缺数量、指标不缺体系、基线不缺清单——三者的缺口都在执行层（Phase B、R6、具名基线扩展），不在设计层。** 本轮核查补一个公开数据集（MemoryAgentBench）与一个方法论引用（MemDelta），其余保持。

### 2.2 生态盘点与筛选判据

2026 年 Agent Memory 评测生态较 2025 年显著扩张（web 核查 2026-08-18）：LongMemEval/LoCoMo 之外出现 MEM 类新基准——EverMemBench（>1M token，oracle evidence 隔离检索/阅读）、MemBench（参与/观察、读写容量悬崖）、StructMemEval（结构状态追踪）、LoCoMo-Plus（潜在约束的记忆）、MemoryArena（记忆—Agent—环境闭环）、AMB/BEAM（agentic 任务 + 成本追踪）、MemDelta（受控评估协议而非数据集）。另有工程生态（Mem0/Cognee/Graphiti/Letta 等）不属学术基准。

**加入判据**（数据主张的检验价值 = 场景覆盖 × 可核验性 × 统一合同可迁移性 × 可达性）：

1. 覆盖 SQCAD 治理主张的失败模式：版本冲突、低频关键、有害保留、作用域漂移、self-obscuring；
2. 金标可独立核验（oracle/隐藏层/确定性指标），不依赖黑盒 LLM judge 才能计算；
3. 可嵌入统一合同（chronological stream、成本记录、冻结 reader/evaluator）；
4. 许可与资源可达（无 GPU 无 API key 环境下 CPU 可跑核心指标）。

### 2.3 核查结论

| 候选 | 判定 | 理由 |
|---|---|---|
| **MemoryAgentBench**（ICLR 2026, MIT） | **加入，作为 L2 第二战场** | peer-reviewed；四能力（多跳检索/测试时学习/长程理解/冲突消解）中**冲突消解与测试时学习正是 SQCAD 资格治理的场景映射**；核心字符串指标（`exact_match`、`Recall@5`）CPU 可跑（`15-` 已审计）；增量 multi-turn 协议与统一合同兼容。缺点：部分子集需 GPT-4o judge（该子集列为 `not reproduced`，不填伪数字） |
| EverMemBench | Phase C 候选，暂不加入 | oracle evidence 设计优秀（与我们 R5 独立实现同构），但 >1M token 评测成本与本机环境不匹配；等 Phase B 端到端后再评估 |
| AMB / BEAM / MemBench / StructMemEval / LoCoMo-Plus / MemoryArena | 记录在案，不加入本轮 | 新近发布、无统一合同先例、多数依赖 LLM judge 或长上下文 API；与当前主张（资格治理而非检索架构）匹配度低于 MemoryAgentBench |
| **MemDelta**（受控评估协议） | **并入统计协议 §9 方法论引用** | 与我们的统一合同方法同构（一次只变一个组件、固定 embedding/模型、分层报告、报告写路径成本）——作为统一合同方法论的外部正当性来源，也是评审防守点：我们已满足其全部建议，且额外提供了冻结 manifest 与 hash 链 |

### 2.4 数据维度总判断

- 已有数据的场景覆盖是**完备的**：LME-S/LoCoMo 提供真实轨迹外部效度，overlay 提供治理目标注入，LifecycleBench 提供反事实金标内部效度；
- 真正的缺口是**端到端真实 agent loop**（LifecycleBench 是规则世界，公开集无生命周期金标）——这由 Phase B 解决，**不是再引入数据集能解决的**；
- 引入更多数据集会稀释统一合同的可维护性（每增一个数据集 = 一组新 frozen 资产 + 一组 hash 链），收益边际递减。

## 3. 指标核查

### 3.1 三层指标—主张映射（含强调级别）

| 层 | 服务环节 | 指标集合 | **强调级别** | 不可用于 |
|---|---|---|---|---|
| **L1 理论** | 环 1/2 | 提交斜率、max regret 下界、minimax 探测下界、识别集合分离、配对恒等式 | **主**：下界成立性（存在性证明）<br>次：斜率常数 | 系统性能对比（结构证明不能当胜出指标） |
| **L2 公开** | 环 4 | Hit、evidence recall、LoCoMo 官方 token-F1、storage/exposure tokens、probe 数、候选覆盖、成本 Pareto | **主**：治理策略资源效率与覆盖（成本 Pareto、Guard 修复）<br>**不强调**：Hit/Recall 排名（bm25 静态召回上界领先是如实报告的检索质量差距，不是本框架主张） | 因果资格证明（无生命周期金标） |
| **L3 自建** | 环 5 | lifecycle value、oracle 一致率、false-commit、lifecycle regret、false-forgetting、harmful-retention、rare-bridge rescue、probe action-change、restore precision、time-to-recovery | **主**：false-commit / safe-commit / abstention 精度与 lifecycle regret（治理因果）<br>次：探测量、恢复延迟<br>**不强调**：与 oracle 的绝对距离（oracle 是上界，不是可达目标） | 直接外推到真实部署 |

**强调纪律**：每环主张只依赖其"主"指标；"次"指标仅作报告；"不强调"指标出现差距时如实报告（16- bm25 召回、20- memory_worth 等价行均照此执行）。这是"主/次/效率指标提前固定"的具体化——防止事后挑选有利指标。

### 3.2 主观先验审计（"自娱自乐"风险的对冲结构）

| 主观先验来源 | 是否存在 | 对冲机制 | 状态 |
|---|---|---|---|
| 成本合同参数（$\gamma=0.9$、$v_{\mathrm{task}}=10$、$c_{\mathrm{harm}}=20$ 等） | 是（经济/判定参数） | R2 敏感性扰动 31 组：翻转率 <5% 稳健；5–30% 敏感区如实报告；>30% 重定位（GAMMA/TAU_TOL 已重定位至有效域） | ✅ 已执行 |
| oracle == 设计者意图（标签真值由设计者规则生成） | 是 | R5 独立实现位级一致（第二实现仅凭文档重写，1380/1380）；R3 未见机制 holdout（660 episodes，12/15 转移 + 3 机制边界如实报告）；R6 人类锚 $\kappa \ge 0.6$（28 case 已导出，判官批次待外部） | ✅ R3/R5 已执行；R6 待外部 |
| 场景设计与注入方式（overlay E1–E5） | 部分 | 全部程序化标签 + 预注册 seed + 冻结 manifest；evaluator 为同一诚实反事实 | ✅ |
| 指标选择（事后挑指标） | 否 | 必胜区表 R4 预注册（13 行全命中）；指标—主张映射表（§3.1）固定强调级别 | ✅ |

**结论**：指标体系的结构性风险（主观先验 → 自娱自乐）已被四通道防线（真值可独立检验 / 失败可以发生 / 泛化可被挑战 / 评价不可被猜）与 R1–R8 逐条覆盖。**剩余风险在执行层**：R6 外部判官未执行、Phase B 端到端未验证——这两项完成后才能把"规则世界结果"升级为"端到端结果"表述。

### 3.3 指标缺口与修订

1. **主/次/效率指标显式化**（§3.1 强调级别列）——已写入 23- 方案 §1；
2. **LifecycleBench 补充效率指标**：p95 latency（生命周期评估无此维度，端到端 Phase B 引入）——待 Phase B 协议冻结时一并写入；
3. **R6 执行**：判官批次是唯一未执行的外部验证通道（待外部，28 case 已盲化导出）。

## 4. 基线核查

### 4.1 重点比对清单（谁是重点）

按"与 SQCAD 主张的信号重叠度 × 复现可信度"排序，**核心比对对象为 5 个具名治理系统 + 原 SQCAD + 简单规则族**：

| 优先级 | 基线 | 核心信号 | 对应 SQCAD 主张 |
|---|---|---|---|
| **核心** | **FadeMem** | 语义相关性 × 访问频率 × 时间模式的差异衰减 | 差异衰减是否优于资格治理 |
| **核心** | **Oblivion** | utility/access-frequency decay activation | decay 驱动的访问控制 vs 资格授权 |
| **核心** | **Memory Worth** | success/failure 共现 → trust/suppression | 结果反馈关联信号 vs 持久动作因果 |
| **核心** | **DeMem** | 决策充分性区分压缩 | 压缩 vs 资格保留的行动区分 |
| **核心** | **SimpleMem** | 写时 salience + 检索 gating | 写时压缩+门控 vs 三层治理 |
| 重要 | 原 SQCAD（v0.1） | 资格 + 竞争访问 | 框架自身消融基线（Guard 修复前后） |
| 重要 | keep-all / FIFO / LRU / recency / frequency-decay | 无治理/时间频率衰减 | T1/T2 理论失败模式的实例化 |
| 补充 | SAGE（Apache-2.0 开源） | 写侧新颖性门控（von Mises–Fisher 密度估计） | 写时准入 vs 读时资格治理 |
| 登记 | ReMe | 程序经验精炼 | Phase B 过程记忆对照（需可比 agent loop） |

**不列为重点**：BM25/dense/RRF（检索架构基线，回答"检索质量"而非"治理"问题，作覆盖上界与成本对照）；MemGPT/Mem0/Letta（工程记忆框架，无治理主张可对测）。

### 4.2 复现状态审计（开源/闭源/代理）

| 基线 | 许可 | 官方实现状态 | SQCAD 侧当前行 | 升级条件 |
|---|---|---|---|---|
| FadeMem | 未确认（同名视频仓库身份不符，官方 Agent-Memory 实现未核实） | 未获证 | `fademem` **行为代理**（差异衰减公式） | 找到官方仓库 → 复核 → 升为官方复现行 |
| Oblivion | **专有许可**（NEC Labs，代码公开可读） | decay 数学逐字验证 ✅；完整系统受 Python 3.12/端点/依赖阻塞 | decay-core 验证行 + `not reproduced` 完整系统 | 环境解锁后补端到端 |
| Memory Worth | 未确认 | 未核实（无官方实现） | `memory_worth` **estimand-faithful 行为代理** | 官方代码出现后复核 |
| DeMem | 未确认 | 无官方实现 | `demem` **decision-distinction 行为代理** | 同上 |
| SimpleMem | MIT | 官方读取器 + 词法评分层已验证 ✅；LLM 压缩/嵌入/生成未复现 | 官方代码级验证行 | 本地 LLM 路径补全 |
| SAGE | Apache-2.0（mem0 fork） | 未核实 | 待加入 | 复核后按统一合同运行 |
| ReMe | 未确认 | 未核实 | `not transportable`（无等价执行闭环） | Phase B |

**执行门**（来自 23- §2.2）：代理与官方复现分栏；缺实现身份/commit/hash/传输公式/不可迁移组件/seed 任一项即降级为"未复现"。

### 4.3 闭源 SOTA 参考价值界定（以 Oblivion 为例）

| 维度 | 事实 | 参考价值判定 |
|---|---|---|
| 论文报告的评估设定 | Oblivion 论文在其自有设定（自建评测轨迹 + 指定模型）上报告数字 | **不可直接引用**为同场比较：reader、候选流、预算、成本合同、seed 均不同 |
| 我们可获得的 | 官方 decay 数学逐字验证（代码级） | **高价值**：机制的精确事实（做什么、不做什么）可比 |
| 统一合同下的行动 | 按官方 decay 方程实现 `not reproduced` 行为代理行，在相同 frozen stream/budget/evaluator 下跑 | **唯一允许的数值比较通道**：同合同同指标 |
| 对"框架更好"主张的作用 | 只能支持"在同一合同下，SQCAD 的资格治理优于其 decay 信号"这类限定比较 | 不构成"SOTA 全面超越"声称（23- §12 边界） |

**通用原则**：任何闭源基线的参考价值 = 机制事实（代码级可验证，高）+ 报告数字（设定不可比，低）。数值比较只允许发生在统一合同内部。

### 4.4 基线维度结论

1. 重点比对对象已收敛为 5 个具名治理系统（FadeMem/Oblivion/Memory Worth/DeMem/SimpleMem）+ 框架自消融（原 SQCAD/Guard）；
2. 复现分层（官方复现/官方代码级验证/行为代理/不可迁移）已固化，代理行一律分栏标注；
3. 闭源 SOTA 的机制事实进入统一合同（Oblivion decay-core 已做到），报告数字不进入任何比较表；
4. **新增**：SAGE（Apache-2.0）加入复核队列——写侧门控与 SQCAD 读时资格是互补视角，低成本（mem0 fork 可本地跑）。
