## 2. SimpleMem open-weight 完整复现

### 2.1 协议（30- R1 "open-weight substitute protocol reproduction"）

| 层 | 官方（论文） | 本行替换 | 说明 |
|---|---|---|---|
| 压缩 LLM | GPT-4.1-mini | **Qwen3-8B（temperature 0）** | 官方 MemoryBuilder 原样（窗口结构化压缩，无代词+绝对时间锚定） |
| 检索 | 混合检索（planning/reflection 默认开） | 官方 HybridRetriever 原样 | top_k = 官方默认 5/3/10 |
| 嵌入 | text-embedding 类 | **Qwen3-Embedding-0.6B（fp16 加载）** | 官方仓库自带 qwen3 映射；fp16 为显存同驻约束（见下） |
| 答案生成 | LLM | **合同抽取式 reader** | 与 sqcad/bm25 行同 reader，只比较记忆管理机制 |

**open-weight 替代层的运行配置（官方代码零改动，以下均为替代层适配，如实披露）**：

1. **窗口化**：`add_dialogues(auto_process=True)` 走官方滑动窗口（WINDOW_SIZE=10, OVERLAP=2）逐窗口压缩 + 官方并行 worker（8 并发，vLLM 批处理）。初版误用 `auto_process=False` 导致 550 条消息滞留单窗口、单 prompt 32769 token 超限（400 BadRequest）——窗口化是官方默认语义，非本行改动。
2. **thinking 禁用**：Qwen3 默认 thinking 模式在响应前输出 `<think>` 块，官方 JSON 数组解析器无法处理。官方代码只对 dashscope base_url 注入 `enable_thinking`；本行在 openai client 的 `create()` 层注入 `extra_body.chat_template_kwargs.enable_thinking=False`（vLLM 接受的参数）——与官方 dashscope 路径注入的参数相同，官方代码零改动。
3. **JSON 数组约定**：官方 `USE_JSON_FORMAT=True`（json_object 模式）下 Qwen3-8B 输出 JSON 对象而非数组（官方解析器与 prompt 均要求数组）；关闭 json_object 强制后 Qwen 遵循 prompt 的 "Return a JSON array" 指令，官方 `extract_json` 宽松解析 fenced/前缀文本。
4. **fp16 嵌入**：官方 EmbeddingModel 以 float32 加载 SentenceTransformer（0.6B ≈ 2.4 GB）；vLLM util 0.72 预分配 22.6 GB 后同驻失败（util 0.9 时 28.8 GB 直接 OOM）。固定 `torch_dtype=float16`（同输出维度，语义不变）。
5. **嵌入单例**：官方 SimpleMemSystem 每次构造新建 EmbeddingModel——每 trace 重载 0.6B 模型导致显存累积（实测 60 traces 后 +2.8 GB，500 traces 必然 OOM）。类级单例（同模型名共享实例）语义等价，显存稳定在 ~4.7 GB。
6. **计数路由**：所有官方 LLM 调用经 CountingLLMClient（temperature 强制 0 + 调用/字数计数，threading.Lock 保护）；组件共享 `system.llm_client` 实例（main.py 构造时注入），包装在系统自建实例上（包装外部实例会完全失效——修复时确认的接线细节）。
7. **provenance**：实例级 MethodType patch 记录 entry_id → 来源窗口 dialogue ids（官方内部 `self._generate_memory_*` 调用链不经过包装器，实例属性绑定是唯一可靠注入点；生成逻辑 100% 官方）。
8. **max_tokens 上限（2048）+ 失败窗口计数**：官方代码从未设置 max_tokens（vLLM 默认 max_model_len=32768）；Qwen3-8B 对个别窗口触发退化生成（repetition loop）时单请求可生成数万 token，独占 vLLM 并阻塞整个 worker 池（全量初跑 19 分钟仅 5 traces，根因即此）。在 create() 层注入 `max_tokens=2048`（正常窗口输出 500-1500 token，仅切断退化；官方 3 次重试随即快速失败，该窗口返回 `[]` 并在输出中如实计数 `failed_windows`）。注意：退化输出是 Qwen3 对特定窗口的确定性行为（temperature 0 下重试输出相同），失败窗口统计用于披露，不改变官方管道。

- 合同评估：workspace = 检索条目的**来源消息**；存储 = 全部压缩条目 token（SimpleMem 全量保留无逐出，lifecycle 计数按构造为 0——如实标注"无生命周期管理"）。
- LLM 调用量/输入输出字数全部计数回传。
