## 3. 关键发现：`_version_map` 跨进程非确定性

### 3.1 现象

对同一数据、同一代码（`src/sqcad/public_unified_contract.py` 8/17 版）重复运行，`sqcad` 系列策略的指标出现 1–2 个样本（480 单位）级波动：

| 运行 | 环境 | LME `sqcad` hit | locomo `sqcad` hit |
|---|---|---|---|
| 16- 主表（8/14） | 本地 Windows / Py3.x | 0.7792 | 0.2198 |
| 第一次本地对照 | 本地 Windows / Py3.x | 0.7813 | 0.2218 |
| 第二次本地对照 | 本地 Windows / Py3.x | 0.7833 | 0.2181 |
| 远端（修复前） | AutoDL Linux / Py3.12 | 0.7771 | 0.2164 |

基础策略（`no_memory`/`keep_all`/`bm25`/`fifo`/`lru`/`recency`/`fixed_decay`/`frequency_decay`）在所有运行中逐项一致，波动只出现在依赖 `_version_map` 的 `sqcad` 系列。

### 3.2 机制

`_version_map` 中：

```python
for j, c in counts.items():                      # counts 插入序依赖 set(m.tokens) 迭代序
    if c >= overlap and msgs[j].session_id != m.session_id:
        updaters[m.msg_id].append(msgs[j].msg_id)
        newest[m.msg_id] = msgs[j].msg_id        # 最后一次覆盖者胜出 —— 非确定
```

`for t in set(m.tokens)` 的迭代顺序依赖字符串哈希（Python 进程间 `PYTHONHASHSEED` 随机化）。`counts` 的插入顺序因此跨进程不同，`newest[mid]` 取到哪个 updater（当多个消息满足重叠条件时）随之漂移，进而改变 `conflicted_unresolved` 与 eviction 决策。该缺陷只影响需要 `newest` 的 `sqcad` 系列；`_lineage_map` 已用 `sorted(counts, reverse=True)` + `break`，是确定的。

### 3.3 影响范围

- 指标波动：`sqcad` 系列 LME hit 约 ±2/480、locomo hit 约 ±1/10。
- 判定影响：120 个 sqcad-vs-外部基线（`no_memory`/`keep_all`/`bm25`/`fifo`/`lru`/`recency`/`fixed_decay`/`frequency_decay`/`dense`/`rrf`）的配对 bootstrap 显著性判定在修复后**零翻转**；420 个判定中有 22 个 sqcad 内部消融对比翻转（全部为 1–2 样本边界，见 §6）。
- 16- 主表（8/14 生成）是某一次随机 seed 下的快照，非确定性成立前无法声称跨进程可复现。

## 4. 修复

`_version_map` 改为确定性顺序（`newest` 取时间最新即索引最大的 updater）：

```python
for j in sorted(counts, reverse=True):
    if counts[j] >= overlap and msgs[j].session_id != m.session_id:
        updaters[m.msg_id].append(msgs[j].msg_id)
        newest[m.msg_id] = msgs[j].msg_id
```

语义：`newest` = 满足重叠条件且索引最大（时间最新）的 updater；`updaters` 列表按索引降序。下游所有使用点（`mid in updaters`、`mid in newest and newest[mid] in retained`）只做成员判断，行为仅取决于 `newest` 的取值规则。该修改对 `_lineage_map` 的选择规则完全对齐。

## 5. 修复后验证

### 5.1 本地确定性

同一命令（含 dense cache）连续运行两次，60 个策略 × 3 项指标（hit / recall / tokens）**逐项一致**（`results/public_unified_contract_fixed_run1.json` vs `_run2.json`）。

### 5.2 跨环境一致性

本地（Windows / Python）与远端（Linux / Python 3.12.3 / RTX 4080 SUPER）同代码运行：**60 策略 × 3 指标零差异**，数据集 SHA-256 一致。这是修复后复现性声明的直接证据：策略输出与操作系统、Python 版本、硬件无关。
