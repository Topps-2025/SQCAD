# 37- 严格理论审计与 48GB 云 GPU 实验切换报告（2026-08-21）

## 1. 本轮目标

本轮按 0819 meeting 的要求优先检查数学声称是否强于证明，再推进显存允许的基线复现。报告只记录当前可核验状态，不把冒烟、代理行或未完成的云端进程写成全量结果。

## 2. 理论修订（已落地）

### 2.1 P4 检测下界

- `16-T2严格reduction-separation与P4minimax探测下界` 的固定样本检验改为
  $n \ge 2\log(1/(2\delta))/\operatorname{KL}$，并明确简写为
  $\log(1/\delta)/\operatorname{KL}$ 时只是阶记号/常数省略。
- 定义整数门槛 $N^*(\delta)$，避免后悔分解中把实数下界当作探测次数。
- `src/sqcad/decision_identification_theory.py` 的 `probe_complexity` 与测试同步采用 Bretagnolle--Huber 固定样本下界；结果字段增加 `lower_bound_kind`，并声明顺序停止规则不声称达到固定样本常数。

### 2.2 后悔下界的适用类

- 原“$\mathcal C_{\mathrm{arch}}$ 内任意策略”的表述收窄为
  $\mathcal C_{\mathrm{arch}}^{(N)}$：提交 archived 后，获得 $N$ 个成功 probe 前不能提交 keep。
- 定理 4 加入时域条件 $T-n_{early}\ge N/(q\rho)$；短时域需要单独截断，不能直接套用无限时域式。
- 推论 4 改为“固定门槛子类内阶匹配”，不外推到默认 keep、任意提前停止的更大策略类。
- T1(b) 删除“样本均值之后 a.s. 永不跌破阈值”的不必要声称，改用恢复动作吸收态定义完成证明。

- 本地最小框架挑战已完成 `results/minimal_framework_challenge_strict_20260821.json`。一个重要 badcase 是：多数场景中 `minimal_framework` 与 `item_causal_risk_no_restore` 的效用/后悔差异为 0（机制开关没有被触发）；只有 `recurring_regime_shift` 出现很小的正向差异（utility +0.00087，n=20）。这说明当前框架在静态/弱 gap 场景存在“退化为基线”的可观测边界，下一轮应优先增加能区分恢复、预算和 sentinel 触发条件的外部轨迹，而不是扩大叙述声称。

### 4.1 半合成机制触发轨迹（CPU，单条固定 badcase）

为避免把“模块没有被调用”误读成“模块没有价值”，在原有随机世界之外加入了独立的半合成轨迹 `semi_synthetic_mechanism_trigger`。该轨迹不进入公开数据主表，也不提供泛化显著性结论；它只检查模块是否能在预先指定的决策压力下被调用，并把失败也记录下来。轨迹结构为：目标组内一条记忆在 phase 0 为正、phase 1 为负且在 phase 2 恢复；同组另有一个负向 hitchhiker；风险和歧义在任务间交替；层级组证据因此可能误导 item-level 选择。

结果文件：`results/minimal_framework_challenge_triggered_20260821.json`（`n=1`，固定机制 badcase）。

| 对比 | utility 差异 | regret 降幅 | 额外现象 |
|---|---:|---:|---|
| `minimal_framework` − `item_causal_risk_no_restore` | +3.31365 | +0.66273 | restore events 0 → 1；false-forgetting regret 被消除 |
| `task_adaptive_cap_candidate` − `minimal_framework` | +0.26364 | +0.17403 | 高/低风险预算交替下 harmful selection 降低 0.11111 |
| `hierarchical_sentinel_candidate` − `hierarchical_candidate` | −0.20747 | −0.14731 | item probes 0.05556 → 0.16667，probe cost +0.21667；该噪声轨迹暴露 sentinel 触发后的负收益 badcase |

因此，本轮只把前两项作为“机制可触发”的正向证据；sentinel 结果作为框架修改输入，不能写成 sentinel 普遍有效。该 badcase 支持下一步优先改进 sentinel 的成本门控/组证据校准，并做 paired replay，而不是增加更强的叙述。

## 5. 下一步排序

1. SimpleMem 单 trace 冒烟、合同字段、存储 token、LLM 调用计数和 SHA 校验已完成；5 条 LME-S 子集因官方窗口耗时过长未纳入结果，后续需单独预算时间再跑。GPU 成本计时已完成，但不替代具名系统质量复现。
2. 释放 GPU 后运行 SQCAD 关键 badcase 家族的最小消融（lineage conflict、hitchhiker association-only、scope mismatch、correction-visible），优先使用 CPU/冻结轨迹重放；半合成触发轨迹已先覆盖 recovery、adaptive budget 和 sentinel 路径。
3. ActMem 仅在更高吞吐/更大显存卡可用时继续；当前不声称全量复现，不用部分结果挑战论文结论。
4. 所有云端 JSON、日志和 QA 文件回传本地 `results/` 与外部数据库后，执行 md5/字段/零差异核对，再关停云实例。

## 6. 诚实边界

本报告关闭的是理论声称边界与 48GB 实验切换决策，不等同于 ICLR 555 完成。SimpleMem 全量、ActMem 全量、人工锚定和基于真实 badcase 的下一轮框架改动仍需独立证据。
