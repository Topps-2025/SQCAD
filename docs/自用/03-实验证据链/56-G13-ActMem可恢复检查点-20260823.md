## 1. 进入本轮时的真实状态（不是"已有检查点就算过"）

`tools/repro_named_actmem.py` 里确实有检查点设施：

| 已有 | 位置 |
|---|---|
| `_atomic_json`（先写 `.tmp` 再 `os.replace`） | 401 |
| `run_dataset(..., checkpoint: Path | None = None)` | 428 |
| 写检查点 | 465–472 |
| `--checkpoint-dir` | 513 |

但按 G-13 的原始理由核对，两处不达标：

1. **粒度错了**。写检查点的语句在 `for trace_idx, trace in enumerate(traces)` 循环的**末尾**，即 `run_actmem_trace` 完整返回之后。而一条 trace 内部有四个 LLM/GPU 阶段（3.1 事实抽取 → 3.2 embedding 聚类 → 3.3 因果候选 + PMI 校验 → 3.4 反事实检索）。embedding 或 PMI 阶段炸掉时，这条 trace 已经付掉的**全部 LLM 生成直接丢弃**——正是 `40-` §6 要防的那件事。
2. **没有 resume**。全仓 grep `resume` 在该文件里 **0 命中**。检查点被写出来，但没有任何读取路径，所以它只是个进度快照，不是恢复点。

## 2. 做法：内容寻址的生成缓存，而不是恢复控制流状态

新增 `StageCache`（`--stage-cache <path.jsonl>`）。设计取舍写在这里，因为它决定了正确性边界：

- **键 = sha256(model, system, user prompt)**，不是 trace 序号或阶段序号。四个生成阶段在 temperature 0 下都是 prompt 的纯函数，所以内容键在 `--max-traces` 改变、数据集重排、或从不同位置恢复到同一 prompt 时**仍然正确**。用序号键则这几种情况全部会错配。
- **不恢复控制流**。重跑走同一条代码路径，凡是已经答过的 prompt 从磁盘返回。不需要序列化 `facts`/`clusters`/`adj` 这些中间结构，也就没有"恢复出来的状态和重算的状态不一致"这类隐患。
- **append-only JSONL + fsync**。被 kill 时残缺的尾行在加载时 `json.JSONDecodeError` 跳过，所以中断**不能**把缓存损坏成不可读。
- **只缓存生成，永不进评测器**。缓存是成本工件，不是结果工件。

## 3. 成本计数的诚实性（这一条不做会造成虚假成本声明）

`llm_usage.calls` 在论文里是**成本声明**。缓存命中是"上一轮已经付过的生成"，如果计进 `calls`，一次恢复跑出来的 calls 会低于真实首跑成本，等于把成本报小。故：

- 命中**不进** `calls` / `in_chars` / `out_chars`，单独计入 `cache_hits`；
- payload 里带 `cache_hits_note`，明说恢复跑的总数不能与单次跑的成本相比；
- `payload["stage_cache"]` 记 path / entries / hits / misses。

## 4. 验证（不是"编译过就算"）

**缓存本身**：跨进程持久化命中；键对 model 与 prompt 均敏感（换模型、换 prompt 都不命中）；人为追加一条截断 JSON 行后，好条目仍可读、截断条目不被复活。

**真正的 G-13 断言——中断不丢工件**：用假端点计数真实生成次数，6 个 prompt，第 5 个位置模拟 PMI 阶段 OOM。

| | 真实生成 | `calls` | `cache_hits` |
|---|---:|---:|---:|
| run 1（第 5 个 prompt 处崩） | 4 | 4 | 0 |
| run 2（同一 `--stage-cache` 路径） | **2** | **2** | **4** |

即：崩溃前付掉的 4 次生成**全部存活**，重跑只补跑欠的 2 次；`calls=2` 证明命中没有污染成本计数器；恢复出的 4 条回复与原始回复逐字相同。

`python -m py_compile` 通过，`--help` 正常渲染。

## 5. 使用（云端，内存/大文件放数据盘）

```
python tools/repro_named_actmem.py ... \
  --checkpoint-dir /root/autodl-tmp/sqcad_ckpt \
  --stage-cache    /root/autodl-tmp/sqcad_ckpt/actmem_stage_cache.jsonl
```
