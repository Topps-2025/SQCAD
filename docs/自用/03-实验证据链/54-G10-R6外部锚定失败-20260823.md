## 3. 为什么这不是「再调一版提示词」的问题

**我停在两版，不继续调。** 继续按 κ 挑提示词就是拿 oracle 标签做模型选择，等于把盲评做成拟合，blindness contract 直接失效。两版都是**事先声明**的，都留在 `tools/r6_run_judge.py` 的 `PROMPTS` 里，跑出的每个批次在 raw JSON 里记 `prompt_variant`，所以报告的是「两版各自的结果」，不是「最好的一版」。

三条排除性检查说明责任在判官、不在导出集：

1. **导出集自身无矛盾**：21 个代表两两比对，相似度 ≥0.90 且 oracle 标签不同的对 **0 个**。不存在「正文一样、标签相反」的不可判样本。
2. **不是解码噪声**：7 对逐字节相同的呈现，判决**分裂 0/7**（`identical_pair_inconsistency`），且对内两例在呈现顺序上相隔 5–15 位。同一文本judge稳定复现同一答案，所以近零 κ 是能力/校准问题，不是随机性。
3. **不是解析吞掉了答案**：28/28 全部解析成功，回复长度只有 {4, 7} 两种（就是单词本身），terse 版 28 条回复里提到 `neutral` 的有 **0** 条——它是真的不产出该类别，不是被正则丢了。

另一条本可归咎于素材的地方也检查了：部分 case 正文确实很薄（如 case 7 只有 1 个 session、10 个未来 slot 全同、oracle 为 neutral），21 例里 6 例只有 1 个互异未来任务。这类样本对判官不友好是事实，但它解释不了 archive 侧的系统性丢失——archive 家族的 case 恰恰带 2 个 session（含被覆盖/冲突证据），信息量更足。
