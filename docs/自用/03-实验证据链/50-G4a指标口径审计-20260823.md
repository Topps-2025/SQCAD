# G-4a LoCoMo 指标口径审计（0823）

> **门槛**：G-4a（0823 方案 §3.2，批次 0，所有 GPU 支出的前置）
> **结论**：**不存在指标混用。** 0823 方案 §0.2 提出的「同一系统两套差一个数量级的数字」判断**不成立，予以撤回**。

## 1. 被质疑的两处数字

| 位置 | 数字 | 我此前的判断 |

## 2. 核对结果：两张表的列不是同一个量

`16-` L75 的表头（L89-91 所属表）是：

```
| 消融 | hit | recall | rare_recall | ku_recall |
```

**0.151/0.177/0.224 是 `recall` 列，不是 F1 列。** L112 所属表才含 `官方 F1` 列。同一行 candidate_guard_4 的完整读数是 hit 0.944 / recall 0.224（LME-S 单位），而 LoCoMo 上是 hit 0.484 / 官方 F1 0.0469（`16-` L114 明确并列给出）。两套数字**分属不同指标、不同数据集单位**，量级差异是 recall 与 token-F1 的定义差异，不是同一指标的口径冲突。

## 3. 官方评分器一致性

`public_unified_contract.py:1022 mirror_f1_score` 是官方 `evaluation.py` 的仓内镜像：`normalize`（去逗号/冠词/标点、小写）→ Porter stem → Counter 交集 → token-P/R 调和平均。`:1046 mirror_locomo_f1` 复刻官方按 category 的聚合：cat-1 逗号多答案取每个 gold 的最大匹配后求均值、cat-3 取首个子答案、cat-5 为对抗性二值检查。docstring 明确「官方文件仍是权威评分器（运行时交叉核对）」。

**判定**：主稿引用的 LoCoMo F1 数字口径一致，且与官方评分器对齐。

## 5. 对 0823 方案的修正

1. **撤回 §0.2**：不存在指标混用，G-4a 关闭条件由「修正冲突」改为「已核验一致 + 产出本表」。
