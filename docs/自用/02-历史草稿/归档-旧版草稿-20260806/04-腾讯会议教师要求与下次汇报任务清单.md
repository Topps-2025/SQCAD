# 腾讯会议教师要求与下次汇报任务清单

## 1. 会议形成的研究决策

本轮会议已经将近期工作收束到 **Agent Memory 已存记忆的状态减负**，即优先研究记忆形成后的保留、降权、衰减、归档或弃用问题。语义压缩、记忆关系重组以及覆盖写入—管理—读取的完整大系统可保留为后续论文矩阵，但不属于当前半年内的首要工作。

当前论文应以一个明确、可验证的核心问题为中心，而不是同时解决 Agent Memory 的全部生命周期问题。老师认可先推进“最有把握、已有初步解决思路”的第一个方向，并按一篇论文的结构倒推下一步工作。

### 作业一：完成论文 Introduction 初稿

**原话依据：31:11—31:47。** 老师明确将其称为“第一个 homework”，要求按照论文写作方式直接推进，并加入真实引用和对比工作。最后的贡献段可以暂时留空，但正文必须收束到 Research Gaps。

#### 2.1 写作范围

- 直接从 **Agent Memory** 切入，不从 LM 或 LLM 的发展史展开。老师在 20:56—21:22 明确指出，论文最大的叙事范围就是 Agent Memory。
- 用一至两句话说明记忆在 Agent 中的作用，以及为什么记忆管理具有研究意义。
- 从 Agent Memory 管理进一步引出当前关注的问题：由历史交互轨迹和代理行为信号驱动的记忆状态管理，以及其中的遗忘、降权和衰减。
- 说明这一类方法为何出现、现有优势是什么、依赖什么管理机制，不能一开始只陈述缺陷或现象。
- 梳理前人如何进行记忆状态管理，并加入真实、可核验的论文引用和需要对比的代表工作。
- 从现有工作自然推出共性限制，并明确写出两个 Research Gaps。
- 暂不强行写最终贡献和实验结论；贡献段等方法与实验稳定后再回填。

#### 2.2 推荐的段落结构

1. **第一段：研究对象与重要性。** 说明 Agent Memory 的功能、持续管理的必要性，并在段末引出交互轨迹驱动的记忆状态管理。
2. **第二段：现有机制与代表工作。** 说明现有方法使用时间、访问频率、检索匹配、任务反馈等信号进行保留、衰减或弃用的基本逻辑、优势和代表工作。
3. **第三段：共性限制与 Research Gaps。** 从文献证据推出低频高效能记忆可能被误删、相关性信号不等于动作贡献、历史轨迹拟合可能削弱未来任务泛化等缺口。
4. **第四段：本文工作与贡献。** 当前可预留位置，待方法、实验和结果稳定后再写。

#### 2.3 Introduction 与 Related Work 的组织选择

老师给出了两种允许的写法：

- **合并写法：** 在 Introduction 中完成现有工作、缺口和本文动机的连续论证。老师更推荐当前阶段采用这种方式，因为逻辑连续、较容易把研究缺口讲清楚。
- **分开写法：** Introduction 先落到研究问题的重要性，再将 Related Work 单列成节。若采用此法，Related Work 的子模块必须与后文的 Research Gaps 一一对应，不能形成互不相关的文献堆砌。

无论选择哪种写法，都要确保“研究对象是什么—为什么重要—前人怎么做—还缺什么—本文准备解决什么”的逻辑闭环。

### 作业二：形成方法与实验的可讨论方案

**原话依据：42:40—44:13。** 老师明确称其为“第二个 homework”，要求下次会议讨论“如何真正解决两个缺口”，并把方法、数据、基线、消融和评价指标一并规划出来。

#### 2.5 核心方法方案

- 针对两个 Research Gaps，分别说明准备如何解决。
- 明确是提出新框架、新算法、新评分机制，还是对既有记忆治理流程中的某一环节进行改造。
- 若采用解构—抽象作为核心表示机制，必须明确：原始证据如何解构为可寻址因子、哪些条件允许抽象为规则、规则如何保留来源与作用域，以及这些候选如何接受因果干预验证；不能把 LLM 生成的解释直接写成因果结论。
- 写清方法从哪里介入现有 Agent Memory 流程、输入输出是什么、核心计算信号是什么。
- 给出基础核心 idea，并说明它与现有时间、频率、相似度或结果反馈方法相比新增了什么信息。
- 说明两个缺口与方法模块之间的对应关系，避免提出与缺口无关的系统组件。

#### 2.6 数据与数据可得性

- 收集本研究可使用的开源数据集或公开 benchmark。
- 逐个说明数据是否真实可获取、下载或构造成本、许可证或访问限制、支持的任务类型。
- 判断每个数据集能否评测遗忘、降权或衰减，而不只是一般长程记忆检索能力。
- 给出主实验数据、辅助实验数据和可控实验数据的优先级。

#### 2.7 对比基线与 SOTA

- 收集与研究问题直接相关的传统基线、Agent Memory 强基线和当前代表性 SOTA。
- 说明每个基线比较的是哪种能力，例如时间衰减、频率淘汰、语义相关性、任务反馈、记忆价值估计或完整记忆系统。
- 尽可能复用公开代码、公开数据划分和原论文评价协议。
- 区分“论文声称的结果”和“本地成功复现的结果”，不能直接把报告值当作已复现性能。

#### 2.8 评价指标

- 规划任务完成效果或问答正确性指标。
- 规划记忆规模、token、延迟和计算成本等减负指标。
- 规划错误遗忘、错误保留、低频高效能记忆保全和未来任务泛化等与核心缺口对应的指标。
- 明确主指标、次要指标和效率指标，避免只用一个总准确率得出结论。

#### 2.9 消融实验

- 列出自研方法中需要逐项移除或替换的模块。
- 检查每个创新点是否都有相应消融来验证其独立贡献。
- 比较不同记忆动作，例如保留、降权、归档与硬删除。
- 检查不同超参数、预算、数据分布或未来任务漂移条件下的稳健性。

## 4. 条件性任务：实验未超过 SOTA 时如何处理

**原话依据：44:38—46:22。** 这不是下次会议前必须执行的任务，而是进入实验阶段后的预案。

1. 首先复现强基线或 SOTA，核验论文报告结果是否能在相同设置下重现。
2. 分析未超过基线的 bad cases，定位是研究机制不成立、实现问题、数据不匹配，还是指标对创新不敏感。
3. 根据 bad-case 证据优化框架、损失、状态动作或实验设置。
4. 反复调试并报告真实结果；不能默认 SOTA 结果一定正确，也不能仅为超过数值而改变研究问题。
