# Agent Memory 遗忘评测：基准、基线与可获取数据选择方案

本节的路径、hash、许可证边界与当前复现状态另见 [[data-card|数据卡与复现冻结草案]]。

## 0. 结论先行

本研究不应把“长对话 QA 得分更高”直接当作遗忘机制有效，也不应声称存在一个跨数据、模型、预算均成立的 Agent Memory “SOTA”。目前论文中的最优结果通常绑定于特定基础模型、检索器、上下文/存储预算和指标；不同论文的数字不能横向拼成总榜。

**建议采用 `LongMemEval + GoodAI-LTM + LoCoMo + 可审计治理叠加层` 的四层组合。**

1. 以 **LongMemEval 的全历史噪声设定（S）** 作为主标准集：有多会话、时间与知识更新，且有 500 个人工问题和 6 类任务，便于同已有记忆论文对照。
2. 以 **GoodAI-LTM** 作为动态验证集：它要求 Agent 在线保留、修订和更新信息，包含 11 个场景、33 个测试及不同任务交织/记忆跨度设置，最接近“状态持续治理”。
3. 以 **LoCoMo** 作为外部有效性集：它是最常用的长程对话记忆协议，也是 FadeMem、SAGE、A-MEM 等路线的共同比较面；官方仓库可获取：<https://github.com/snap-research/locomo>。
4. 在前三者之上构造一个小而严格的**可审计治理叠加层**，并另设合成反事实单元测试。它不替换公开基准，而是补上公开基准没有的“状态动作是否正确、是否可恢复、是否泄漏未来证据”标签。

第一阶段不建议把 MemBench 或 MemoryAgentBench 作为唯一主数据：二者有重要覆盖价值，但前者偏事实/反思记忆的广泛能力，后者虽包含选择性遗忘能力，却都不足以独立给出“某条记忆应被降权/归档/恢复”的逐操作因果标注。它们适合作为第二阶段的覆盖性复验。

## 1. 评测对象与判定边界

本项目的对象是**带来源、时间、主体和作用域的外显记忆条目或记忆簇**，而不是 LLM 参数遗忘。一次状态动作属于：`keep / reinforce / downweight / archive / isolate / restore / delete`。其中 `delete` 必须与授权撤回、保留期或已验证替代关联；默认比较重点是可恢复的降权、归档与恢复。语义压缩属于相邻的表示减负动作，不与本论文的状态治理 treatment 混为一谈。

因此，评测应同时回答四个不同问题：

| 问题 | 仅用普通 QA 能否回答 | 本项目的最低判据 |
| --- | --- | --- |
| 是否答对 | 可以 | 任务成功、QA/F1、约束遵守或决策 regret。 |
| 是否把旧/冗余信息压下去 | 只能间接回答 | 过时条目的错误采纳率、存储/提示 token 和检索次数。 |
| 是否保住低频但关键的边界 | 很难 | 关键证据召回、遮蔽后行动变化、关键约束违反率。 |
| 遗忘动作是否可审计且时间合法 | 不可以 | 动作日志、恢复成功率、来源/作用域遵守、未来证据泄漏率。 |

这与 [[01-核心研究问题与具体设想|核心研究问题与具体设想]] 的序贯因果价值一致：同一条记忆只有在给定任务、主体、时间、候选集、历史暴露和预算后，才可能被判为应保留、降权或退出。评测必须同时验证单步暴露效应与长期治理策略价值，不能把一次遮蔽实验外推为永久价值。

## 2. 已有基准：能测什么，不能替我们测什么

来源等级：`A` = 正式同行评议论文；`B` = 预印本；`C` = 仅由当前本地原文或其引用核验的工程/数据入口，使用前仍须复核许可与发布工件。

| 基准 | 覆盖与可用价值 | 与遗忘的关系 | 明确缺口 | 本项目定位 / 获取状态 |
| --- | --- | --- | --- | --- |
| **LoCoMo**（2024，A） | 超长、多会话对话；本库记录为约 600 轮、平均约 16K token、最长 32 会话；含单跳、多跳、时间和开放域等问题。 | 能压测长程访问、冗余和多跳组合；FadeMem、SAGE 等已有结果可作横向协议。 | 没有逐条保留/归档金标；最终 F1 不能区分写入、检索、采纳与推理。 | **外部有效性主集**；官方仓库已核验可访问。 |
| **LongMemEval**（2024，B） | 多会话聊天“干草堆” QA；论文实验描述为 500 个人工问题、6 类任务，含单会话、跨会话、时间推理、知识更新等；有 Oracle 与全历史噪声 S 两种设定。 | 时间与知识更新能直接暴露“近期重复但已失效”和“旧证据仍有条件有效”的问题。 | 仍是离线问答；没有状态动作金标，也没有参数化知识隔离。 | **主标准集**；从论文/artifact 获取后固定版本和 hash。 |
| **GoodAI-LTM**（C） | 动态长程交互；Oblivion 原文将其描述为 7 种记忆技能、11 场景 × 3 实例，并提供 Isolated、2K、32K、120K 的任务交织设置。 | 直接考验在线 retain / revise / update，适合检验“先降权、后恢复”而非一次性压缩。 | 测试数小，评审需报告逐场景结果与 bootstrap CI，不能只报平均。 | **动态主集**；先锁定作者公开版本、许可和评测脚本。 |
| **MemBench**（2025，B） | 多场景、多层次；事实记忆（单/多跳、比较、聚合、后处理、知识更新、跨会话）与反思记忆（偏好、情绪），并报告准确率、读写时间和容量。 | 知识更新、容量、事实/反思分层可补充“压缩后还能否保持正确”。 | 不提供动作级生命周期、来源/撤回传播与反事实效用标签。 | **第二阶段覆盖集**；优先取知识更新与多会话子集。 |
| **MemoryAgentBench**（2025，B） | 增量多轮交互，覆盖检索、测试时学习、长程理解和选择性遗忘。 | 已明确把 selective forgetting 放入能力面，不能声称“没有遗忘基准”。 | 公开摘要层面尚不足以替代操作级审计；接入前需复核仓库、许可和每项子任务标签。 | **候选复验集**；不要以未核实仓库替代可复现主实验。 |
| **Multi-Session Chat / LTI-Bench**（C） | FadeMem 使用的跨数据实验；后者包含连续交互、关键事实/上下文保留与冲突类型。 | 适合复验时间衰减、冲突解析、存储削减。 | 当前库仅核到 FadeMem 的实验描述，未将其独立 artifact、许可和脚本核为主数据。 | **可选复现协议**；确认公开可得后再纳入。 |
| **可控因果遗忘 simulator**（本研究新增） | 完全控制事件、`available_at`、`valid_from/to`、主体、来源、撤回、日志策略与潜在结果/可枚举反事实。 | 可直接量化暴露效应、长期治理策略价值和 keep/downweight/archive/restore 的反事实损益。 | 生态效度低，不能替代真实长对话。 | **必要的因果真值层**；与公开集并用。 |

补充判断：MemBench 的本地原文在 PDF p.1–2 和 p.8 明确把覆盖扩展到事实/反思、参与/观察、准确性/效率/容量；Oblivion 的本地原文在 PDF p.4–5 将 LongMemEval 与 GoodAI-LTM 配对。二者支持上述“静态标准集 + 动态交互集”的组合，但都不证明某个遗忘策略具有普适最优性。

## 3. 当前方法谱系：应比较的 baseline 与“代表性领先结果”

### 3.1 先区分 baseline 和 SOTA

下表的“作者报告的相对领先”只指原论文在其自身实验配置中的结果，**不**等同于统一排行榜 SOTA。复现实验必须固定：同一基础模型、同一候选记忆、同一检索器、同一上下文 token、同一存储预算、同一动作频率和同一评测脚本。

| 家族 | 必须纳入的方法 | 决策信号 / 动作 | 当前证据与应对方式 |
| --- | --- | --- | --- |
| **无治理下界** | Full context；固定滑窗；No-memory / 原始 RAG | 不压缩或被动截断。 | 给出长上下文和“根本没有外部记忆”的下界，防止把 prompt 长度收益误归给治理。 |
| **廉价规则基线** | FIFO、LRU、Recency、Frequency、Recency×Frequency、固定容量摘要、BM25 / dense / dev-tuned RRF hybrid retrieval | 按时间、访问或相似度淘汰/排序。 | 这是验证“自由能/行动价值”是否真有增量的最低门槛；不能省略。 |
| **常用记忆架构** | MemGPT、MemoryBank、Generative Agents、Mem0、A-MEM、HiAgent | 分层存储、摘要、事实 CRUD、关联笔记或工作记忆控制。 | 不是全都需要重实现；至少选 Mem0 与一个分层/摘要型架构，并冻结检索栈。 |
| **访问衰减 / 生命周期控制** | **FadeMem**、**Oblivion** | FadeMem：时间、频率、语义相关性驱动的差异衰减、融合与冲突处理；Oblivion：不确定性门控读路径、响应贡献强化写路径、可再激活衰减。 | 两者是本研究“降权而非立即删除”的直接强基线。FadeMem 作者在 LoCoMo 报告 29.43 multi-hop F1、85.9% FCR、45% 存储削减（其 Table 3）；不可与不同模型/预算的数字直接比较。 |
| **结果反馈价值** | **Memory Worth** | 每条记忆维护成功/失败共现计数，用于抑制、复核或弃用。 | 必须比较，因为它已用结果反馈而非静态分数；其作者明确 MW 是关联量而非因果贡献，且收敛需平稳检索和最低探索条件。 |
| **决策充分性 / 压缩** | **DeMem** | 仅在数据证明共享状态会导致行动冲突时分裂；以决策率失真定义可遗忘边界。 | 必须比较，因为它直接以决策而非描述保真度定义压缩；额外检验其对来源、时间、主体、撤回和参数重叠是否足够。 |
| **写入降载** | **SAGE**、Mem0g、PREMem | SAGE 在 ADD / UPDATE / NOOP 间做密度自适应新颖性门控；PREMem 将关系推理前移。 | 是“少写入”而非完整退出闭环的强相邻线。SAGE 原文仅以 LoCoMo 为主协议，未输出 DELETE/压缩，不能被当作遗忘全基线。 |
| **程序经验与推理耦合** | **ReMe**、MEM1、Reflexion、Voyager | 验证/提炼成功模式、失败触发与技能；或将巩固和推理联合。 | 用于防止候选方法只在事实 QA 上有效，而破坏可执行经验。 |
| **检索与归因控制** | cosine、BM25、dev-tuned RRF hybrid、Yuan et al. 的 raw chunks / Mem0-style facts / MemGPT-style summaries × 三种检索器 | 改变访问接口，不改变治理目标。 | 已在 LongMemEval-S 复现 BM25、MiniLM dense、turn-max、题型 router 和10 split RRF hybrid；hybrid Recall-all@5=0.861、Recall-all@10=0.928（split-test均值）。必须保留交叉消融，不能把检索差异误认作遗忘收益。 |

### 3.2 因果推断与策略评估基线

本研究不能只比较 Agent Memory 方法，还要证明“因果”模块相对关联与静态估计的增量。因果基线按问题层级组织：

| 层级 | 基线 | 回答的问题 |
| --- | --- | --- |
| 关联 | 成功/失败共现、相关系数、naive exposed–unexposed difference | 当前轨迹选择偏差有多大。 |
| 静态处理 | outcome regression、IPW、AIPW/DR、causal forest、R-learner | 单步记忆暴露及其异质效应能否被恢复。 |
| 纵向处理 | marginal structural model（MSM）/stabilized IPW | 时间变化混杂是否需要显式校正。 |
| 序贯策略 | sequential DR、DR-OPE | 能否从日志估计长期治理策略价值。 |
| Logged bandit | IPS/CRM | 简化为单步治理动作时的反事实风险与方差控制。 |

静态 DR 不能作为长期治理的唯一因果基线；MSM 与 DR-OPE 必须至少在可控 simulator 中验证。详细定义见 [[03-因果推断驱动的Agent Memory遗忘框架论文方案#3. 估计器阶梯：每一层回答不同问题|估计器阶梯]]。

### 3.3 可写入论文的审慎结论

- FadeMem 已证明时间、频率、相关性和融合是有竞争力的工程信号；它不构成“时间衰减已被淘汰”的证据。
- Oblivion 已把遗忘实现为可访问性衰减，并在 LongMemEval 与 GoodAI-LTM 上比较 direct / memory / 自适应控制；它不提供逐条反事实因果价值金标。
- Memory Worth 已给出极轻量的结果反馈基线，也明确其不等于因果归因。
- DeMem 已把“可安全遗忘”推进到决策失真边界；本项目不能再把“决策导向记忆从未研究”写成创新点。
- SAGE、PREMem、MEM1、ReMe 分别覆盖写入门控、预存储推理、记忆—推理耦合与程序经验精炼；本项目的差异必须落在**跨时间/主体/来源条件下的状态退出、可恢复性与行动增量审计**。

## 4. 推荐数据方案：公开基准复现 + 治理叠加层

### 4.1 阶段 A：可立即开始的最小可发表设置

| 层 | 数据与用途 | 固定设置 |
| --- | --- | --- |
| A1：标准对照 | LongMemEval 的 S（全历史噪声）与 Oracle（证据会话上界） | 同一基础模型；先以 S 为主结果，Oracle 只用于判断失败是否由检索造成。保留其时间推理、知识更新、跨会话任务。 |
| A2：动态对照 | GoodAI-LTM 的 Isolated、2K、32K、120K | 只在已锁定的公开脚本上运行；报告每个场景、每个跨度，而非只报宏平均。 |
| A3：外部复验 | LoCoMo | 保留单跳、多跳、时间、开放域四类；与 SAGE/FadeMem 共同协议对齐。固定 token-F1、BLEU-1 和同一 LLM judge（如使用）。 |
| A4：因果真值 | 可控因果遗忘 simulator | 每个 episode 提供候选条目 id、决策时刻、日志策略、真实暴露/策略效应、关键证据、过时/冲突/撤回标记；随机种子和生成器公开。 |

### 4.2 治理叠加层与 simulator 场景

叠加层应从公开基准的会话与问题中抽取候选证据，而不是凭空编造“旧记忆一定重要”。每个条目最少携带：`memory_id`、`source_id`、`available_at`、`valid_from`、`valid_to`、`subject_scope`、`task_scope`、`supersedes`、`revocation`、`evidence_span`。

| 压力场景 | 构造规则 | 金标状态动作 | 主要反例 |
| --- | --- | --- | --- |
| **低频但行动关键** | 一条早期、低出现次数的条件/例外是随后正确行动的必要证据；同时加入语义相近高频干扰。 | 保留或在查询时恢复；不可只因长期未访问而删除。 | 只保留高频/近期项的规则。 |
| **高频但过时** | 较新阶段出现显式、带时间戳的更新，旧规则在当前时点失效；旧条目仍高频。 | 降权、归档或隔离旧版本；激活当前有效版本。 | Frequency / recency 混淆、旧错误继续被采纳。 |
| **冲突但条件上均真** | 两条看似冲突事实仅在不同主体、地点、时段或来源等级下成立。 | 版本分叉/作用域隔离，不能粗暴合并或删除。 | 覆盖条件事实、跨用户泄漏。 |
| **撤回与时间合法性** | 条目被撤回，或其 `available_at` 晚于决策时点；另置与参数通识重叠但缺少可引用来源的条目。 | 隔离/删除并传播到摘要、索引与缓存；拒用未来证据。 | 未来信息泄漏、逻辑删除后仍被检索。 |
| **成功旁观者** | 在易任务中高概率暴露一条无增量记忆，任务无论有无该记忆均成功。 | 不因成功共现自动强化。 | 把成功共现误当正效应。 |
| **失败保护者** | 困难任务总体仍可能失败，但关键记忆降低连续损失或约束违反。 | 保留或强化保护性记忆。 | 把失败共现误当负效应。 |
| **替代与协同** | 两条记忆可互相替代，或只有共同暴露时才能改变行动。 | 按簇或交互效应治理。 | 单条遮蔽低估价值或误删互补项。 |
| **表面变换与因果抽象** | 替换实体名称、描述风格和无关属性，但保留潜在有效条件；另设“同名不同机制”反例。 | 解构后保留条件因子；仅在证据、作用域和效应稳定时激活规则。 | 整体轨迹过拟合表面；仅规则无来源导致过度推广。 |

在公开集无法可靠标注上述金标时，宁可只将其用作标准 QA 结果，不能把启发式标签包装为人工真值。合成层应报告其生态效度边界；公开层应报告其动作标注缺失边界。

### 4.3 为什么不是单独自建一个“大而全”数据集

仅自建数据会失去与 LoCoMo / LongMemEval 的比较面，也容易让规则与本方法评分函数共谋。仅使用公开集又无法判定生命周期动作本身。组合设计把两种风险互相制约：公开集验证外部可比性，合成反事实层验证操作因果性；GoodAI-LTM 验证在线行为，LongMemEval 的 Oracle/S 分离帮助定位检索瓶颈。

## 5. 实验协议与指标：避免“多一个模块，多一点分数”的错归因

### 5.1 公平性约束

1. 预先固定基础模型、温度、最大输出、嵌入模型、候选记忆抽取器、retriever、top-k、reranker 和上下文 token 上限；只有治理策略改变。
2. 对所有方法使用同一候选记忆流；禁止候选方法额外访问未来会话、人工答案或不同质量的摘要。
3. 至少做 `raw chunks / facts / summaries × dense / BM25 / hybrid` 的缩小交叉实验，或明确说明为何只固定一种表示与检索器。
4. 将运行预算写成实际数值：存储条目/字节、写入 token、读入 token、LLM 调用、延迟、检索次数；不能只报告“压缩率”。
5. 每个结果至少 3 个随机种子或 bootstrap CI；GoodAI-LTM 这类小测试集必须保留逐场景结果。
6. MSM/OPE 额外报告序贯权重分布、截断敏感性、horizon 分层、有效样本量，以及 OPE 与独立部署值的差距。

### 5.2 报告面板

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| 任务效用 | QA accuracy、token-F1、任务成功、约束遵守、决策 regret | 同预算下保留正确行动能力。 |
| 因果估计 | ATE/CATE bias、PEHE、effect-sign accuracy、CI coverage/calibration | 只在具有真值或可枚举反事实的 simulator/回放中报告。 |
| 策略评估 | policy-value bias/RMSE、目标策略排序准确率、部署值与 OPE 差距 | 检验长期治理策略估计，而不只验证单步 CATE。 |
| 选择性保留 | 关键证据 recall、过时证据错误采纳率、关键边界违反率、关键/非关键条目的 AUROC 或 AUPRC | 同时测“该留的留住”和“该压的压下”。 |
| 状态动作正确性 | `keep/downweight/archive/restore/delete` macro-F1；误删率、错保率、恢复成功率 | 不把可恢复降权和不可逆删除混在一起。 |
| 时间与治理 | 未来证据泄漏率、来源/作用域违反率、撤回传播完成率、审计日志完备率 | 验证外部记忆而非参数猜测的可审计增量。 |
| 资源 | 存储、平均提示 token、写/读调用、延迟、检索次数、每成功任务成本 | 报告效用—成本帕累托前沿。 |
| 失败归因 | 未写入、未检索、已检索未采纳、过度治理、索引残留、推理/执行失败的比例 | 避免把最终失败一律归因于遗忘。 |

主结果建议为二维帕累托图：横轴为资源成本（存储 + 读写 token 或费用），纵轴为任务效用；以颜色或第二张图报告时间合法性/动作 F1。仅有 QA 分数或仅有存储削减都不足以支持核心主张。

## 7. 当前可证伪假设

> 在同一候选流、检索器、基础模型和资源预算下，基于序贯因果价值的可恢复治理，能否同时降低过时/违规证据的错误采纳率与资源成本，并不显著损害低频关键约束；其效应和策略价值估计能否在可控 simulator 上恢复真值，其治理收益能否在 LongMemEval、GoodAI-LTM 与 LoCoMo 上保持？

下列任一结果都应削弱或否定方法主张：

- 只在 LoCoMo/LongMemEval 的最终分数提升，但对动作 F1、时间合法性或关键证据保留没有增益；
- 换成 BM25/hybrid、变更 top-k 或增加 token 后优势消失；
- 低频关键项的误删率升高，或高频过时项仍被错误采纳；
- “收益”来自未来证据、参数化前视或不同候选/检索预算；
- 同等任务效用下，维护图、评分或恢复的成本高于简单规则基线。
