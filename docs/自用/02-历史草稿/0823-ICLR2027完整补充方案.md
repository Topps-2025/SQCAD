## 0. 本轮 re-challenge 推翻的三项判断

0822 重构版的方向对，但有三处经代码核对后**必须推翻**。这三处直接改变优先级。

### 0.1 推翻：「L3 bucket 从 14 扩到 ≥24」不可行

0822 版把「扩 bucket 数」列为第 1 批 CPU 项，假设 14 = 7 family × 2 variant 可自由扩展。**代码核对结果：不能。**

`generator.py:38-46` 的 `FAMILY_VARIANTS` 是**冻结合同**的一部分：

```
hitchhiker:     (default,)                          → 1
rare_bridge:    (rescue_possible, rescue_impossible) → 2
version_update: (update_before, update_after)        → 2
harmful_stale:  (correction_visible, no_correction)  → 2
self_obscuring: (crowding, rescue_possible)          → 2
scope_mismatch: (future_in_s1, future_in_s2)         → 2
+ CONTROL_FAMILIES (stable_positive/negative/neutral) → 3
                                                    = 14
```

14 是 **11 个机制 bucket + 3 个 control**，由机制分类学决定，不是采样参数。加 variant 等于**改数据集定义**，会破坏 `frozen.py` 冻结合同、47 项合同测试、`bit-identical 1380/1380` 独立实现审计和 freeze 注册。为了 CI 显著性去改冻结数据集，是最典型的 p-hacking，reviewer 一旦发现「统计单元数在看到 CI 之后被调大」，Correctness 直接归零。

**替代方案（§4.1）**：不动 bucket 数，改用**正确的统计方法**——分层 bootstrap + 预注册的多重比较校正，并接受 n=14 下功效有限这一事实。诚实报告低功效比伪造功效强。

### 0.2 推翻：「LoCoMo F1 0.034 比官方低一个数量级」这个诊断不完整

0822 版说 F1 异常低是抽取式 reader 造成的下界。这半句对，但**漏了更关键的一层**：`16-` §112 显示 sqcad 的 LoCoMo 官方 F1 是 **0.0339**，而 candidate_guard_4 是 **0.0469**，BM25 是 **0.0454**。同一份 `16-` §89-91 的另一张表里 candidate_guard 的数值是 **0.151/0.177/0.224**——**同一个系统在同一份报告里有两套差一个数量级的数字**。

这不是 reader 问题，是**指标定义混用**：一处是 LoCoMo 官方评分器的 token-F1，另一处是 evidence-recall 类指标。主稿如果混引这两套，reviewer 会判定评测链路不可信。

**这比接生成 reader 更紧急**：先做指标口径审计（§3.2 G-4a），确认每个数字的定义与来源，再决定是否需要生成 reader。接 reader 是几千美元的 GPU 工作，指标审计是一天的文本工作，且后者是前者的前置。

### 0.3 推翻：「G-2 真实系统定位」应排在第 4 批

0822 版把 G-2（真实系统 G4 分支定位）放在最后一批，前置是生成 reader。**这个依赖关系判断错了。**

G-2 要测的是 forced keep/archive 下 kernel 是否改变、score fiber 内是否有 opposite-sign（`44-` §1）。这**不需要生成 reader**——它需要的是 exposure/workspace/candidate 的状态变化，而这些在现有抽取式管线里就可观测。`46-` 已经用纯 CPU 在 LifecycleBench 上跑完了同构协议（25 episodes、8 surface）。

搬到真实 trace 上主要是**工程移植**，不是新的 GPU 实验。而 G-2 是决定 research gap 强度的唯一门槛（`44-` 把 Real-Agent relevance 打 3.0/5，全审计最低）。把决定论文核心主张的门槛排在最后，等于把最大风险留到最晚发现。

**G-2 提到第 1 批，与 CPU 批并行。**

## 1. 9 分的操作定义

ICLR 没有 /10 综合分。「稳定 9 分」在本方案里翻译为三维评分与门槛状态的联合条件：

| 维度 | 当前（`40-` §7.3 / `44-` §4） | 9 分目标 | 决定性门槛 |
|---|---|---|---|
| Correctness / Soundness | 4/5（内部 4.9，外部置信 4.3） | **4.5+** | G-1 外部复核、G-3 prior-art、G-15 scope audit |
| Empirics / Contribution | **3/5** | **4.5** | G-4 指标口径、G-12 具名完整行、G-2 真实定位 |
| Clarity / Reproducibility | 4/5 | **4.5+** | G-5/G-8/G-9/G-14 失真修正、G-16 口令 |

**Empirics 3/5 是唯一的短板**，且从 3 到 4.5 需要跨两级——这是本方案 70% 工作量的去向。理论层从 4 到 4.5 只需关闭三条不耗资源的门槛。

## 2. 理论层：三条门槛，零资源消耗

**结论：条件化数学闭环已足够，剩余全部是复核与划界工作，不需要新定理。** `44-` §4 明确「继续追加一般 certificate lemma 的边际价值很低」。

### 2.1 已达到，不再投入

G1–G4 在明示合同下成立（有限时域、可测 kernel、standard-Borel、Blackwell/transcript-KL、score-visible immediate cost、`0<γ≤1`、regular quotient、uniformly bounded separating utility）。32 项理论回归 + `safe_recovery_theory.py` Theorem 11–13。

三项必须全文保持的区分：

1. `VoR^info = γ(I^K − I^A)` 由 Blackwell 定号；**`VoR^cont = γ(C^K − C^A)` 非符号确定**。
2. G2 是 **fixed-task iff**；G4 是 **universal model-class converse**。二者不可互换引用。
3. `ε_LC/4` 是**逐任务逐成本的 fiber-wise minimax 界**，不支持「标量维数天然不足」。

已撤回不得复活：horizon-independent `O(1/(qρ))`、任意 sequential policy minimax matching、「一次正 probe 即可安全 restore」。

### 2.2 G-1 外部数学复核（Correctness 首要，纯人力）

`44-` §3 列七个待复核点：standard-Borel factorization、dynamic quotient converse、admissible-value signed-kernel separation、Blackwell strictness、augmented stopping transcript、weighted Bretagnolle–Huber 下界、priced frontier（Lambert-W）。

拆成七份独立材料，每份 ≤3 页（定理陈述 + 证明 + 有限模型数值回归），**不含论文叙事**，避免复核者被结论引导。三条路径并行：导师直接复核 / 同组交叉复核 / 对 G2 rational-level-set 与 G4 三分穷尽性写 Lean 骨架或有限枚举。

**关闭标准**：七点各有一份书面意见（含「无异议」），记入新建 `03-实验证据链/49-外部理论复核记录`。

### 2.3 G-3 prior-art 划界（Novelty 防守）

风险实在：`44-` R3 自认 G2 quotient 条件是「一般 control homomorphism/lumpability 的 Agent-memory specialization」，Lambert-W 亦非原创。熟悉 Ravindran–Barto MDP homomorphism 或 bisimulation metric 的 reviewer 会直接质疑。

`20-` 补三节，每节写明「本文使用的标准工具 / 本文的 Agent-specific 增量」：controlled sensing & active perception；MDP homomorphism、lumpability & bisimulation；selective retention & OPE。

### 2.4 G-15 全文 theorem-scope 逐句审计

`40-` §6 第 3 条。按 §2.1 的三项区分 + 「构造性可能性 vs 普遍失败」+「persistent storage advantage vs total cost」五类，逐句扫摘要、positioning、conclusion、图表标题、代码注释。

### 3.4 G-5 Guard 检索成本陈述（1 天，必须）

主稿 `31-:737` 写「BM25 inverted index, O(log N) lookup per archive entry」。代码 `public_unified_contract.py:638-645` 每 task 调 `bm25_scores(msgs, t.query_tokens)`，而 `trace_grounded_runner.py:198-220` 对**全部 msgs** 重算 df/tf——**O(N·|q|) per query，无倒排索引**，正落在同段下句所述「dense-scan alternative」分支。

**方案 A（推荐，1 天）**：改写为实测复杂度，明确 45× 仅是 *persistent storage* 主张，Guard 的 query-time 成本与全库 BM25 相当，倒排索引实现「would reduce this but is not what we measured」。
**方案 B（可选增强）**：真实现 archive-only 倒排索引并重跑。

先 A。无论哪个，成本合同须分离 storage advantage 与 retrieval cost。

### 3.5 G-6 storage-matched 策略覆盖

主稿已声明「Not tested: LRU, recency-weighted, hybrid eviction」——这是给 reviewer 的现成攻击点：**最容易想到的 LRU 没跑**。SQCAD hit 0.754 vs BM25-stream 0.363 的 2.1×，若 LRU 达 0.6 则主张强度大幅下降。

## 4. L3 自建数据集层

### 4.1 G-8 统计单元：改方法，不改数据集（**取代 0822 的扩 bucket 方案**）

事实（`l3_sqcad_v2.json`）：

| 对比 | episode-level (n=1380) | bucket-level (n=14，诚实单位) |
|---|---|---|
| `sqcad_v2 − sqcad_cert` | 9.766 **显著** | 8.987 CI [−0.009, 27.478] **不显著** |
| `no_censoring` | 11.572 显著 | 11.337 [0.90, 30.73] **显著** |
| `no_probe` | −1.038 显著 | −0.987 [−3.66, 0] 不显著 |
| `no_restore` | −0.028 显著 | 不显著 |

§0.1 已论证 bucket 数不可扩。三项正确动作：

1. **删除无依据的 "significantly"**。主稿被 0822 迭代引入的「significantly outperforming all score-only baselines」无支撑：memory_worth / keep-all **无任何配对 CI 工件**（全目录 grep 无命中）。

3. **改用分层 bootstrap + 预注册校正**：episode-level 按 bucket 分层重采样（保留 bucket 为随机效应），并对 4 项消融做 Holm–Bonferroni 校正。同时**并列报告两个单位**，正文明确「n=14 是机制分类学决定的固定单位，功效有限」。

**关闭标准**：主稿每个显著性声明都能回指工件；n=14 的功效限制写入 Limitations。**低功效如实报告即关闭**——不以显著性为关闭条件。

### 4.2 G-9 oracle 与 probe-willing 的框定（提到正文）

两处必须从脚注提到正文：

- `probe_willing` 与 `sqcad_v2` **逐动作恒等**（identity diff 1.82e-06，CI 跨 0）。这是 **sanity check 通过**，不是 SQCAD 赢了基线。归档方案曾把它当成绩行，是误读。

## 5. G-2 真实系统 G4 分支定位（**提到第 1 批，Empirics 与 Novelty 的共同支点**）

### 5.1 为什么它是最关键的一条

`44-` 五项评分里 **Real-Agent natural-task relevance 3.0/5 是最低项**，理由是「尚未在多个真实框架数据流上定位三分分支或证明现有 score future-lossy」。它同时决定两件事：

- **Empirics**：现有 score 是否真的 lifecycle-incomplete；
- **Novelty**：research gap 是「构造性可能性」还是「经验验证的普遍缺口」。

§0.3 已论证它**不依赖生成 reader**，因此没有理由排在最后。

### 5.2 已有的构造性版本（`46-`）

`46-` 在 LifecycleBench 上跑完同构协议：25 episodes、8 个 score surface、独立 evaluator 计算 `Δ(x)=V^K(x)−V^A(x)`，score fiber 定义为 8 位四舍五入后精确相等（保守可复现）。

结果：最大 `ε_LC` = **159.782**，来自 `version_update/update_before` vs `update_after`（Δ₁=−118.9964，Δ₂=+40.7856，`R_shift ≥ 39.9455`）。SimpleMem lexical / Memory Worth / DeMem / CMI local 各有 2–3 个 opposite-sign fiber。

两个必须保留的诚实点：

- `46-` 开头自我声明这是「构造性算法证据，**不能写成自然任务 external-validity**」；
- **`trivium` surface 的 ε_LC = 0.0000，opposite-sign fibers = 0** —— 即该 score 上**造不出 witness**。这是负面结果，必须保留：它证明本文构造不是对任意 score 都能造反例，反而增强可信度。

### 5.3 G-2 的执行内容

把 `46-` 协议移植到真实 trace（LongMemEval-S / LoCoMo），对 **≥2 个真实 memory 实现**（候选：SimpleMem `keyword_search` 实际路径、LangChain VectorStore retention）执行 forced keep/archive paired intervention，测 `44-` §1 列的五项：

1. keep/archive 是否**实际改变** candidate / workspace / evidence kernels；
2. 自然任务是否**分离**这些变化（`44-` R4 明示真实失败可能：若 kernel 差异与全部可实现 value 正交，则对该任务类 decision-equivalent）；
3. baseline score fiber 内的 `ε_LC` 与 opposite-sign frequency；
4. archive/defer 分支的 conditional KL（**不得预设 archive 为零信息**）；
5. probe/restore 是否以可测成本重新打开通道。

### 5.4 负面结果预案（**必须提前写好，不能等 reviewer 指出**）

`44-` §1 原话：若系统全部 future-null 或现有 score 已 lifecycle-complete，**数学三分仍成立，但针对现有工作的强 research-gap claim 会失去经验支撑**。

届时论文定位改为「构造性可能性 + 条件化理论」，Limitations 明确写出。这是稳定 9 分的诚实上限，不是失败。**预案先写进 Limitations 草稿，实验结果回来后二选一激活**——这样无论正负都不会临时改写。

## 6. 具名基线层：Empirics 的另一支点

导师 meeting §3.3 要求四栏分层。`47-`/`48-` 已完成，**结论比归档方案假设的严峻**：五个具名基线**都不能称为论文系统的精确复现**。

| 基线 | 最准确名称 | 精度 | 允许用途 |
|---|---|---|---|
| CMI | query-local causal-effect control | 低到中 | 仅挑战 local-effect sufficiency，**不得写成 CMI 系统失败** |
| Memory Worth | MW-shaped associational proxy | 中（形状保留，信号不等价） | **必须声明 signal substitution** |
| DeMem | decision-distinction heuristic | 低 | heuristic control，**不代表 DeMem learner** |
| Trivium | demand-weighted effect control | 低 | temporal-demand control |
| GovMem | access-time coverage control | **不可迁移** | **不得作为 GovMem 结果**（GovMem 是 write-time policy） |

`48-` round7 已把 faithful core 分离到 `faithful_baseline_reproduction.py`，五个 protocol 达到 `official-code faithful core` 或 `paper-mechanism faithful core (partial)`——**但全部仍是 smoke，无 n≥10 完整质量行**。

### 6.1 G-12 至少一条 n≥10 完整具名行（Empirics 单点最大杠杆）

`40-` §6 第 1 条硬门槛原文：SimpleMem 或 ActMem 至少一个 `n>=10` **预注册**完整质量行；资源不容许时保留 smoke/partial，**不作胜负结论**。

当前 SimpleMem 仅 n=1 smoke（hit 1.0、recall 0.6667、storage 22,767、66 LLM calls），ActMem 无完整质量 trace，主稿 `31-:741` 已诚实标为 path-validation artifacts。这是主表「具名系统」栏的唯一空白。

**前置**：`40-` §5 记录云端 TCP 不可达 → 必须先恢复连通或确认本地 GPU 方案（G-13 亦为前置）。

### 6.2 G-13 ActMem 可恢复 checkpoint（半天，B1 前置）

`40-` §6 第 2 条：避免事实提取完成后因 embedding/PMI 阶段失败丢失全部工件。成本低，但不做会导致长跑白费。**排在 G-12 之前。**

### 6.3 G-14 主表四栏同步

- **GovMem 行从主表移除**，仅在附录以「access-time coverage control（非 GovMem）」保留 —— 导师 §3.3 明确「不要为了凑基线而强行塞入主表」。
- **`trivium` 零 witness 如实保留**（§5.2）。
