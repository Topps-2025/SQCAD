### 2.1 Guard 成本披露（最关键，1 天）

**问题**：
- 当前 "1/45 storage" 只计算 persistent store
- Guard 在每次 query 时扫描 archive（72k tokens）
- 真实检索成本取决于索引结构：
  - 倒排索引：~1/45 优势保持
  - 密集扫描：等效成本可能是 1/8-1/10

**修正位置**：§5.2 表格后

**修正内容**：
```markdown
**Guard cost breakdown**: The bounded candidate guard (§4.4) expands query-time 
retrieval without changing persistent authorization:

1. **Persistent store** (1,631 tokens): determined by keep/archive decisions
2. **Query-time candidate expansion**: retrieve top-K from archive (K ∈ {1,4})
3. **Workspace selection**: re-rank persistent + expanded candidates, select top-B=12

**Cost accounting**:
- Storage: only persistent store (1,631 tokens, unchanged)
- Exposure: workspace tokens (may increase if expanded candidates selected)
- **Retrieval cost**: Guard requires additional archive scan (proportional to 
  archive size ~72k tokens). Current implementation uses [确认后填入：倒排索引/密集扫描].

**Comparison fairness**: 
- Full-store BM25: retrieves from 74k tokens at query time
- SQCAD (no Guard): retrieves from 1.6k persistent at query time  
- SQCAD+Guard: retrieves from 1.6k persistent + top-4 archive at query time
- The 45× storage advantage reflects persistent store only; query-time retrieval 
  cost depends on archive index structure.
```

**Admission rule** (strictly online):
