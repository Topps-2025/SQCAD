## 1. 评分口径：为什么不用 /10

旧版用 /10 + Accept 概率（7.5 → 9.3、Accept 95%）。这套口径有三个问题：

1. **不可对照**。ICLR 审稿是三维 /5 + soundness/contribution/presentation 分项，没有 /10 综合分。旧版「Phase 1 后 Correctness 9.0→9.5」而 Phase 1 里没有任何理论工作，说明这个分数不由证据驱动。
2. **鼓励自我麻醉**。`44-` 已给出保守分（内部证明 4.9、外部置信 4.3、真实相关性 3.0），明确写「不能诚实给出三维均 5/5」。把它换算成 9.3/10 会掩盖 3.0 这一项。
3. **导师明确反对**。0819 meeting §6：「不能把『AI 给出 5 分』当作真实审稿结论」，要求「逐条自检暴露 reviewer 可能提出的关键问题」，目标不是编造分数。

**本方案口径**：每项工作对应一条**可关闭的门槛**，门槛只有 open/closed 两态，关闭需要工件路径。当前判定：

| Correctness（理论） | 4/5 | 外部数学复核缺失；真实系统未定位 G4 分支 |

| Clarity / Reproducibility | 4/5 | 主稿三处失真陈述；口令泄露阻塞公开包 |

「接近 10 分」在本方案里的操作定义是：**三维稳定 4.5+，且 §10 的 12 条硬门槛全部关闭**。这不是分数承诺，是可验证的状态定义。

## 3. 理论层：现在够 solid 吗

**直接回答：条件化数学闭环够了，但「理论 solid」不等于「reviewer 会给 Correctness 5」。**

`44-` 的判定是可信的，它自己就写了边界：「不能用自审替代外部数学复核」。所以理论层剩余工作**不是补新定理**，是关闭三类缺口。旧方案说「不需要补充新证明」这半句对，但由此推出「理论层无需投入」是错的。

### 3.1 已达到（不要再投入）

G1–G4 在明示合同下成立：有限时域、可测 kernel、belief update、standard-Borel、Blackwell/transcript-KL、G4 的 score-visible immediate cost、`0<γ≤1`、regular quotient、uniformly bounded separating utility。

- **G1** Lifecycle Bellman 分解：immediate / future-access / future-info 三项分账，依赖 canonical Agent filtration。Bellman-tower 本身不是原创，`44-` 已标注。
- **G2** Score sufficiency iff Doob–Dynkin 可测：零宽度 tie fiber 已单独处理，避免 `0/0`。
- **G3** VoR：`VoR^info = γ(I^K − I^A)` 在共同 state kernel + conditional Blackwell + belief-value 凸性下非负，strict Jensen gap + `γ>0` 下严格正。**`VoR^cont = γ(C^K − C^A)` 非符号确定** —— 这是必须全文保持的区分。
- **G4** 架构无关三分（future-null / lifecycle-complete / future-lossy）+ 最小统计量 `T_LC*`、近似量 `ε_LC`。三分穷尽且互斥；`ε_LC/4` 是**逐任务逐成本的 fiber-wise minimax 界**，不支持「标量维数天然不足」这类强主张。
- 32 项理论专项回归通过 + `safe_recovery_theory.py` 的 Theorem 11–13 安全恢复证书。

已撤回且不得复活的旧表述：horizon-independent `O(1/(qρ))`、任意 sequential policy 的 minimax matching、「一次正 probe 即可安全 restore」。

### 3.2 硬缺口 T1：外部数学复核（门槛 G-1，**最高优先**）

`44-` §3 第 1 条列了七个需独立复核的点：standard-Borel factorization、dynamic quotient converse、admissible-value signed-kernel separation、Blackwell strictness、augmented stopping transcript、weighted Bretagnolle–Huber 下界、priced frontier（Lambert-W）。

这是**唯一能把 External proof confidence 从 4.3 推到 4.8+ 的动作**，而且不需要 GPU、不需要标注员、不需要云端。旧方案 6 周里对此投入为零。

执行方式（按可行性排序）：

1. **导师直接复核**：把 proof appendix 按七个点拆成七份独立可读材料，每份≤3 页，附有限模型数值回归。下次 meeting 前交付。
2. **同组/外部博士生交叉复核**：只给定理陈述 + 证明，不给论文叙事，要求指出假设遗漏。
3. **形式化辅助**：对 G2 的 rational-level-set 构造和 G4 的三分穷尽性，写 Lean/Coq 骨架或穷尽有限模型枚举，作为附录 machine-checked 证据。

**关闭标准**：七个点各有一份独立复核意见（含「无异议」也算），记入新文档 `49-外部理论复核记录`。

### 3.3 硬缺口 T2：真实系统 G4 分支定位（门槛 G-2）

`44-` 把 Real-Agent natural-task relevance 打 **3.0/5**，理由是「尚未在多个真实框架数据流上定位三分分支或证明现有 score future-lossy」。这是全部审计里最低的一项，也是 research gap 强主张的经验支撑点。

`44-` §1 明确了要测什么：

- keep/archive 是否**实际改变** candidate / workspace / evidence kernels（不是构造世界里改变）；
- 自然任务是否**分离**这些变化（`44-` R4：若 kernel 差异与全部可实现 value 正交，则对该任务类 decision-equivalent —— 这是真实的失败可能）；
- baseline score fiber 内的 `ε_LC` 与 opposite-sign frequency；
- archive/defer 分支是否低 KL（**不能预设 archive 为零信息**）；
- probe/restore 是否以可测成本重新打开通道。

`46-` 已经在 LifecycleBench 上做了这件事的**构造性版本**：25 episodes、8 个 score surface、最大 `ε_LC` = 159.782（`version_update` 的 Δ₁=−118.9964 vs Δ₂=+40.7856），SimpleMem lexical / DeMem / CMI local 等出现 opposite-sign fiber。但 `46-` 自己的开头就声明这是「构造性算法证据，不能写成自然任务 external-validity」。

**所以 T2 的内容是把 `46-` 的协议搬到真实框架数据流上**，这是本方案的真 P0，不是端到端任务成功率。

具体：在 LongMemEval-S / LoCoMo 的真实 trace 上，对至少 2 个真实 memory 实现（候选：SimpleMem 的 keyword_search 实际路径、LangChain VectorStore retention）执行 forced keep/archive paired intervention，测 `ε_LC` 与 opposite-sign rate。

**可能的负面结果必须预先接受**：如果真实系统全部 future-null，或现有 score 已 lifecycle-complete，则 G1–G4 数学仍成立，但**针对现有工作的强 research-gap claim 失去经验支撑**（`44-` §1 原话）。届时论文定位必须改为「构造性可能性 + 条件化理论」，不能硬写成普遍失败。这一条要写进 Limitations，不是等 reviewer 指出来。

### 3.4 硬缺口 T3：prior-art 完整检索（门槛 G-3）

`44-` §3 第 6 条：对 Agent memory、**controlled sensing**、**MDP homomorphism / lumpability** 做完整检索，避免把标准 quotient result 包装成原创。

这条风险实际存在：G2 的 quotient 条件是「一般 control homomorphism/lumpability 的 Agent-memory specialization」（`44-` R3 原话），Lambert-W 优化也已标注「不是原创」。如果 reviewer 熟悉 Ravindran–Barto 的 MDP homomorphism 或 bisimulation metric 文献，而论文没有明确划界，Novelty 会被直接扣。

**关闭标准**：`20-` 文档补三节 —— controlled sensing / active perception、MDP homomorphism & bisimulation、selective retention & OPE，每节明确「本文用了什么标准工具 / 本文的 Agent-specific 增量是什么」。

### 3.5 理论层不做什么

- 不再追加 certificate lemma。`44-` §4 明确「继续追加一般 certificate lemma 的边际价值很低」。
- 不试图证明「现有 score 必然失败」。G4 是三分，不是不可能性定理。
- 不把 32 项回归测试当证明。测试确认实现与文档自洽，不确认数学正确。

## 4. L2 公开数据集层：严谨性补强

### 4.1 导师给 L2 划定的作用范围（必须遵守）

meeting §3.1：公开集**没有同一历史流下的 keep/archive 反事实分支**，因此不能单独证明 lifecycle 价值或持久动作因果效果。公开集只回答四个问题：任务命中/召回/答案质量是否可接受；是否以更低 persistent storage 换取有竞争力的质量；guard/probe/restore 是否修复了**可定位的** bad case；质量-存储-暴露-探测之间是否有可解释 Pareto。

并明确禁止：写成「SQCAD 全面击败检索基线」或「公开集已证明 lifecycle causality」。

**旧方案违反了这条**。§2.5 的叙事重构把 L2 从「trade-off」改写为「establishes a significant efficiency gain … outperforms」，正是导师禁止的方向。虽然 storage-matched 比较本身成立，但措辞必须保留约束条件，不能省略「under matched persistent budget」这个前提。

### 4.2 缺口 E1：reader 是抽取式下界（门槛 G-4，**L2 最大硬伤**）

`16-` §28 原文：「本机无生成模型，QA 采用确定性抽取式 sentence reader……抽取式 reader 的绝对 F1 是下界」。

这解释了为什么 LoCoMo token-F1 全部在 0.034–0.047 这个**异常低**的量级。官方 LoCoMo 论文的 F1 在 0.2–0.5 区间。reviewer 看到 0.0454 会立刻质疑评测链路，而「所有 policy 共享同一 reader，相对比较仍有效」这个辩护只在同一 reader 内部有效，无法回答「你的绝对数字比官方低一个数量级」。

**这是 Empirics 3/5 的首要原因，优先级高于端到端任务成功率。**

执行：接入真实生成 reader（本地 Qwen2.5-7B-Instruct 或 API），在同一 chronological candidate stream、同一 workspace 预算 B=12、同一官方评分器下重跑 LoCoMo 全部 policy 行。至少覆盖 BM25 / dense / SQCAD / Guard-4。

**关闭标准**：LoCoMo F1 进入官方可比量级，或明确报告「生成 reader 下 SQCAD 与 BM25 的相对关系与抽取式 reader 一致/不一致」。后者即使是负面结果也关闭门槛 —— 关键是不再用下界 reader 做主表。

### 4.3 缺口 E2：Guard 检索成本陈述失真（门槛 G-5，**1 天，必须立即**）

主稿 `31-` 第 737 行写：

> Current implementation uses BM25 inverted index, yielding O(log N) lookup per archive entry; the 45× persistent storage advantage is preserved.

代码实际是 `public_unified_contract.py:638-645`，每个 task 调 `bm25_scores(msgs, t.query_tokens)`；而 `trace_grounded_runner.py:198-220` 对**全部 msgs** 重算 df/tf，无倒排索引、无 archive-only 扫描。即 **O(N·|q|) per query**，正落在同段下一句所说的「A dense-scan alternative would approach full-store retrieval cost」分支。

**修正方向（二选一，不可含糊）**：

- **A（诚实披露，推荐）**：改写为「current implementation recomputes BM25 over the full message set per query (O(N·|q|)); the 45× advantage is a *persistent storage* claim only, and query-time retrieval cost of Guard is comparable to full-store BM25. An inverted-index implementation would reduce this but is not what we measured.」
- **B（改实现）**：真正实现 archive-only 倒排索引，重跑 Guard 全部行，再保留原文。

选 A 只需 1 天且立即消除失真；选 B 需重跑但能保住 Guard 的成本论证。**建议先做 A**，B 作为可选增强。无论哪个，都要在成本合同 §2.3 明确分离 storage advantage 与 retrieval cost。

### 4.4 缺口 E3：storage-matched 对照的策略覆盖（门槛 G-6）

当前 storage-matched 只有 BM25-stream / dense-stream，论文已在 `31-:750` 附近声明「Not tested: LRU, recency-weighted, hybrid eviction」。这个诚实声明反而给了 reviewer 一个现成的攻击点：**最容易想到的 LRU 基线没跑**。

SQCAD hit 0.754 vs BM25-stream 0.363 的 2.1× 提升，如果 LRU 或 recency-weighted 能达到 0.6，主张强度会显著下降。补这三个策略是纯 CPU 工作，成本极低，收益是消除一个必被问到的问题。

**关闭标准**：LRU、recency-weighted（score × 1/age）、hybrid 三行在 matched budget（1,631 tokens）下跑完并入主表，附 paired bootstrap CI。

### 4.5 缺口 E4：LoCoMo 规模（门槛 G-7）

当前 LoCoMo 只有 10 conversations。`16-` 记录的是官方 10 组，但 reviewer 会问统计功效。若官方数据集更大，应扩到全量；若确实只有 10 组，需在正文明确「LoCoMo official release contains N conversations; we use all/subset」并给出 CI。

### 4.6 L2 不做什么

- 不追求「全面优于 bm25/dense/RRF」。静态召回落后是已确认事实（`16-` §157），如实报告。
- 不把 Guard-4 的 LoCoMo F1 超过 BM25（0.04694 vs 0.04538）写成 SOTA —— 在抽取式 reader 下界的量级上，这个差距不足以支撑任何强主张，必须等 E1 关闭后重评。

### 5.2 缺口 L2：oracle 不是上界，probe-willing 是恒等（门槛 G-9）

两个框定问题必须在正文明确，不能只留脚注：

- `probe_willing` 与 `sqcad_v2` **逐动作恒等**（bootstrap identity diff = 1.82e-06，CI 跨 0，n.s.）。这是 sanity check 通过，**不是** SQCAD 赢了一个基线。旧方案 §0.4 把它当成 SQCAD 的成绩行是误读。
- **oracle 不是上界**：no-probe ablation 达 1.903 > oracle 0.964。所以「达到 oracle 89.7%」这个说法在本 benchmark 上没有上界含义。旧方案把它提为主发现是送分给 reviewer。

**正确的 L3 主发现表述**：interval authorization 在 1,380 配对 episodes 上 false-commit 0.072、regret 0.115、oracle agreement 0.907；在 14 个规则世界实例的诚实单位下，**只有 censoring suppression 达到统计显著**；restore 通道在本 benchmark 价格下净负（如实报告）。

### 5.3 缺口 L3：外部锚定（门槛 G-10）

`40-` §6 第 5 条硬门槛：完成一项外部锚定 —— 真实长期流量的 intervention/annotation，或预注册 Phase B deployment。

R6 的 28 cases 已导出但 judge batch 未推动。**28 条是可在一天内完成的规模**，却挂了多轮。这比旧方案计划的「100 episodes × 2 名 blind 标注员 + κ」现实得多。

**执行**：先关闭 28 cases（可用 LLM-as-judge + 作者复核双轨，明确标注方法）。若要更强锚定，再考虑扩展。**不要在 28 条未完成前规划 100 条。**

### 5.4 缺口 L4：GAMMA 单点 → 多参数鲁棒性（门槛 G-11）

当前只有 GAMMA=0.9，validity domain 声明为 [0.9, 0.99] 但未实测。censoring 是唯一显著效应，如果它只在 GAMMA=0.9 显著，整个 L3 主发现就悬了。

**执行**：GAMMA × τ × probe-cost 的 3×3 网格（9 组合），纯 CPU。**关闭标准**：censoring 在 ≥7/9 组合下 bucket-level 显著。若不达标，如实报告参数敏感区。

导师 meeting §3.3 要求四栏分层：可完整复现 / 官方代码级验证 / 论文规则代理 / 不可迁移。`47-` 和 `48-` 已经做完这个分层，**结论比旧方案假设的严峻**：

| 基线 | 最准确的名称 | 精度 | 可用于 lifecycle gap 构造实验？ |

## 7. 范围决策：本方案的边界

### 7.1 单篇 vs 拆分（导师未决问题 #1，必须先定）

meeting §4 原话：「当前工作量较大，全部塞入一篇文章可能导致主线松散、篇幅超限，也可能浪费后续扩展成期刊论文的空间」。

现有内容量：G1–G4 四条主定理 + Appendix A 的 Construction/Proposition/Corollary 族 + L1 十余项 witness + L2 两数据集多策略 + L3 1,380 episodes 六机制族 + R1–R8 审计 + 五个具名基线 fidelity 分层。**这明显超过一篇 ICLR 9 页正文的容量。**

**建议方案（需导师确认）**：

- **论文 A（本次 ICLR 2027 投稿）**：理论 + 方法 + 精简实证。G1–G4 + E-Q-A 框架 + L2 Pareto + L3 主结果（censoring 显著 + false-commit）。LifecycleBench 只作为**内部效度验证工具**，构造细节全部进附录。
- **论文 B（后续，benchmark/评测论文）**：LifecycleBench 完整构造规则 + 六机制族 + R1–R8 审计链 + 五基线 fidelity 分层 + `46-` 的 baseline-internal gap 协议。

理由：`46-`/`47-`/`48-` 三份 fidelity 审计本身就是一篇 benchmark 论文的核心贡献，塞进论文 A 的附录会浪费。而论文 A 少了它们仍然完整（G4 + L3 主结果足够支撑）。

**这个决策必须在动工前定**，因为它决定 §10 门槛里哪些是本次必须关闭的。以下门槛表按「论文 A」范围列出。

### 7.2 明确降级的两项（旧方案的 P0）

**端到端任务成功率 → Priority 2**。理由：

1. 方案指定的 AgentBench / GAIA / ToolBench **本地都没有**（`D:\Engineering\SQCAD\database` 只有 LongMemEval、LoCoMo、GoodAI-LTM、MemoryAgentBench），「从现有基准选取」不成立。
