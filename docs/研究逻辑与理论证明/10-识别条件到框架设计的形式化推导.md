> 日期：2026-08-12

> 状态：设计规范。与 `09-从研究直觉Gap到理论空白` 配套——09 负责研究逻辑，本文负责框架推导。

## 0. 论文的核心逻辑（修订后）

论文的核心逻辑不再是：

> ❌ 我们设计了 Evidence–Qualification–Access 三个模块，实验显示它们有效。

而应变成：

> ✅ 我们先证明 persistent-access lifecycle value 在历史日志、局部干预或无条件作用域平均下不可识别（§0.1–0.3 的三个反例构造）；随后刻画其识别所必需的日志、干预和稳定性条件（本文）；SQCAD 将这些条件实现为 Evidence–Qualification–Access 的可审计治理协议。

逻辑链：

\[
\boxed{\text{Non-identifiability}}
\rightarrow
\boxed{\text{Sufficient operable auditable authorization conditions}}
\rightarrow
\boxed{\text{SQCAD logging / intervention protocol}}
\rightarrow
\boxed{\text{Qualification gate}}
\rightarrow
\boxed{\text{Risk-sensitive reversible access decision}}
\]

**约束**：如果某个框架模块无法对应某个不可识别性反例或识别条件，它就不应进入核心方法；反过来，如果某条识别条件没有被框架实现，理论主张就不能落地。

## 1. Gap 的当前定位

**Non-identifiability side（已基本立住）**：

通过三个构造性反例（`gap_proof_experiments.py`），建立了：

| 反例 | 证明内容 | 对应基线路径 |
|------|---------|-------------|
| 命题 A | 存在 P(O\|M₁)=P(O\|M₂) 但 lifecycle value 符号相反的世界 | Memory Worth（关联价值） |
| 命题 B | 存在 Δ_do 完全相等但 lifecycle value 符号相反的记忆 | CMI（局部干预效应） |
| 命题 C | 存在 source 数据完全相同但 target value 符号相反的世界 | OPE/MSM（作用域平均） |

**当前可成立的定位**：

> A formally counterexample-grounded, memory-specific identification gap for persistent-access lifecycle value.
>
> 一个通过观测等价模型和决策遗憾反例建立的、面向持久记忆访问生命周期价值的识别空白。

**Identification side（尚需完成）**：

> 在什么充分且可审计条件下，persistent-access lifecycle value 可由日志和 micro-intervention 识别？（注：Lemma A–D 表明完整 C1–C8 不是唯一识别路线；并未逐项证明 C1、C4、C5 不必要，见 `12-必要性证明与识别路线分类学`。）

这一侧需要：
- Identification theorem（识别定理）
- Observable formula（可观测公式）
- Partial-identification bound（部分识别界）

**不能写成**："我们已经建立完整的 Agent Memory 基础因果理论。"

## 2. 识别条件 → 框架组件的对应表

以下表格是 SQCAD 框架设计的**理论来源**。左列是反例或定理导出的识别条件，右列是该条件强制要求的框架设计。

### 2.1 反例导出的条件（Non-identifiability → Required conditions）

| 反例揭示的不可识别性来源 | 导出的识别条件 | 框架中必须有的设计 |
|---|---|---|
| 命题 A：历史 (C,E,Y) 无法区分"真正有用"和"被混杂" | 需要记录 exposure propensity、co-exposure、task context | **Evidence 层**：candidate generation、proposal score、exposure propensity 日志 |
| 命题 A：m_star 和 m_prime 共暴露导致关联信号被错误归因 | 需要区分暴露、采用、行动和结果 | **Evidence 层**：exposure / adoption proxy / action / outcome 分离记录 |
| 命题 B：局部效应相同但持久效应相反 | treatment 必须是 persistent access action，不是一次 prompt insertion | **Access 层**：记录 keep/downweight/archive/restore 的生效时刻、持续期与 rollback |
| 命题 B：m_short 的 crowding 效应在局部查询中不可见 | 需要处理 policy feedback 和 co-memory interference | **Evidence 层**：sequential policy state 与 next candidate stream 日志 |
| 命题 C：source 数据相同但 target 效应相反 | source 不能自动外推 target | **Qualification 层**：scope transport 条件、target support audit |

### 2.2 识别定理导出的条件（Identification theorem → Required conditions）

| 识别条件 | 定理角色 | 框架中必须有的设计 |
|---|---|---|
| **Consistency**：实际执行的 persistent action 与反事实定义一致 | 将观测数据连接到潜在结果 | **Access 层**：action type、生效时刻、持续期、rollback 显式记录 |
| **Sequential exchangeability**：给定完整历史后无未观测混杂 | 消除 confounding bias | **Evidence 层**：task state、policy state、memory state 的完整历史 |
| **Positivity / overlap**：每个候选 action 在每层状态中有非零支持 | 确保识别所需的 variation | **Qualification 层**：在符合安全条件的候选上做 randomized micro-intervention |
| **Treatment observability**：access action 被真实记录 | 避免 treatment misclassification | **Access 层**：action type、duration、生效状态日志 |
| **Exposure observability**：候选、暴露、位置、预算可区分 | 将 exposure 机制写入 likelihood | **Evidence 层**：candidate、exposure propensity、position、budget 分离字段 |
| **Adoption measurement**：模型是否使用 memory 不可等同于 prompt 出现 | 避免 adoption-outcome 虚假关联 | **Qualification 层**：adoption proxy、测量误差模型、不识别边界 |
| **Interference specification**：co-memory 竞争和共同暴露显式建模 | 避免 per-memory ATE 的虚假可加性 | **Access 层**：workspace budget、position、co-memory composition、joint/conditional treatment |
| **Measurement stability**：reader/model/tool/evaluator 版本固定 | 避免 measurement drift 冒充 treatment effect | **Evidence 层**：scope/version 字段；**Qualification 层**：measurement-stability gate |
| **Scope transport**：target 在 source support 内或显式 transport 假设 | 允许 source estimate 用于 target decision | **Qualification 层**：target support audit、Bayesian uncertainty、abstention |

## 3. Evidence–Qualification–Access 三层的理论角色

### 3.1 Evidence 层的理论角色

\[
\boxed{\text{Evidence} \Rightarrow \text{保存识别所需变量和干预记录}}
\]

Evidence 层不直接决定长期访问，也不被派生 belief 覆盖。它的理论功能是满足识别条件的**观测性要求**：

- 记录 candidate generation、proposal score、exposure propensity（满足 exposure observability）
- 分离 exposure / adoption proxy / action / outcome（满足 treatment + adoption observability）
- 记录 sequential policy state 和 next candidate stream（满足 exchangeability + policy feedback）
- 记录 scope/version 字段（满足 measurement stability）
- 保存 immutable source 和 provenance（满足可审计性）

**理论约束**：如果某个变量未被 Evidence 层记录，识别定理就不能假设它被观测。反过来，如果一个变量被记录但没有对应的识别条件需要它，它就是工程选择而非理论要求。

### 3.2 Qualification 层的理论角色

\[
\boxed{\text{Qualification} \Rightarrow \text{检查识别假设是否足以授权决策}}
\]

Qualification 层不是"给记忆打正负分"的评分器。它的理论功能是**逐 scope 检查识别条件是否满足**：

\[
Q_i(s) \in \{\text{positive}, \text{negative}, \text{unresolved}, \text{mismatch}\}.
\]

| Qualification 状态 | 对应的识别条件状态 | 语义 |
|---|---|---|
| `positive` | 正向效应 + 识别条件满足 | 有权限改变 persistent access（如 protect/restore） |
| `negative` | 负向效应 + 识别条件满足 | 有权限限制 persistent access（如 downweight/isolate/archive） |
| `unresolved` | 识别条件不满足（positivity/adoption/interference/transport 任一条失败） | **理论上不允许系统把证据升级为 persistent-access action** |
| `mismatch` | scope/version 不匹配 | 证据来自不同作用域，不能直接用于当前决策 |

**unresolved 的强化定位**：

> `unresolved` 不是一个经验上较保守的 memory score，而是当 positivity、adoption measurement、interference 或 transport 条件不满足时，理论上不允许系统把证据升级为 persistent-access action 的状态。

这意味着：
- unresolved 不是"记忆价值为零"
- unresolved 不是"记忆有害"
- unresolved 是"没有理论权限改变持久访问权"
- unresolved 允许可撤回的当前任务访问（fallback），但不允许改变长期权限

### 3.3 Access 层的理论角色

\[
\boxed{\text{Access} \Rightarrow \text{在已识别或有界的价值下执行长期动作}}
\]

Access 层在固定 workspace budget 下分配访问质量。它必须接收 qualification、风险、成本和 interference 信息：

\[
a^\star = \arg\max_{a\in\mathcal A} \left[ \widehat{V}_s^\pi(a) - \lambda\widehat{C}(a) - \rho\widehat{R}(a) \right].
\]

但只有在识别和不确定性门成立时才允许改变 persistent access。决策逻辑：

| 识别状态 | 允许的动作 |
|---|---|
| 点识别充分 + 风险可接受 | 允许 qualified action（keep/downweight/isolate/archive/restore） |
| 仅有区间 + 动作排序稳定 | 允许保守动作或受限访问 |
| 区间跨越决策阈值 | 执行额外 probe 或 review |
| overlap/measurement/transport 不成立 | 输出 `unresolved`，保持可撤回的当前任务访问，不改变长期权限 |

## 4. 识别条件到框架的完整推导链

```text
Non-identifiability (counterexamples A, B, C)
  │
  ├─ 命题 A: P(O|M₁)=P(O|M₂) but V_M1 ≠ V_M2
  │   → 需要: exposure propensity, co-exposure, adoption distinction
  │   → Evidence: candidate gen + exposure + adoption 分离日志
  │
  ├─ 命题 B: Δ_do equal, lifecycle opposite
  │   → 需要: persistent treatment definition, policy feedback tracking
  │   → Access: action type + duration + rollback 记录
  │   → Evidence: sequential policy state + next candidate stream
  │
  └─ 命题 C: source identical, target opposite
      → 需要: scope transport conditions
      → Qualification: scope/version gate + target support audit
  │
  ▼
Sufficient operable auditable authorization conditions (9 conditions)
  │
  ├─ Consistency, Exchangeability, Positivity
  │   → Qualification: overlap check + randomized micro-intervention
  │
  ├─ Treatment/Exposure observability
  │   → Evidence: 完整日志字段
  │
  ├─ Adoption measurement
  │   → Qualification: proxy + error model + partial ID
  │
  ├─ Interference specification
  │   → Access: workspace budget + joint/conditional treatment
  │
  ├─ Measurement stability
  │   → Evidence: scope/version 字段
  │   → Qualification: measurement-stability gate
  │
  └─ Scope transport
      → Qualification: target support audit + Bayesian uncertainty + abstention
  │
  ▼
SQCAD logging / intervention protocol
  │
  ├─ candidate generation → proposal score → exposure propensity
  ├─ position / budget → adoption proxy
  ├─ action → outcome / risk / cost
  └─ governance action → next candidate stream
  │
  ▼
Qualification gate
  │
  ├─ positive / negative: 识别条件满足 → 授权 action
  ├─ unresolved: 识别条件不满足 → 禁止 persistent action
  └─ mismatch: scope/version 不匹配 → 禁止直接应用
  │
  ▼
Risk-sensitive reversible access decision
  │
  ├─ keep / downweight / isolate / archive / restore
  ├─ probe / review（当区间跨越决策阈值时）
  └─ fallback-only（当 unresolved 时）
```

## 6. 约束：什么不应进入核心方法

以下内容不应出现在 SQCAD 的核心方法描述中，因为它们无法被追溯到某个不可识别性反例或识别条件：

- 新的通用因果估计器（SQCAD 使用现有 MSM/DR/OPE，不发明新的）
- 自由能、贝叶斯或神经动力学术语包装
- 自动 hierarchy 或因果图表示本身
- 仅在合成世界中读取 latent truth 的复杂 posterior
- "模块越多越完整"的系统叙述

**检验方法**：对于框架中的每个组件，问两个问题：
1. 它解决了哪个不可识别性反例揭示的信息缺失？
2. 它满足了哪条识别条件？

如果两个问题都回答不上来，该组件应被标记为"工程选择"而非"理论要求"，或直接移除。

## 7. 当前最准确的状态表述

**可以说的**：

> SQCAD 通过三个构造性反例（观测等价 SCM、等 do-effect 相反 lifecycle、source-equivalent 不同 target）建立了 persistent-access lifecycle value 的识别空白，并由此反推出一组充分、可操作、可审计的授权条件。Lemma A–D 表明这组条件不是唯一桥型；其中部分条件可被额外假设替代，或在改变治理粒度/estimand 后退守。治理必要性落在 Theorem 4 所限定的未识别类上的门控，而非完整 C1–C8。条件直接导出 Evidence–Qualification–Access 三层框架：Evidence 保存识别所需变量，Qualification 检查识别假设是否满足，Access 在已识别或决策稳定的价值下执行可撤回的持久访问动作。

**不能说的**（2026-08-13 两批更新）:

- "我们已经建立完整的 Agent Memory 基础因果理论"（self-obscuring 基础理论问题已建立，但"全部基础理论"仍不可声称——`16-` §5 校准边界）
- "authorization certificate 已形式化"（P0 遗留）
- "所有 OPE/MSM 方法都无法完成作用域迁移"
- ~~"T2 的任意-reduction 形式化"~~ → 已升级：faithful feedback-preserving reduction 不可能性为严格证明（`16-` §1：定义 1/2 + 引理 3/4 + 定理 2 + 推论 2/3）
- ~~"探测复杂度的 minimax 严格下界"~~ → 已升级：定理 3 检测下界 + 定理 4 后悔分解 + 推论 4 阶匹配为严格证明（`16-` §2）

**当前最准确的一句话**：

> A counterexample-grounded, memory-specific identification gap that derives an auditable governance protocol from explicit non-identifiability constructions and sufficient operable auditable authorization conditions, with the necessity of the gate (Theorem 4) rather than of the conditions themselves — the identification-theorem side closed by Theorem 3, the necessity side by Theorem 4 (`12-必要性证明与识别路线分类学`), and the structure-side dynamics closed by T1/T2 (`15-self-obscuring形式定理与严格证明`、`实验证据链/13`)。

## 8. self-obscuring 机制对框架的净设计增量（T1/T2 之后，2026-08-13）

`14-` §6 的 T1/T2（严格证明与数值见 `15-`、`实验证据链/13`）回答了 §6 检验方法的第二个问题：**治理动作（archive）如何改变未来候选/证据流（审查），从而改变未来可识别性（证据饥饿），进而锁定后续治理动作（永无修正）**。这一闭环为四层各带来一条可审计的设计增量：

| 层 | 设计增量 | 定理来源 | 数值验证 |
|---|---|---|---|
| Evidence | **沉默语义**：审查世界的沉默是自生成的（静默冻结，引理 2），不是"价值低"的证据；以证据饥饿（t−last_exposed ≥ stale_gap）作为触发信号，而非后验宽度（后验在错误归档下会坍缩——确定性本身是陷阱） | T1(a)、引理 2（15-） | W2 审查下全部策略精确 5.85；W0 去审查即 0.044（`13-` §3） |
| Qualification | **识别集加宽 + P2 三成本决策**：决策用由先验加宽的识别集做 commit/restore/probe 比较（朴素 CI 排除 0 不等于决策可识别） | Theorem 5（12-）+ T1(b) | cost_aware 规则 slope 0.0000、corr 0、一次付费恢复 80（`13-` §5） |
| Access | **恢复通道付费语义**：仅在 censored 世界（审查使 flip 成为真恢复）计费；恢复后再归档 ⇒ 沉默有信息（harm_confirmed），不重复恢复 | T1(b)、T1(c) | A 世界恰一次恢复、成本 80；K 世界平台 0.2937（`13-` §6.2） |
| Decision | **平台保证**：q>0 的恢复策略 E[R_T] ≤ τp/(qρ) + O(1/q)，与 T 无关；恢复通道达到正确复杂度阶（与探测下界同阶，严格化 `16-`） | T1(b)（15-）+ 定理 3/4/推论 4（16-） | sweep q=0.01/0.05/0.2 → corr 818/142/37，理论界 600/120/30 常数因子内一致；`14-` §4–5：E[探测] ≥ N* 全格点、后悔分解 r/L ∈ [2.2, 3.4]（绑定 regime）、τ≤0.5 恢复类严格占优（U/L < 1）、主配置 U=800 ≈ 经验 850.2 |

**框架层级的净变化**：SQCAD 的 Evidence 层不再承诺"日志记录即足够"，而是记录**治理动作对证据流的反馈结构**（action → exposure 机制），Qualification 层把"unresolved"输出升级为三成本比较（commit/restore/probe），Access 层把 restore 定义为付费通道并带 harm-confirmed 语义。这些增量全部可追溯到 T1/T2 的具体机制，符合 §6 的检验方法。

**不变的部分**：C1–C8 授权条件族、Theorem 3/4、识别路线分类学、成本合同与统计门均不变；"不能说的"清单更新如下。
