# 解构—抽象—因果遗忘框架：阶段性可行性判断

## 1. 结论

当前判断为 **Conditional GO（有条件继续）**，而不是“框架已经成立”或“必然超过 SOTA”。现有证据支持继续开发的原因是：表示层、静态因果识别和序贯策略评估均通过了最小可证伪测试，LongMemEval-S 又显示纯时间治理与简单粒度切分存在真实可测的不足。但公开 benchmark 上的词法因子/规则代理及其 sidecar 融合均未超过 Raw BM25 或 dev-tuned RRF hybrid；修复后的可审计 POS 关系 sidecar 也只使 Recall-all@5 增加0.0021，同时显著损害 Recall@1、NDCG 和 MRR。因此框架的外部有效性目前**尚未成立**；能否成为论文贡献仍取决于真实语义解构质量、因果日志/干预可行性以及固定预算下能否超过强检索与遗忘基线。

## 2. 已获得的四类证据

| 证据层 | 已完成实验 | 结果 | 支持范围 |
| --- | --- | --- | --- |

### 解构质量压力测试

新增的组噪声扫描显示，联合解构—抽象—因果方法对机制归类质量敏感：组噪声由 0.0 增至 0.4 时，归一化 utility 从 1.000 降至 0.482，rare-critical recall 从 1.000 降至 0.690，stale retention 从 0.000 升至 0.254。在噪声 0.4 下，联合方法的 utility 点估计（0.482）低于 `causal_item_stable`（0.493），但逐 seed 配对差的95%区间跨过零。因此，当前证据支持的是“在高质量、可审计解构下存在机制性潜力，并且质量下降会产生可测负迁移”，而不是“抽象必然优于因子级治理”。这也将解构质量、provenance coverage 与 scope completeness 设为 Gate A 的实证门槛。

逐 seed 胜率进一步收紧了结论：组噪声0.0/0.1/0.2/0.4时，联合方法在 normalized utility 上战胜 item-level causal 的比例为1.00/1.00/0.98/0.46，在 rare-critical recall 上为1.00/1.00/1.00/0.92，但 stale-retention 胜率始终为0。因而当前框架证明的是高质量解构下的效用与关键记忆保全潜力，不是所有风险指标上的绝对支配；公开实验必须以效用—风险—成本帕累托前沿而非单一平均分决定是否成立。

新增的 risk-gated fallback（表示置信度、跨层效应符号一致性和 item-level 负效应 veto）在同一协议下将噪声0.4的结果改善为 utility 0.815、rare-critical recall 0.690、stale retention 0.007、positive precision 0.896，utility 逐 seed 胜率为1.00。该结果说明风险门控能够缓解抽象误差传播，但 stale retention 尚未严格优于本身为0的 item-level causal baseline，且置信度校准仍是外部验证前提。

## 3. Research Gaps 是否成立

### Gap 1：因果可寻址性与序贯记忆效应识别

**证据状态：部分成立，尚未完成真实系统识别。** 文献与方法审计表明，现有遗忘路线已经使用时间、频率、相似度和结果反馈，因此“现有方法没有任务反馈”不是 Gap。更严格的缺口是：整体轨迹尚未被统一转化为带来源的可干预组件，且暴露由当前策略内生生成。静态混杂实验说明在该机制存在时，共现会产生严重偏差；LongMemEval 的 turn-max 结果又说明机械切分不能解决它。但真实 Agent 日志中是否存在足够 overlap、是否能稳定识别因子效应，仍需实际 runner 验证。

### Gap 2：受证据约束的抽象与样本外安全治理

**证据状态：机制上成立，公开 benchmark 证据不足。** 表面变换实验支持“规则+证据”在条件稳定时迁移，也明确显示低质量解构会产生错误规则。LongMemEval 中 multi-session、temporal-reasoning 与 preference 的较低 Recall-all 暗示跨事件组合和条件作用域确有改进空间，但它没有因子/规则因果金标。因此，Gap 2 的公开验证必须来自扰动叠加层、证据审计和端到端 OOD 任务，而不能只靠原始 QA 标签。

## 4. 框架与痛点是否一一对应

| 痛点 | 方法响应 | 必须观察到的证据 |
| --- | --- | --- |
| 整体轨迹绑定表面特征 | 证据锚定的因子/关系解构 | 表面变换下因果条件覆盖提高，机械切分和摘要不能达到同等效果。 |
| 成功/失败共现不等于贡献 | propensity日志、微干预、DR/MSM/OPE | 因果真值或部署回放中估计偏差和策略排序改善。 |
| 低频关键记忆易被降权 | CATE、不确定性与非对称损失 | 固定保留预算下 false-forgetting 与 rare-critical violation 降低。 |
| 局部规律被过度抽象 | 规则作用域、独立证据支持、规则—证据对照 | 同名不同机制反例中错误继承下降；rule calibration提高。 |
| 错误遗忘不可恢复 | downweight→archive→restore 状态机 | 漂移反转时恢复成功率与恢复延迟优于硬删除。 |

上述对应关系在逻辑上闭合，但只有在消融中逐项退化，才能写为论文贡献。

## 5. 三个 Go/No-Go 门槛

### Gate A：解构器是否达到可用区间

- 已生成 [[experiments/semantic_gate_a/LongMemEval语义解构Gate-A标注规范|LongMemEval语义解构Gate A]]：200个分层问题包（multi-session 70、temporal 50、knowledge-update 50、preference 30），含40 pilot、160 main、418个 gold evidence sessions；源数据与标注资产均有 SHA-256 和独立校验器；
- 人工标注后由确定性评分器报告 Factor micro-F1、Relation F1、provenance coverage、scope completeness 以及 negation/temporal/update error rate；以 packet 为单位做1,000次 bootstrap，性能指标的95%下界须分别≥0.80、≥0.70、≥0.95、≥0.90，错误率95%上界须≤0.10；
- 已实现 `experiments/semantic_gate_a/semantic_decomposition_pos_baseline.py` 及200包预测工件，作为不读取问题、答案、gold evidence ID 的结构性 negative control；其跨度、因子和关系引用通过2项自动测试，但因当前 gold 仍为空模板，尚不报告 Gate A 分数；
- “规则+证据”必须优于整体 session、turn-max、摘要和仅规则；
- 若真实解构质量落入当前模拟中的低准确率区间，停止扩大抽象层，退回证据级治理。

### Gate B：因果效应是否可识别

- 行为日志必须真实记录候选概率、暴露 propensity、共同暴露项和后续状态；
- overlap、有效样本量与权重尾部满足预注册阈值；
- DR/MSM/OPE 在可枚举真值与部署回放中正确排序策略；否则“因果”降级为诊断分析。

### Gate C：是否超过强基线的帕累托前沿

- 至少比较 BM25、dense/hybrid、recency/frequency、FadeMem、Oblivion、Memory Worth 和 DeMem 中可复现者；
- 固定 reader、candidate stream、top-k、token/存储预算和 evaluator；
- 在多随机种子上同时报告任务效用、关键证据保全、错误遗忘、token、延迟和恢复；
- 若只能提升成本或风险而不提升平均准确率，按帕累托改进表述；若所有维度均无增益，否定方法。

## 6. 当前最合理的论文主张

在公开端到端结果产生前，只能使用以下实验前主张：

> 本文研究如何将整体 Agent 轨迹转换为证据锚定、可干预的因子与条件规则，并通过序贯因果效应和风险敏感状态迁移控制其未来可访问性。初步校准表明，该表示在高质量解构下能够跨表面变化迁移，而因果调整可缓解由内生暴露造成的共现偏差；与此同时，低质量解构和无作用域抽象会导致可测量的负迁移。

不能写“绝对提升”“保证泛化”或“已超过 SOTA”。科学上可成立的目标是：明确适用条件、报告失效边界，并在统一协议下证明稳定的多指标帕累托改进。

## 7. 下一步优先级

1. 先对 Gate A 的40个 pilot 包双人独立标注并裁决，冻结 factor/relation/scope 本体；
2. 实现 `EvidenceRecord → FactorRecord → AbstractRule` 的真实语义 parser，在 Gate A 上通过预注册门槛；
3. 设计 LongMemEval 扰动叠加层：表面改写、条件保持、同名不同机制、来源撤回；
4. 在固定 BM25 与 RRF candidate stream 上运行整体 session、turn-max、因子束、规则+证据、仅规则五种表示；
5. 接入一个本地可运行 reader 后做端到端 QA；
6. 配置 Python 3.12/LLM endpoint 后复现 Oblivion；同步核验 FadeMem、Memory Worth 和 DeMem 代码；
7. 达到 Gate A/B 后再进行超参数搜索，避免用调参掩盖机制失效。
