# 基线复现分级与首轮审计

## 1. 复现通过门

为避免把“仓库可访问”写成“论文已复现”，每个 benchmark 和 baseline 依次通过：

1. **R0 身份确认**：论文题名、作者、arXiv/正式出版信息与官方仓库 README 对应；
2. **R1 资产冻结**：源码 commit、remote、license、原论文数据、hash 和 clean worktree 已记录；
3. **R2 官方环境验收**：使用论文声明的 Python/依赖运行官方单测、数据 reader 和 evaluator；
4. **R3 原论文结果复现**：使用论文模型、prompt、数据、评估器和预算获得可与论文表格逐项核对的结果；
5. **M1 统一迁移**：R3 通过后才接入 SQCAD Harness，并保留原协议与迁移协议两套结果。

R1 之前不得运行自定义 proxy；R3 之前不得写“完整复现”；M1 结果不得替代原论文 R3 结果。

## 4. 已发现的协议问题

1. LongMemEval 官方 BM25 脚本在模块导入阶段也要求 dense/OpenAI 依赖，增加了纯 BM25 复现成本。
2. 官方 `sentence-transformers==2.2.2` 与新版 `huggingface_hub` 的 `cached_download` 接口不兼容，必须同时冻结官方 `huggingface-hub==0.23.4`。
3. SimpleMem 最新 main 已显著晚于论文发布，不能用 main 的功能或数字回填原论文结果。
4. LoCoMo 两个本地文件的原始 SHA-256 不同，但 `json.loads` 后对象相等；差异来自 JSON 序列化，后续同时记录 byte hash 与 canonical semantic hash。
5. 当前机器无 NVIDIA GPU，且未发现 OpenAI/Anthropic/Azure/Hugging Face API 密钥；需要模型的 R3 暂不能伪装成离线复现。
