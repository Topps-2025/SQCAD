# 0808 会议：老师要求与后续执行清单

> 本文只聚焦 2026-08-08 会议中老师明确提出、反复追问或要求尽快验证的事项。方法框架本身已得到“合理、可以继续推进”的初步认可；当前最紧迫的工作是把框架落到可复现的实验、数据和对比方案上。

## 1. 老师对当前工作的总体判断

- 当前研究问题和整体方法框架基本合理，两个 Research Gaps 与 Permission / Access 的回应关系能够讲清楚。
- 研究者能够定位当前难点，主体想法已经比较充分；下一阶段的关键不是继续扩展概念，而是验证能否支撑一篇论文。
- 当前主要短板集中在：**对比实验、数据支撑、基线复现、评价指标和方法落地**。
- 可以按照 ICLR 2027 的目标继续推进，但暂时不要过早受页数限制影响研究探索；先形成完整版本，再根据会议页数压缩。
- 可采用“先投会议、再根据审稿意见扩展期刊”的路线，因此实验资产和复现记录要保留完整。

## 2. 老师明确要求优先解决的问题

### 2.1 把“解决什么问题”说成可实验验证的命题

需要用通俗且可检验的方式回答：

1. 本方法究竟解决 Agent Memory 中的哪个具体问题？
2. 与现有方法相比，新增了什么信息或治理能力？
3. 为什么该问题不能只用相关性、频率或普通衰减解决？
4. 什么结果能够证明方法有效，什么结果会否定当前设计？

当前建议固定为以下最小论证：

> 在有限工作区预算下，普通关联信号可能把无关记忆一并强化，也可能因低频而遗忘稀有但高价值记忆。SQCAD 需要验证：作用域限定的资格判断与竞争性访问投影，能否减少错误保留，同时保护低频高价值记忆，并保持未来任务效用。

这段表述必须在 Introduction、Method 和 Experiments 中保持一致，不要在尚未验证前写成已经取得的性能结论。

### 2.2 尽快确定 baseline / SOTA 对比方案

老师要求逐个回答以下问题：

- 每个 baseline 来源于哪篇论文？
- 它解决的是哪一类问题：检索、压缩、时间衰减、频率淘汰、反馈更新，还是记忆价值估计？
- 是否有公开代码和公开数据？能否在当前环境中复现？
- 如果不能复现，是否可以构造行为等价的 proxy？proxy 必须明确标注，不能冒充原方法。
- 预印本是否真的属于强 SOTA？引用后是否有能力进行公平比较？
- 不同维度上可能存在多个 SOTA，最终选择标准是什么？

建议建立并持续更新以下表格：

| 方法 | 原论文/版本 | 对比能力 | 代码 | 数据与协议 | 是否完成复现 | 备注 |
|---|---|---|---|---|---|---|
| 基础检索 | 待确认 | BM25 / dense / hybrid | 待查 | 统一候选集 | 未开始 | 必须保留 |
| 时间/频率衰减 | 待确认 | recency / frequency decay | 待查 | 统一时间切分 | 未开始 | 对应常规治理 |
| 记忆治理方法 | FadeMem / Oblivion / Memory Worth / DeMem 等 | 记忆保留、访问或价值治理 | 逐项核验 | 按原协议对齐 | 未开始 | 不得只比较论文报告值 |
| 内部基线 | v3、default-cold、scope gate only 等 | 验证各模块必要性 | 自有 | D0 受控世界 | 未开始 | 优先做小规模预实验 |

## 3. 数据要求：先证明“数据能支撑研究问题”

老师特别强调，提出新 framework 后最现实的问题是：现有公开数据是否包含所需信息。如果没有，必须说明数据如何构建、如何标注以及为什么有效。

### 3.1 公开数据的核验清单

对每个候选数据集记录：

- 是否真实可下载、许可证和访问限制；
- 历史 / 未来切分方式，是否支持 chronological split；
- 是否包含长期事实保持、时间更新、多跳访问和跨 session 变化；
- 是否包含能判断“记忆对任务的真实贡献”的证据；
- 是否能够构造作用域变化、版本变化、低频高价值和错误记忆场景；
- 与每个 baseline 的数据和评价协议是否兼容。

当前候选方向：

- LongMemEval：用于长期事实、时间变化、多 session 和未来任务效用；
- LoCoMo：用于长期对话、多跳记忆和跨 session 更新；
- 受控机制世界：用于构造真实贡献、hitchhiker、低频保护性记忆和作用域迁移的可控真值。

### 3.2 自建/受控数据的最低说明

若公开数据不能直接验证核心主张，需要补充受控数据，并写清：

1. 数据从哪里来，哪些部分是原始数据、哪些部分是合成或增广；
2. 如何定义 positive、negative、unresolved 和 mismatch；
3. 如何标注记忆贡献、作用域和版本迁移；
4. 是否存在任务难度、共同曝光、提示词位置等混杂因素；
5. 如何验证标注效度（人工复核、双人一致性、预实验或微干预）；
6. 合成数据是否只用于机制验证，不能直接替代公开数据的外部有效性。

### 3.3 老师要求的快速验证方式

不要等完整数据集全部准备好再开始。先做一个小规模 subset / 预实验，确认：

- 数据中确实存在“有用记忆 + 无关 hitchhiker”共同出现的情况；
- 低频高价值记忆能够被普通时间/频率衰减错误降低；
- 作用域或版本变化能够产生负迁移；
- 现有 baseline 与 SQCAD 的差异能够被指标观测到。

如果这些现象在 subset 上无法稳定复现，应及时收缩 Research Gap 或调整数据构造。

## 4. 评价指标：必须覆盖“任务效果 + 记忆治理效果 + 资源效率”

老师认为不能只报告公开数据集上的常规准确率。建议分三层规划：

### 4.1 任务效果

- 任务完成率、问答准确率或 future utility；
- 时间更新、长期事实保持、多跳访问能力；
- 作用域切换后的任务成功率；
- 在相同任务效用下的风险变化。

### 4.2 记忆治理效果

- 错误遗忘：低频高价值记忆被错误降权或无法访问的比例；
- 错误保留：负向、过期或作用域外记忆继续影响决策的比例；
- hitchhiker 持久强化率；
- qualification 的 coverage、sign error 和 calibration；
- out-of-scope rejection、negative transfer；
- quarantine / restore rate 与恢复延迟；
- evidence precision、adoption precision，以及 exposure 与 adoption 的区分。

### 4.3 资源与信噪比

- active tokens、workspace occupancy、active fraction；
- token、LLM 调用、工具调用、延迟和成本；
- 固定预算下的任务效用—资源曲线；
- 记忆访问后的信噪比或 Decision-SNR：有用证据占访问资源的比例，或单位预算带来的 future utility。

主指标、次指标和效率指标要提前固定，不能看到实验结果后再挑选有利指标。

## 5. 消融与必要性验证

老师已认可消融实验可以较多，但要求它们服务于“每个模块是否真的必要”。最低应覆盖：

| 消融 | 要回答的问题 | 失败后的处理 |
|---|---|---|
| 去掉 qualification | 作用域资格是否比关联性更重要 | 若无差异，收缩 Permission 主张 |
| 全局资格替代 scoped qualification | 作用域限制是否减少负迁移 | 若无差异，删除 transport gate |
| 去掉 competitive normalization | 竞争性预算投影是否必要 | 若无差异，回退简单衰减 |
| 去掉 protected focus | 低频高价值记忆是否得到保护 | 若无改善，删除保护性主张 |
| unresolved 设为 default-cold | bounded fallback 是否避免过度保守 | 若无改善，简化 fallback |
| 去掉 negative attenuation | 负向资格是否减少 harmful retention | 若无改善，降低负向治理强度 |
| 去掉 mismatch penalty | 作用域外过滤是否有独立贡献 | 若无差异，不主张 scope filtering |
| 去掉恢复/审计路径 | 错误资格后能否恢复 | 若无差异，简化工程接口 |

压力测试不是当前第一优先级。老师建议先确认核心数据、基线和预实验；只有核心机制有效后，再决定是否加入复杂压力测试。

## 6. 当前方法中的两个实验难点

### 难点 A：Score Qualification

需要确定算法如何在明确作用域下，将证据判为：

- `positive`：有足够证据支持记忆的正向贡献；
- `negative`：有足够证据支持负向贡献、伪相关或高风险；
- `unresolved`：证据不足，不能改变持久状态；
- `mismatch`：记忆不属于当前作用域。

可以保留人工审计区域作为安全兜底，但论文主实验应明确自动判定流程、输入证据、阈值、校准和错误恢复方式。

### 难点 B：Competitive Access Decay

需要通过预实验确定：

- 统一公式还是非对称公式；
- positive / negative / unresolved / mismatch 如何映射到访问预算；
- 如何把访问质量投影到固定 workspace budget；
- 如何避免“更多保护”导致工作区过度拥挤；
- 如何证明 token 减少不是以任务效用下降为代价。

公式和超参数不能先凭直觉定稿，应通过小规模实验筛选后冻结，并在测试集上保持不调参。

## 7. 近期执行顺序（按紧迫度）

### P0：立即执行

- [ ] 建立 baseline / SOTA 复现表，先确认代码、数据、协议和可比较性。
- [ ] 建立候选数据集卡片，确认公开数据能否覆盖四类核心场景：hitchhiker、低频高价值、作用域迁移、过期/负向记忆。
- [ ] 设计 D0 受控机制世界的最小版本，并完成 subset 预实验。
- [ ] 用统一 reader、candidate stream、workspace budget、model、prompt 和 evaluator 做首轮公平比较。

### P1：首轮预实验后

- [ ] 确定 Score Qualification 的自动判定和人工审计接口。
- [ ] 确定竞争性访问衰减公式及预算投影方式。
- [ ] 固定主指标、效率指标、风险指标和统计报告格式。
- [ ] 完成内部消融，先验证 qualification、scope、competition、protected focus 四个核心组件。

### P2：机制有效后

- [ ] 接入 LongMemEval 和 LoCoMo 的严格时间切分实验。
- [ ] 加入低风险 randomized expose / mask / delay 微干预，校准资格方向和证据有效性。
- [ ] 再决定是否加入 GoodAI-LTM 或其他动态交互环境。
- [ ] 根据 ICLR 页数限制压缩完整版本，并保留会议后扩展期刊的实验资产。

## 9. 明确的“不应提前声称”

- 尚未完成实验前，不声称 SQCAD 已优于 FadeMem、Oblivion、Memory Worth、DeMem、SimpleMem 或其他 SOTA。
- 尚未完成数据有效性和标注验证前，不声称自建数据集能够代表真实 Agent Memory 场景。
- 尚未完成资格校准前，不把相关性或 LLM 解释直接称为因果证据。
- 尚未证明 token 减少与任务效用相容前，不把访问衰减称为“提高智能”或“必然提升信噪比”。
- 不把压力测试、完整端到端系统和期刊扩展写成 0808 会议前的硬性要求。

## 10. 一句话行动准则

> 先用小规模、可复现的预实验回答“数据能不能测、基线能不能比、指标能不能看出差异”；只有这三点成立后，再扩大实验和压缩 ICLR 版本。
