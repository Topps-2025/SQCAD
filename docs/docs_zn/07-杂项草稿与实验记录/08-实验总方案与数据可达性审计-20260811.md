# SQCAD 完整实验方案、基线与数据可达性审计

> 本文沿着 0808 会议要求，集中回答四个问题：方法到底解决什么、如何公平比较、哪些指标能证明或否定方法、数据和基线是否真的可达。本文是实验设计与可达性审计，不把已有模拟结果写成公开 benchmark 结论。

## 0. 一句话论证与当前边界

### 0.1 一句话论证

在固定工作区预算和策略诱导的记忆曝光下，SQCAD 将关联信号限制在候选提议与低风险临时访问，将持久访问权限交给目标作用域内经过证据审查的资格状态，并通过预算守恒的访问投影检验其是否能在未见作用域和作用域迁移下减少错误保留、保护低频高价值记忆，同时保持未来任务效用。

### 0.2 目前可支持的证据边界

| 结论 | 当前证据 | 状态 |
|---|---|---|
| LongMemEval-S 可用，且 BM25/dense/RRF 检索接口已跑通 | 本地数据、hash、脚本和报告 | 已支持（仅检索层） |
| 关联共现可能造成 hitchhiker 强化 | 受控 simulator 与 v3 报告 | 受控机制支持 |
| qualification gate 在受控世界中有正向模块证据 | v3 / governance simulator | 受控机制支持 |
| 作用域限定在未见 scope 上优于全局规则 | 尚无公开 future-scope 结果 | 待验证 |
| SQCAD 减少 active tokens 且不增加 future regret | 尚无 SQCAD 公开端到端结果；v4 候选结果反而暴露 trade-off | 待验证 |
| SQCAD 超过 FadeMem、Oblivion、Memory Worth、DeMem 或 SimpleMem | 尚未统一复现 | 不得声称 |

### 0.3 关键研究问题

**RQ1：资格权限是否必要？** 在高频 hitchhiker 与任务难度混杂存在时，qualification 是否能阻止无独立证据的记忆获得持久影响？

**RQ2：作用域是否真正提供样本外降噪？** 在任务、用户、工具、模型版本或风险条件变化后，scoped qualification 是否比 global qualification 减少负迁移，而不是把训练轨迹编码成更细粒度的过拟合规则？

**RQ3：竞争性访问是否有独立价值？** 在固定 token / workspace budget 下，competitive projection 是否能把访问质量从未支持、负向或作用域外记忆重新分配给合格记忆？

**RQ4：低频保护与错误遗忘能否同时改善？** protected focus 是否能保留低频高价值记忆，同时不造成过多 harmful retention 或工作区拥挤？

**RQ5：资格判定是否可校准、可审计、可恢复？** Score Qualification 的 sign、coverage、calibration、错误恢复和审计成本是否达到启用 persistent governance 的门槛？

## 1. 实验分层：不让一个数据集承担所有问题

| 层级 | 目的 | 真值/标签 | 主产出 | 不能声称 |
|---|---|---|---|---|

## 2. 统一实验合同（所有方法必须遵守）

在主表比较任何方法前，固定以下合同：

1. 相同 history、candidate stream、query、time split、reader、prompt、LLM/model、tool version 和 evaluator；
2. 相同写入器、Evidence Ledger、embedding、retriever、top-k、workspace token、storage budget 和最大调用次数；
3. 相同随机种子与 paired seeds；所有方法共享潜在结果和候选曝光流；
4. 记录 candidate、exposure、position、adoption、action、outcome、cost、state transition 和 propensity；
5. 公开 benchmark 使用 chronological / rolling-origin split，禁止随机打散导致未来泄漏；
6. 开发集只冻结 hyperparameters，测试集不得按结果重新调 alpha、beta、gamma、temperature、budget 或 gate threshold；
7. 原论文报告值、本地真实复现值、behavioral proxy 和 oracle reference 分栏；
8. 任何方法不能读取 latent value、答案、future evidence 或 gold scope；oracle 只作为诊断上界，不进入主排序；
9. 失败模块按预注册裁决删除或降级，不通过更换弱基线、修改 DGP 或测试集调参保留；
10. 所有外部数据、代码、模型和脚本记录 commit、版本、hash、许可和运行命令。

## 3. D0 受控机制世界：最小可证伪协议

### 3.1 记忆与任务构成

每个 world 包含以下可枚举记忆类型：

- `rare_positive`：低频但在目标 scope 内降低损失或提高 future utility；
- `common_positive`：高频、稳定有用的记忆；
- `hitchhiker`：与真正有用记忆共同曝光，但自身增量贡献为零；
- `negative`：在目标 scope 内增加风险或导致错误行动；
- `stale`：旧版本有效，scope/version shift 后过期；
- `unresolved`：当前证据不足，不能改变持久状态；
- `mismatch`：语义相关但不属于目标 scope；
- `conflict`：与另一条记忆发生时间或版本冲突。

### 3.2 预注册因素

| 因素 | 水平 |
|---|---|
| 任务难度混杂 | low / medium / high |
| hitchhiker 共曝光 | 0、0.25、0.5、0.75 |
| rare-positive 调用频率 | 低频 / 中频 / 高频 |
| scope shift | none / gradual / abrupt |
| version shift | none / tool / model / policy |
| scope overlap | 0、0.25、0.5、0.75、1 |
| qualification noise | 0、0.1、0.2、0.4 |
| workspace budget | 极紧 / 中等 / 宽松 |
| action risk asymmetry | false-forgetting 高 / harmful-retention 高 / 对称 |
| evaluator drift | none / mild / severe |

### 3.3 主要 estimands

1. **Future utility effect**：在相同未来任务流和预算下，方法相对基线的长期 utility 差值。
2. **Hitchhiker persistent influence**：无增量贡献记忆获得 positive persistent permission 的概率。
3. **False-forgetting regret**：rare-positive 被错误降权、隔离或不可恢复造成的未来损失。
4. **Harmful-retention regret**：negative、stale 或 mismatch 继续影响行动造成的未来损失。
5. **Scope transport error**：source scope 的资格错误迁移至目标 scope 的概率。
6. **Access concentration**：固定预算中分配给 positive-qualified evidence 的访问质量占比。
7. **Qualification calibration**：预测 positive / negative 概率与潜在真实状态的一致性。

### 3.4 D0 的核心比较

首轮不要同时运行所有复杂模块，按以下顺序：

1. `keep-all`；
2. `recency / fixed exponential decay`；
3. `frequency decay`；
4. `association-only competitive access`；
5. `v3 qualification gate`；
6. `global qualification + access`；
7. `scoped qualification + no competition`；
8. `scoped qualification + competitive projection`（SQCAD full）；
9. `oracle scope/value`（仅上界）；
10. `item-level causal stable`（强机制基线）；
11. `risk-gated fallback`（资格置信度、符号一致性、negative veto）；
12. `unresolved default-cold` 与 `unresolved bounded fallback`。

### 3.5 D0 的最低运行规模

- 开发阶段：每个关键切片至少 100 worlds × 5 seeds；
- 正式机制主表：至少 300 paired worlds × 10 seeds；高成本配置可采用 300 worlds × 5 seeds，但必须报告 seed-level CI；
- 每个 world 的策略共享 candidate stream、potential outcomes 和任务序列；
- 预注册三类切片：`gap-present`、`gap-absent`、`structure/cost-failure`；不能只报告随机总体。

## 4. 公开数据实验设计

### 4.1 D1 LongMemEval-S：主检索与外部过程验证

**本地已具备：** `tmp/upstream/LongMemEval/data/longmemeval_s_cleaned.json`，470 个非 abstention 问题；数据 SHA-256 为 `D6F21EA9D60A0D56F34A05B609C79C88A451D2AE03597821EA3D5A9678C3A442`；上游 commit 为 `9e0b455f4ef0e2ab8f2e582289761153549043fc`。

**已完成：** Recency、BM25、MiniLM dense、BM25/dense router、dev-tuned RRF；已有报告显示 BM25 是强廉价底线，RRF 提升多证据覆盖但不提升所有排序指标。

**正式 protocol：**

- chronological history → future query；
- session-level 与 turn-level 两种证据粒度；
- 共享 candidate stream，先固定 BM25 / dense / RRF，再叠加 qualification/access sidecar；
- 主切片：knowledge-update、multi-session、temporal-reasoning、single-session preference/user；
- 端到端 QA 使用同一 reader、prompt、LLM 和 evaluator；没有 reader/API 时，只报告 retrieval/process 指标；
- Gate A 200 evidence packets 只用于语义表示审计，不当作整套 LongMemEval 的性能结果。

**D1 主指标：** Recall-any@1、Recall-all@5/10、NDCG@5/10、MRR、evidence precision、active tokens、workspace occupancy、latency、cost、future QA utility、scope slice error。

**D1 限制：** `answer_session_ids` 只能证明证据 session，不能证明某条内部记忆具有增量因果贡献；因此 D1 不能单独证明 persistent qualification。

### 4.2 D2 LoCoMo：长程多跳和外部有效性

**本地可达性：** 已从官方仓库获取 `data/locomo10.json`，10 个 conversation；本地 SHA-256 记录为 `EE94F4C621C82D248847E8A51D2843F72DFB0F77B80F8593DF4FB9B47CC592D`；仓库 `snap-research/locomo` main commit（2026-08-11 核验）为 `3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376`。仓库 README 同时提供 QA、event summarization 和 RAG 评估脚本。

**正式 protocol：**

- 按 conversation/session 时间切分，禁止随机拆分；
- 原始 dialogue、observation、session summary 三种 memory representation 分开跑；
- 重点切片：multi-hop、temporal、open-domain、跨 session update、相似但无决策贡献的 dialogue；
- 主 reader、prompt、candidate stream、token budget 和 evaluator 固定；
- 使用 evidence dialogue ids 做 evidence coverage，而不把 QA F1 直接解释成记忆治理因果效果。

**D2 指标：** QA EM/F1、evidence recall/precision、multi-hop success、temporal consistency、contradiction rate、active tokens、latency、cost、作用域切换后负迁移。

**许可证边界：** GitHub API 返回仓库 license 为 `NOASSERTION`；使用前核对 `LICENSE.txt` 和数据再分发条款，论文发布前保留许可记录。

### 4.3 D3 GoodAI-LTM：动态在线验证

**网络可达性：** `GoodAI/goodai-ltm-benchmark` main commit（2026-08-11 核验）为 `188e7618413775f1ce783763d5ee0b5ccd4c31c9`；仓库提供 benchmark configurations、runner、datasets、evaluate.py 和已有 reports；README 标明包含动态长期记忆任务和多个 memory-span 配置。

**执行条件：** 需要统一 agent adapter、配置文件、模型/LLM endpoint 和 evaluator。仓库 license 元数据为 `NOASSERTION`，需人工核对 LICENSE 与内含数据的第三方许可。若没有可用生成模型或 judge endpoint，不得将仓库可访问写成端到端复现。

**D3 protocol：** retain → revise → update → conflict → scope shift → return-to-old-scope → restore；报告逐场景结果，不只报告平均分。

**D3 指标：** task success、update accuracy、stale access、false forgetting、restore success、recovery latency、active tokens、LLM/tool cost、worst-scenario 和 CVaR。

### 4.4 D4 MemoryAgentBench：第二阶段覆盖复验

**网络可达性：** `HUST-AI-HYZ/MemoryAgentBench` main commit（2026-08-11 核验）为 `455306dcabc3842526eb83cd4e225e5d486c5c5d`；仓库 license 为 MIT；README 提供 Hugging Face 数据入口、四类能力和任务级 exact/substring match 说明。

### 5.4 Baseline 可比性规则

- 不能只与 recency/FIFO 比；至少纳入 BM25、dense、RRF、fixed decay、v3、item-level causal 和一个可运行的强治理方法；
- 论文没有开源或环境不可运行时，必须写 `not reproduced` 或 `behavioral proxy`；
- 不把 SimpleMem 的自报 SOTA 数字直接放进本地主表；除非运行同一版本、同一数据、同一模型和同一 evaluator；
- FadeMem、Oblivion、Memory Worth、DeMem 的原论文报告值只能作为背景，不能与本地结果混排；
- 若最接近 baseline 在同协议下不能运行，主张应收缩为“相对可复现控制的机制结果”。

## 6. 最重要的评价指标与预注册主次层级

### 6.1 主指标（论文主表）

1. `Future utility`：未来任务效用，越高越好；
2. `Future regret`：相对 oracle policy path 的损失，越低越好；
3. `False-forgetting regret (FF-regret)`：低频高价值记忆被错误降权/隔离造成的损失；
4. `Harmful-retention regret`：negative、stale、mismatch 继续影响行动造成的损失；
5. `Scope transport error / negative transfer`：资格跨 scope/version 错迁移造成的错误；
6. `Matched-utility active tokens`：在相同 future utility 或 regret 下的 active token 成本；
7. `Qualification calibration`：Brier、ECE、coverage、sign error 和 interval coverage。

### 6.2 次指标

- Retrieval：Recall-any@1、Recall-all@5/10、NDCG@5/10、MRR；
- evidence：evidence precision、coverage、provenance completeness、scope completeness；
- memory action：positive / negative / unresolved / mismatch confusion matrix；
- lifecycle：quarantine rate、restore rate、recovery latency、stale survival；
- robustness：worst-group utility、CVaR、scope-shift degradation、evaluator drift degradation。

### 6.3 成本指标

- active tokens、workspace occupancy、storage bytes；
- LLM call、embedding call、tool call、probe call；
- wall-clock latency、GPU/CPU memory、API price；
- 每单位 future utility 的 token/cost；
- qualification coverage–cost curve。

### 6.4 Decision-SNR（只作为派生指标）

不要把“token 少”直接称为信噪比提高。建议报告：

\[
\mathrm{Decision\text{-}SNR}_t=
\frac{\sum_i a_{i,t}\,\mathbf{1}[m_i\text{ is positive in target scope}]}{\sum_i a_{i,t}}
\]

并同时报告 utility、risk 和 token。若 SNR 上升但 future utility 下降，不能称为成功。

## 7. 消融矩阵与失败裁决

### 7.1 核心模块单变量消融

| 编号 | Full vs ablation | 主要假设 | 必须同时看 | 失败裁决 |
|---|---|---|---|---|
| A1 | scoped qualification vs association-only | 资格阻止 hitchhiker 持久强化 | future utility、hitchhiker influence | 收缩 Gap 1 |
| A2 | scoped vs global qualification | scope 降低负迁移 | unseen scope、transport error | 删除 transport gate |
| A3 | competitive projection vs independent decay | 固定预算耦合必要 | matched utility tokens、FF | 回退简单衰减 |
| A4 | protected focus vs no positive floor | 保护低频高价值 | FF-regret、rare recall | 删除保护主张 |
| A5 | bounded fallback vs default-cold | 中性访问避免过度保守 | utility、unresolved recall | 简化 fallback |
| A6 | negative attenuation vs no negative action | 减少 harmful retention | harmful-retention regret | 降级负向治理 |
| A7 | mismatch penalty vs no penalty | 作用域外降噪 | negative transfer | 不主张 scope filtering |
| A8 | qualification auto vs oracle qualification | 自动审查误差代价 | sign error、coverage | 不启用 persistent governance |
| A9 | Evidence–Belief–Access 分离 vs 合并 | 防止来源被派生状态覆盖 | recovery、audit completeness | 保留为工程安全，而非性能贡献 |
| A10 | restore path vs irreversible deletion | 可恢复治理降低 FF | restore success、latency、cost | 只保留证据账本 |

### 7.2 作用域过拟合专项实验

这是当前最重要的理论风险，必须单独做，而不能藏在普通消融里：

1. `seen-scope`：训练与测试作用域一致；
2. `unseen-scope`：留出用户、任务类别、工具或模型版本；
3. `scope-shift`：训练后改变 tool/model/policy；
4. `return-to-old-scope`：旧作用域重新出现；
5. `granularity`：粗、中、细三种 scope 粒度；
6. `scope label permutation`：打乱 scope 标签，检验是否只是标签记忆；
7. `boundary adversary`：高语义相似但目标作用域中无效的记忆；
8. `complexity penalty`：报告 scope 数量、规则数、状态存储和审计成本。

**判定原则：** 只有当 unseen / shifted scope 上同时降低 negative transfer 或 harmful retention，且没有成比例增加 FF-regret 和规则复杂度，才能称为 scope-conditioned denoising；只在 seen-scope 改善，应判为作用域过拟合。

### 7.3 成本与预算专项实验

- workspace budget：极紧、中等、宽松；
- probe price：0、低、中、高；
- token cost heterogeneity：短/长记忆混合；
- risk asymmetry：false forgetting 高、harmful retention 高、对称；
- cold-start：没有 qualification evidence 时是否还能工作；
- high-noise：Gate A 表示或 scope 识别错误时是否安全回退。

## 8. 统计、报告和停止规则

### 8.1 统计规则

- world/episode 为分析单位，不把每个 token 或每次检索当独立样本；
- paired seed-level bootstrap 95% CI；同时报告均值、median、worst-group、CVaR 和 pairwise win rate；
- 多切片、多消融使用预注册 family control；
- 先报告 absolute metrics，再报告 paired delta；
- utility 与 risk 必须联合解释，不用单一平均值掩盖 trade-off；
- 外部 benchmark 报告数据集版本、样本数、过滤规则和失败样本数；
- reader/evaluator 不稳定时，报告 evaluator agreement、重复运行方差和停止更新规则。

### 8.2 Go / No-Go 门

| Gate | 通过条件 | 不通过处理 |
|---|---|---|
| G1 数据可测 | subset 上稳定出现 hitchhiker、rare-positive、scope shift 和可观测差异 | 重构 D0 或收缩 gap |
| G2 基线可比 | 至少 B1–B8、v3、item-level causal 可统一运行 | 不进入 SOTA 主表 |
| G3 qualification 必要 | A1 在 gap-present 切片降低 hitchhiker influence 且不恶化 future utility | 降级为诊断协议 |
| G4 scope 样外有效 | unseen/shifted scope 降低 negative transfer | 删除 scoped denoising 主张 |
| G5 低频保护 | A4 降低 FF-regret，matched utility 下不增加 harmful retention | 删除 protected focus |
| G6 预算耦合 | A3 在固定 utility/risk 下减少 active tokens | 回退简单访问规则 |
| G7 calibration | qualification sign error、ECE、coverage 达到预注册阈值 | 不启用 persistent permission |
| G8 外部效度 | 至少 LongMemEval 或 LoCoMo 一个 future-split 通过，且 D6 一个微干预切片通过 | 只保留受控机制结论 |
| G9 成本可接受 | probe、LLM、token、latency 不超过预设预算 | 简化 audit / fallback |

### 8.3 当前不应使用的成功标准

- 只减少 active tokens；
- 只提高 Recall-all；
- 只在 seen-scope 有效；
- 只在 oracle qualification 下有效；
- 只超过 recency/FIFO；
- 只引用别人的 SOTA 数字；
- 只用 LLM judge 的单次分数；
- 用合成数据结果替代公开数据外部效度。
