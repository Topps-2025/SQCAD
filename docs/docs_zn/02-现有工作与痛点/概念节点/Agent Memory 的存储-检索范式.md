# Agent Memory 的存储-检索范式

存储-检索范式是当前 Agent Memory 中最常见的工程模式：系统将对话、任务轨迹、工具调用结果、用户偏好或环境反馈写入外部存储，并在后续任务中通过向量相似度、关键词、图索引或规则检索相关记忆。

## 基本流程

1. 写入：把当前交互或任务结果保存为记忆条目。
2. 索引：为记忆生成向量、关键词、时间戳、实体或图关系。
3. 检索：在新任务中找出相关记忆。
4. 注入：将检索到的记忆放入上下文，辅助模型回答或决策。

## 核心局限

这个范式容易默认“保存更多就是更好”。但长期运行的 Agent 会不断积累低价值、过时、重复和冲突信息，使记忆系统从经验资产变成认知负担。

主要问题包括：

- 检索候选空间持续扩大，成本上升。
- 低质量记忆可能被错误召回，污染上下文。
- 旧经验可能在环境变化后失效。
- 系统缺乏判断记忆生命周期的机制。
- 删除、降权、压缩和归档常被视为补丁，而不是基础操作。

## 与遗忘机制的关系

遗忘机制不是存储-检索范式的附属功能，而是对这个范式的必要修正。没有遗忘，写入会退化为无差别堆积；没有记忆治理，检索会被迫在越来越嘈杂的历史中寻找信号。
