## 4. 环 2：形式化基础理论（必要性/充分性证明）

**问题**：为什么该问题不能只用相关性、频率或普通衰减解决（必要性与充分性）。

**指标（L1）**：提交斜率、max regret 下界、探测下界、配对恒等式、识别集合分离。

**已得证明与数值**（证据链 `11-`/`12-`/`13-`/`14-`，代码 `reduction_closure.py`）：
- T1(a)(b)(c)（`15-`）：无恢复提交策略 slope **5.8500 精确** = τ·p·(T−n_early)/T；W0 去审查 0.0440；W3 恢复平台 0.4250 / 0.2937 / 0.0000；W0/W1 reduction controls 有效；
- T2 严格化（`16-`，commit 481f18c）：faithful feedback-preserving reduction；配对恒等式 regret_K+regret_A ≡ τp(T−n_early) = **11700.0 对任意策略逐点精确**；定理 2：max regret ≥ ½τp(T−n_early) = Θ(T)；推论 2/3；数值：bandit_ucb/standard_ope 精确 5.8500、oracle 0.0000、contextual_bandit ≈0.03（**失败必要条件是行动触发的审查**）；

## 5. 环 3：框架设计（三层 + 资格授权）

**设计**（`10-` §8 + `21-`）：
- Evidence 层：不可变证据日志（沉默语义：未暴露 ≠ 不存在）；
- Qualification 层：资格证书 τ(i,s) = V_s^π(keep_i) − V_s^π(archive_i)，识别区间 [L,U]；
  - L>0 → keep/restore；U<0 → archive；L≤0≤U → defer 或 VOI probe（VOI = C_defer − (C_probe + R\*(L′,U′))，R\*(L,U) = U(−L)/(U−L)）；
  - 识别集合跨动作边界不允许"低 regret 随机 commit"（最小安全提交条件）；
- Access 层：资格投影（先移除被授权 archive 的对象）→ 排序投影（冻结 proposer 在资格兼容对象内选 top-B）。检索器只能决定"先看谁"，不能决定"谁长期留下"。

**实现**：`src/sqcad/qualification_access.py`（QualificationCertificate / decide_persistent_action / ProbeOption·probe_value / plan_access）+ 5 项结构测试（tests/test_qualification_access.py 全过）。

**指标（L1 派生）**：interval coverage、false-commit rate、safe-commit rate、action sign error（E1 验收）。

**待办**：E1 受控资格授权恢复实验（`21-` §3 E1：在 identification_recovery_experiment 上输出每 memory-scope 证书，treatment 随机化 keep/archive）。

## 7. 环 5：自建 SQCAD-LifecycleBench（内部效度）

### 7.1 数据集（22- 方案 → 本批 MVP 构建完成）

**为什么需要**：LongMemEval-S/LoCoMo 没有同一持久动作在未来的对照轨迹，不能单独证明 keep/archive 的生命周期价值（22- §1）。

**构建结果**（`src/sqcad/lifecycle_bench/`，输出 `results/lifecycle_bench/`，本批 20260817 完成）：
- 6 家族 × 200（hitchhiker / rare_bridge / version_update / harmful_stale / self_obscuring / scope_mismatch）+ 3 controls × 50（stable_positive / stable_negative / neutral）+ 15 观测等价对（30 episodes，hitchhiker 槽 5 隐藏 needed e1→h1 翻转）＝ **1380 episodes**；
- 全部 14 个场景 bucket 的 oracle == designer label **严格一致**（含 controls 的 neutral 弃权），15/15 pairs flip 生效；
- 三层序列化：public.jsonl（无金标）/ policy_log.jsonl（reference_sqcad 双分支，无 needed/success/tau）/ hidden.jsonl（evaluator 独占标签）/ manifest.json（冻结合同：常量、seeds BASE=20260817 / PAIR=20260818 / SPLIT=20260819、split 表）；
- split：group 级（family, variant, entity）60/20/20 → train 818 / dev 354 / test 208；同一 pair 永不跨 split；
- 47 项数据合同测试全过（tests/test_lifecycle_bench_contract.py）：6 特征、branch fork、slot0 局部相同、oracle sign map、观测等价对、split hygiene、frozen manifest、policy log 无金标、probe 行为（crowding deny 仍计费 / rescue restore / NEGATIVE 禁 probe）。

**六特征落实**（22- §3）：持久动作分支（keep/archive 双 rollout，keep 字面语义：NEGATIVE 不自动驱逐，驱逐只由未来事件 requalify 触发）；真正 chronological future（槽 1–10，未来值不提前泄漏）；可执行 outcome（折扣效用按 frozen 合同计算）；同源反事实（共享未来流，slot0 位级相同）；隐藏可核验标签（needed ids / oracle 只在 hidden 层）；压力与不可识别世界（crowding、rescue 失败、观测等价翻转、version drift、harm 对称不可识别 → neutral）。

### 7.2 实验协议
