# 基线开源状态与无 GPU 复现审计（2026-08-13）

## 0. 文档定位

承接 `17-SQCAD公开数据集落地与框架实验方案` §3 的 R1/R2/R3 三层比较，回答每个基线工作的四个问题：

1. **代码是否开源**（官方仓库、license、与论文的同一性）；
2. **未开源时如何复现**（论文披露了什么、缺什么、行为代理怎么做）；
3. **开源代码在无 GPU 环境下复现会发生什么**（CPU 可跑的部分 / API key 阻塞 / GPU 阻塞，逐项列出）；
4. **该基线与 SQCAD 在实验方案中的对比位置**（R1/R2/R3、统一合同行、transportable/not_transportable、主张边界）。

**核实方法**：2026-08-13 网络核查（官方 README、LICENSE、arXiv/会议页；HF 走镜像），交叉确认；本地 D 盘冻结快照（复现门 R1）优先于网络状态。无法直接抓取的页面标记 `unverified`。机器可读细节在仓库 `docs/实验证据链/15-基线开源状态与无GPU复现审计-20260813.md`（GitHub 展示层，英文），本文件只保留结论与对实验方案的裁决。

**环境事实**：本机无 NVIDIA GPU、无 OpenAI/Anthropic/Azure/HF API key——这是本次审计的动因，如实记录，不伪装离线复现。

## 3. 核心结论

1. **无 GPU 不是主要墙，API key 才是**。12 个系统中只有 ActMem 一个真正被 GPU 卡死（8B 嵌入模型）；其余要么纯 CPU 可跑（Oblivion 的衰减/Qdrant、SAGE 的 vMF、GateMem 的构造、Memory Worth 的计数器），要么被 LLM API key 阻塞（SimpleMem、Oblivion、CMI 的骨干与评测）。
2. **Oblivion 是"代码公开但闭源许可"**——可以本地运行与审计（快照已冻结），但不能随仓库再分发，论文中必须如实写成非开源，不能写成"open-source baseline"。
3. **五个系统无官方代码**（FadeMem、Memory Worth、DeMem、Trivium、GovMem）。论文机制披露足以实现行为代理——这正是统一合同里 `not reproduced` 代理行的含义；原论文数字一律不借用。
4. **GateMem 是基准、SAGE/MemAudit 是写时/事后系统**，三者都不映射到访问时治理策略，维持 `not_transportable`、主表无行（`实验证据链/09` 声称纪律不变）。
5. **无 GPU 环境下 17 号方案的现实执行顺序**：(a) R1/R2 统一合同主表——已完成；(b) LongMemEval-S / LoCoMo 检索协议——现在可做；(c) LoCoMo 官方 F1 评分——无需 judge LLM，本地 reader 生成答案即可解锁；(d) 端到端 QA 与 R3 官方复现——阻塞如实标注；其中 Oblivion/SimpleMem 的**非 LLM 机器（单测、数据 reader、检索组件）现在就能离线验收**，缩小日后只剩端点的缺口。
6. **对比位置不变**：SQCAD 完整行必须用动态生命周期 runner；`risk_gated_decomp_abstract` 只标受控代理（17 §5.2）；官方系统行保持 `not reproduced`/`not_transportable` 直到 R3/M1 门通过。
