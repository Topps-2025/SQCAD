# 解构—抽象最小模拟实验：初步可行性报告

## 1. 实验定位

该实验是方法可行性的 sanity check，不是 LongMemEval、LoCoMo 或任何公开 benchmark 的结果，也不构成 SOTA 结论。它只检验一个必要条件：当训练阶段的表面身份在测试阶段发生变化、但潜在有效条件保持不变时，证据锚定的解构—抽象是否比整体轨迹记忆更能保留可迁移的条件信息，同时避免因低频而遗忘关键因素。

实现脚本：[[decomposition_abstraction_sanity.py]]；原始结果：[[decomposition_abstraction_sanity.json]]。

## 2. 协议

- 30 个独立随机种子（`0–29`）；
- 24 个潜在类别；每类拥有训练阶段的 opaque surface identity 和测试阶段未见过的 opaque identity；
- 潜在因果因子在训练/测试之间保持不变，表面身份发生变化；
- 解构器以 `0.9` 概率正确测量潜在因子，以 `0.1` 概率产生测量错误；
- 额外设置一个只有 2 条训练证据的低频关键类别；频率治理以训练计数中位数为阈值，故会将该类别降为不保留；
- 比较整体表面匹配、证据锚定的解构—抽象、真实因子上界，并报告 OOD 效用、规则精度和低频关键记忆保全。

## 3. 30-seed 汇总结果

| 指标 | 整体表面匹配 | 频率基线 | 因子但不抽象 | 解构—抽象 | 真实因子上界/参照 |
| --- | ---: | ---: | ---: | ---: | ---: |
| IID exact accuracy | 1.000 ± 0.000 | — | — | — | — |
| OOD accuracy | 0.667 ± 0.000 | 0.667 ± 0.000 | 0.667 ± 0.000 | **0.898 ± 0.030** | 1.000 ± 0.000 |
| 规则 precision | — | — | — | 0.823 ± 0.056 | — |
| 规则 false-positive rate | — | — | — | 0.099 ± 0.041 | 0.000 |
| 低频关键类别保全 | 0.000 | 0.000 | 0.000 | **1.000** | 1.000 |

均值和样本标准差由脚本直接生成；解构—抽象的 OOD accuracy 的 95% 正态近似置信区间半宽为 0.011，规则 precision 的半宽为 0.020，false-positive rate 的半宽为 0.015。`rule precision` 只在规则被激活的预测上计算。结果表明，在该机制明确、难度受控的世界中，整体轨迹、频率治理和“因子但不抽象”均无法跨越表面身份变化；解构—抽象取得明显 OOD 增益并保留低频关键类别，但仍产生可测量的错误规则激活。

### 3.1 解构准确率敏感性（30 seeds）

| 解构测量准确率 | 解构—抽象 OOD accuracy | 规则 precision | 与整体表面匹配 OOD（0.667）的关系 |
| ---: | ---: | ---: | --- |
| 0.60 | 0.609 | 0.439 | 更差 |
| 0.75 | 0.760 | 0.618 | 更好 |
| 0.90 | 0.898 | 0.823 | 更好 |
| 1.00 | 1.000 | 1.000 | 更好 |

该敏感性结果是重要的否证边界：解构质量不足时，抽象会放大测量错误，拟议机制反而劣于简单表面匹配。因此，论文不能把解构器视为无代价前提；真实实验必须报告其来源可追溯率、规则校准与 OOD 增益，并设置“整体轨迹/摘要/仅规则”对照。

## 4. 可以支持与不能支持的结论

**可以支持的暂定判断：** 解构—抽象作为因果遗忘架构的表示接口具有必要的可行性信号；它直接对应“表面相关性不等于可迁移贡献”和“低频不等于低价值”两个压力场景。规则 precision 的下降说明来源证据、作用域门控和规则—证据对照不是装饰，而是必须进入后续方法。

**不能支持的结论：** 该实验不能证明真实 Agent Memory 上的因果识别成立，不能证明 LLM 能可靠完成解构，不能替代公开 benchmark，也不能证明已经超过任何 SOTA。它使用了显式潜在因子和受控测量噪声，真实数据还需要面对未测混杂、多个记忆干扰、检索失败、工具版本变化和评估器漂移。

## 5. 下一步实验门槛

1. 将同一协议扩展为可枚举潜在结果，比较整体轨迹、摘要压缩、因子束、规则+证据和仅规则五种表示；
2. 扫描解构准确率、规则支持阈值、环境漂移强度和低频比例，报告 OOD utility、PEHE/effect-sign、rule calibration、false-forgetting 与存储/token 成本；
3. 在实现真实 Agent runner 后，固定模型、检索器、提示模板、预算和 evaluator，以多随机种子重跑 LongMemEval/GoodAI-LTM/LoCoMo；
4. 若去掉证据定位、作用域或稳定性门槛后指标不退化，则删除或降级相应方法主张；若公开 benchmark 无增益，则将本文定位收缩为因果诊断与安全治理协议。
