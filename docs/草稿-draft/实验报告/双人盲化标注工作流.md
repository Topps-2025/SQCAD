# Gate A 双人盲化标注工作流

## 1. 文件分配

- 标注者A只接收 `workspaces/pilot_annotator_a.jsonl`；
- 标注者B只接收 `workspaces/pilot_annotator_b.jsonl`；
- 两人均不接收主模板中的参考答案；
- 裁决者保留 `longmemeval_semantic_gate_a_200.jsonl`，但第一轮结束前不展示参考答案。

两份工作区都包含相同40个 pilot 包和相同原始证据，但 `annotator_id` 不同。manifest 保存答案哈希和不可变 packet identity，可证明问题与证据未被标注者修改。

## 2. 离线界面

双击 [[gate_a_annotation_ui.html|Gate A离线标注器]]，通过“载入盲化 JSONL”选择自己的工作区。界面支持：

1. 在同一 turn 中选择文字并创建精确 Evidence span；
2. 添加 Factor、Relation 和 Abstract rule candidate；
3. 指定 subject/task/time scope、否定极性和 evidential status；
4. 记录 query-required factors、反例检查和 notes；
5. 下载更新后的 UTF-8 JSONL。

界面不访问网络，也不会自动读取参考答案。浏览器内的“检查当前包”只检查本包 ID 引用；下载后必须运行 Python 校验器。

## 3. 独立性要求

- 裁决前不交换标签、截图或讨论具体 packet；
- 可共同讨论说明书中的抽象定义，但一旦修改本体，必须记录版本并重新检查已标包；
- pilot 完成前不查看 POS-v2、LLM parser 或其他系统预测；
- 第一轮完成后才由裁决者解盲参考答案并处理漏标。

## 4. 校验命令

```powershell
python validate_longmemeval_semantic_gate_a.py `
  "..\..\..\..\..\tmp\upstream\LongMemEval\data\longmemeval_s_cleaned.json" `
  "workspaces\pilot_annotator_a_annotated.jsonl" `
  "workspaces\pilot_annotator_a_manifest.json"
```

标注文件允许变化，但不可变 packet identity 必须与 manifest 一致；跨度偏移、role、Factor/Relation/Rule 引用或枚举错误都会导致失败。

## 5. 裁决与评分

两份文件分别校验通过后，先计算双标一致性，再产生第三份 `pilot_adjudicated.jsonl`。只有裁决文件可以作为 Gate A gold，随后使用 [[score_semantic_gate_a.py|评分器]] 比较语义解构器预测。通过条件采用1,000次 packet bootstrap 的保守95%边界，而非点估计。

工作区、界面、manifest、校验器和评分器已经可用；HTML 中的 JavaScript 已通过 Node 语法检查。自动化浏览器因安全策略禁止访问本地 `file://` 页面，故未完成浏览器内交互回归；标注者首次使用时应先载入一份工作区、创建一个测试 span 并下载后运行 Python 校验器。人工标注尚未执行，因此当前只能报告“annotation-ready”，不能报告“Gate A passed”。
