## 3. 统一合同主表

### 3.1 共享合同（所有策略逐项相同，缺一不可）

- **候选流**：32 个候选（4 rare_critical + 8 common_useful + 8 stale + 12 noise），每候选携带 `content_tokens`（词法痕迹 + 语义标签 token，是 BM25/dense/RRF 的确定输入）与全部属性列（真实组、语义组、语义置信度、recency、frequency、success_rate、item/group 效应下界、token 成本）；
- **写序无信息性（公平性修复）**：`build_episode` 按组序生成候选后，用 `random.Random(seed·7919+17)` 重排——**流的写序不携带质量信息**，否则 FIFO 会因"稀有组先写"而天然最优；
- **任务流**：100 步，30% rare_critical / 55% common_useful / 15% none，`query_tokens` 驱动检索器；
- **工作区预算**：12 项（workspace item budget）；keep_all 例外行按其性质保留（上下文成本对照，见 §4）；

- **流一致性**：30 seeds 内每个策略收到的候选流 SHA-256 完全一致（`TestSharedContract` 校验）；
- **种子**：每策略每 seed 同一 RNG 流。

### 3.3 主表上的公平性工程修复（审计透明）

1. **写序洗牌**：流的写序与质量解耦（§3.1），否则 FIFO 天然最优、主表失效——这是"共享合同必须对所有策略一视同仁"的直接实现；
2. **FIFO 语义**：按 `write_order`（最先写入的最先驱逐）而非"最久未访问先驱逐"——后者会把 rare（recency 最低的组）当最旧驱逐，等价于作弊的 recency 策略；
3. **检索器共享输入**：BM25/dense/RRF 只消费候选流自带的 `content_tokens`/语义嵌入，不读任何"正确答案"字段；
4. **not_transportable 行物理缺行**：sage/memaudit/gatemem 的 engine 直接抛 `KeyError`（`TestTwoTables` 断言），主表结构上不存在这些行的数字。

## 4. 读表：三层解读（全部限定在共享流上）

**第 1 层 — 简单对照组（排除平凡解释）**：

- `no_memory` 0.159 / 0 tokens：无记忆基线（只有 15% 的 none 任务天然成功）；
- `keep_all` 0.650 / **962.2 tokens**：全保留的上下文成本是主表 token 中位（≈359）的 **2.68×**——"更大上下文"不是免费解释，预算约束下的治理问题依然存在；其 stale 暴露 = 1.0；
- 检索器对照：bm25/dense 召回 1.0 但 **stale 暴露也是 1.0**（最近记忆即过期记忆，词法与语义检索都把 stale 检索出来并暴露）；rrf 融合把 stale 降到 0.796——**更好的检索器改善暴露质量，但治理问题（近记忆 = 过期记忆）不消失**；
- fifo/lru/recency/fixed_decay 在 0.067–0.632 区间：任意静态预算策略都系统性暴露 stale。

**第 2 层 — 核心治理基线**：所有传输策略在**共享流上**的表现：memory_worth 0.205（关联性信号信任最近成功的 stale——Gate A 已标注的结构性失败模式）、oblivion 0.085（衰减方程 R=exp(−age/S) 中 S 含 access_frequency，而 stale 正是高频成功记忆）、fademem 0.233、simplemem 0.308、demem 0.540（区分性准则保留 rare，stale 暴露仍 1.0）。**结论限于本流**：依赖观测成功/频率/最近性的治理策略被"最近 = 过期"的结构性惩罚——这不是设计缺陷，而是评审要求暴露的真实结构；代价曲线属于 Gate 4 的 utility–risk–cost frontier。

**第 3 层 — 最近的理论工作**：causal_item 0.891 但 **rare 召回 0.217**（流的 75% rare 项 item 效应不可识别 → 局部效应策略结构性丢弃它们，stale 0）；trivium 0.767（rare 0.817 但 stale 0.667）；**risk_gated_decomp_abstract 0.991 / rare 0.833 / stale 0.000 / 359.7 tokens**——item 效应 + 组级回退（causal_item 丢弃的未识别 rare 由组效应接住）+ 危害否决，在**零 stale 暴露与零 token 溢价**下恢复 rare。这是 Theorem 2（局部效应不足）在治理层最接近的对照：causal_item 拿到的正是 CMI 的 estimand，而它做不了 rare 的生命周期决策。

**统一合同下可迁移治理策略的排名（utility）**：demem 0.540 > simplemem 0.308 > fademem 0.233 > memory_worth 0.205 > oblivion 0.085；理论组：causal_item 0.891 > trivium 0.767；框架：0.991。**声称范围**（与目标声称一致）：在固定的 Agent、候选流、预算、评估器和时间协议下，SQCAD 相比强治理基线改善 utility–risk–cost frontier 上的预注册指标；**不是**"SQCAD 解决所有真实 Agent Memory 管理问题"。

## 5. 可以声称 / 尚不能声称

**可以声称（均有数字支撑）**：

1. 三组基线在**同一共享合同**（同一候选流 + 任务流 + 预算 + 评估器 + 种子，流 hash 一致、决策日志完整率 1.0）上可比；主表不存在"不同协议下各跑各的"；
2. 简单对照结论：**更大上下文（keep_all）与更好检索器（bm25/dense/rrf）不解决治理问题**——预算约束下 stale 暴露不消失，token 成本 2.7× 于受治理方案；
3. 关联/局部因果/时间折现三类核心替代方案在共享流上各有结构性失败点（memory_worth/oblivion 信任 stale；causal_item 丢弃未识别 rare；trivium stale 0.667），SQCAD 的组级回退在**零 stale 暴露、零 token 溢价**下恢复 rare（0.833 vs causal_item 0.217）；
4. **原协议复现表完整记录了"哪些没复现、为什么没复现"**（模型依赖的 R3 被离线环境阻塞，如实标注，没有伪造数字）；
5. 无法公平迁移的完整系统（sage/memaudit/gatemem）**不存在主表行**，未与任何数字比较。

**尚不能声称**：

- 主表数字是**共享合成流上的 M1 工程表**，不是真实轨迹上的结果——最终数字必须来自 Gate 2.2 的 trace-grounded 半合成 episode（真实对话/候选/时间线 + 受控注入），Gate 1 仅证明"统一合同本身公平且传输规则忠实"；
- 任何"在真实 Agent 上的治理改善"——需要 Gate 2.3 的端到端外部验证；
- 成本维度——trivium 的探测层成本、probe 预算等属于 Gate 4 的 λ/ρ 成本合同，本表只含 token 成本；
- 对 `not reproduced` / `not_transportable` 系统的任何优劣判断——没有数字就没有竞争；
- 该流的任务分布（30% rare / 55% common / 15% none，recent=stale）下 SQCAD 的优势是否跨任务分布稳健——敏感度扫描（rare 率、组噪声）列入 Gate 2.2/5。
